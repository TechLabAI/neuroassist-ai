## Objetivo

Escrever do zero os cenários E2E do EVNT. Como no DASH, não há stubs — apenas `describe` vazios.

## Contexto

5 arquivos, todos com `describe` vazio (`0 scenarios`):

```
apps/evnt-e2e/src/notificacao-rotina.spec.ts
apps/evnt-e2e/src/confirmar-atendimento.spec.ts
apps/evnt-e2e/src/confirmacao-concorrente.spec.ts
apps/evnt-e2e/src/alarme-emergencia-preempcao.spec.ts
apps/evnt-e2e/src/entrega-degradada.spec.ts
```

Os nomes dos arquivos descrevem exatamente os cenários que faltam — inclusive os dois
mais delicados do produto: **preempção de alarme de emergência** e **confirmação concorrente**
(dois cuidadores confirmando o mesmo evento).

A rota `/eventos` existe e o alarme de emergência é um outlet global do shell
(não uma rota) — ver `app.routes.ts`.

## Checklist

- [ ] Features BDD do EVNT localizadas e auditadas
- [ ] `notificacao-rotina` — feed de rotina
- [ ] `confirmar-atendimento` — confirmação → `EventoConfirmado` (BE `NTF-05`)
- [ ] `confirmacao-concorrente` — dois cuidadores, uma confirmação vence, UI do perdedor reconcilia
- [ ] `alarme-emergencia-preempcao` — emergência preempta a superfície atual via outlet do shell
- [ ] `entrega-degradada` — retry budget, `no_open_session`, DASH indisponível (BE `NTF-02`/`NTF-04`)
- [ ] Verde nos perfis `mock` e `integrated`

## Atenção

`confirmacao-concorrente` é o cenário mais difícil de reproduzir e o mais valioso:
exige duas `browserContext` Playwright simultâneas sobre o mesmo evento.
