# FE-E2E-001 — Transporte: proxy.conf.json + configuração Nx `integrated`

**Módulo:** FE E2E Integration
**Fase:** F0 — Habilitação de Transporte
**Prioridade:** P1 (bloqueante)
**Status:** OPEN
**Criado em:** 2026-08-20
**Plano:** [plan-e2e-integration.md](../plans/plan-e2e-integration.md)

---

## Objetivo

Permitir que o `neuroassist-ai-web` servido em `localhost:4200` alcance o GWY em `localhost:8080`,
e que exista uma configuração Nx dedicada (`integrated`) que ative os HTTP adapters — sem
quebrar o modo `mock` default.

## Contexto

- Não existe `proxy.conf.json` no repositório (`find . -name "proxy*.json"` → vazio).
- Não existem arquivos de `environment` (`find apps libs -name "environment*"` → vazio).
- O alvo `serve` em `apps/neuroassist-ai-web/project.json` só tem as configurações
  `development` e `production`, ambas apontando para o mesmo build com adapters mock.
- Os base paths dos módulos **não são uniformes** — o proxy precisa cobrir 4 prefixos distintos.

## Cenários de Validação

| ID | Cenário | Critério |
|---|---|---|
| TRN-01 | Proxy roteia os 4 prefixos para `http://localhost:8080` | `curl :4200/api/v1/hist/history` chega ao GWY |
| TRN-02 | `nx serve neuroassist-ai-web -c integrated` sobe com HTTP adapters | request de rede real observável no DevTools |
| TRN-04 | CORS/preflight resolvido (ou desnecessário via proxy same-origin) | `OPTIONS` não bloqueia |

## Prefixos que o proxy DEVE cobrir

```
/api/v1/acs/**     → acs-service   (tenants, caregivers, directory)
/api/pac/v1/**     → pac-service   (pacientes, comandos)
/api/v1/events/**  → evnt-service
/api/v1/reports/** → evnt-service
/api/v1/hist/**    → hist-service
/api/v1/edge/**    → edge-service  (única rota que já existe no GWY)
/panel/**          → dash-service
/gest-service/**   → gest-service  (ver FE-E2E-004)
/oauth2/**         → acs-service   (token, refresh, jwks)
```

## Checklist
