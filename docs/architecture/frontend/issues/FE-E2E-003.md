## Objetivo

Implementar a sessão de autenticação do browser contra o ACS como Authorization Server.

## Contexto

Estado atual — o arquivo inteiro:

```ts
// libs/shared/auth-session/src/lib/auth-session.ts
// @neuroassist/shared/auth-session — Wave-0 stub (D-328/FE-4)
export interface AuthSession { readonly token: string | null; }
```

Não há login, nem storage, nem refresh. O ACS expõe `@RequestMapping("/oauth2")`
(`acs-service`) com token, refresh e JWK Set.

## ⚠️ Blocker B2 — resolver antes de iniciar

O `application.yml` do GWY tem:

```yaml
issuer-uri: ${KEYCLOAK_ISSUER_URI:http://localhost:8180/realms/neuroassist-ai}
```

O `docker/docker-compose.dev.yml` sobrescreve para `http://acs-service:8088` (correto),
mas **fora do compose** o default aponta para um Keycloak que não existe no stack.
Toda a Fase 1 falha com `401` sem causa óbvia. Pedir ao backend (E2E-002) a renomeação
para `ACS_ISSUER_URI` com default apontando para o ACS.

## Cenários de Validação

| ID | Cenário | Critério |
|---|---|---|
| AUTH-FE-01 | Login pela UI emite `POST /oauth2/token` e persiste o par | token RS256; sessão populada |
| AUTH-FE-02 | Credencial inválida → `401` como erro de formulário | nenhum token persistido; mensagem PT-BR |
| AUTH-FE-07 | Refresh falho → logout + redirect `/entrada` | sessão limpa; navegação ocorre |

## Escopo

- `login(credentials)` → `POST /oauth2/token`
- `refresh()` → `POST /oauth2/token/refresh` com rotation (novo `jti`, espelha BE `AUTH-03`)
- `logout()` → limpa storage e navega para `/entrada`
- Storage: decidir e documentar (`sessionStorage` vs memória + refresh em cookie httpOnly)
- Signals expondo `isAuthenticated`, `claims`, `roles` para os guards existentes
