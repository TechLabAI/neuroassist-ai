# FE-E2E-012 — Degradação e fail-closed na UI (DEG-01..08)

**Módulo:** FE E2E Integration
**Fase:** F4 — Degradação e Fail-Closed
**Prioridade:** P2
**Status:** OPEN
**Criado em:** 2026-08-20
**Plano:** [plan-e2e-integration.md](../plans/plan-e2e-integration.md)

---

## Objetivo

O backend já prova que degrada corretamente (BE Fases 3, 5, 7). Este issue prova que a UI
**conta a verdade ao cuidador** quando isso acontece.

## Por que importa mais aqui do que num app comum

Este é um produto de tecnologia assistiva para pessoas com ALS/MND. Uma UI que mostra
"nenhum evento" quando na verdade o serviço está fora, ou um chip "online" quando o
dispositivo está degradado, não é um bug de UX — é uma falha de segurança do paciente.
Silêncio nunca pode ser renderizado como "tudo bem".

## Cenários de Validação

| ID | Comportamento do backend | Expectativa na UI |
|---|---|---|
| DEG-01 | HIST `503 scope-unavailable` (ACS down — BE `DIR-03`) | banner "histórico indisponível"; **nunca** lista vazia |
| DEG-02 | EDGE `profilePointerDegraded: true` (BE `HB-03`) | chip degradado, **não** "online" |
| DEG-03 | EDGE liveness `offline` (BE `DSH-04`) | chip offline + timestamp de última vista |
| DEG-04 | EDGE liveness `304 Not Modified` (BE `DSH-05`) | sem re-render, sem flicker |
| DEG-05 | DASH `no_open_session` (BE `NTF-02`) | notificação não desaparece silenciosamente |
| DEG-06 | PAC `422` device inválido (BE `DEV-02`/`DEV-03`) | erro no campo do dispositivo, não toast genérico |
| DEG-07 | Serviço indisponível (connection refused) | estado retryable; app não trava |
| DEG-08 | `ProblemDetail` RFC 7807 | `title`/`detail` via `shared/error-model`; nunca JSON cru |

## Método

Cada cenário é forçado de duas formas:

- perfil `mock` — via `page.route` com a resposta de erro (determinístico, roda em todo PR)
- perfil `integrated` — derrubando o serviço real no compose (prova o comportamento de verdade)

`apps/edge-e2e/src/backend-error-handling.spec.ts` e
`apps/gest-e2e/src/backend-error-handling.spec.ts` já existem e servem de modelo.

## Checklist

- [ ] DEG-01..08 cobertos no perfil `mock`
- [ ] DEG-01, 02, 03, 07 reproduzidos no perfil `integrated` (derrubando serviço)
- [ ] `shared/error-model` mapeia `ProblemDetail` para mensagens PT-BR
- [ ] Nenhum cenário de erro renderiza estado vazio (auditar todos os `empty state`)
- [ ] Nenhum JSON cru ou stack trace visível na UI

## Regra de ouro deste issue

**Estado vazio ≠ estado de erro.** Toda tela com lista precisa distinguir
"não há dados" de "não foi possível saber se há dados".
