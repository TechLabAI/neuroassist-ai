# FE-E2E-016 — Seed determinístico + global-setup Playwright (login uma vez)

**Módulo:** FE E2E Integration
**Fase:** F3 — Superfícies de Módulo
**Prioridade:** P2
**Status:** OPEN
**Criado em:** 2026-08-20
**Plano:** [plan-e2e-integration.md](../plans/plan-e2e-integration.md)

## Objetivo

Dar ao perfil `integrated` uma base de dados previsível e uma sessão autenticada
reutilizável, para que os testes sejam determinísticos e rápidos.

## Problema que resolve

No perfil `mock` cada teste controla os seus próprios dados. No perfil `integrated`
os testes compartilham um PostgreSQL real. Sem seed determinístico:

- os testes passam a depender da ordem de execução;
- `fullyParallel: true` (todos os `playwright.config.ts`) causa interferência entre specs;
- fazer login por UI em cada teste custa segundos × 100+ testes.

## Escopo

1. **Seed** — dataset conhecido: 1 tenant, 2 cuidadoras (papéis distintos: `hist:read`
   e `hist:read:all`), 2 pacientes, 1 device pareado + 1 device com código expirado,
   comandos publicados. Aplicado após as migrations, antes da suíte.
2. **`globalSetup` do Playwright** — login uma vez, `storageState` salvo e reutilizado
   por todos os specs.
3. **Isolamento** — decidir entre reset por suíte ou namespacing por tenant/execução.

## Checklist

- [ ] Script de seed idempotente (rodar duas vezes não duplica nem falha)
- [ ] `globalSetup` emite `POST /oauth2/token` e persiste `storageState`
- [ ] `storageState` para os dois papéis (cuidadora com escopo restrito e coordenadora)
- [ ] Estratégia de isolamento decidida e documentada
- [ ] `fullyParallel` reavaliado no perfil `integrated` (pode ter de ser `workers: 1`)
- [ ] Perfil `mock` **não** usa nada disto — continua hermético e sem setup

## Atenção

`forbidOnly: !!process.env['CI']` e `retries: CI ? 2 : 0` já estão configurados em todos
os `playwright.config.ts`. Retry mascara flakiness causada por dados compartilhados —
se um teste do perfil `integrated` só passa no retry, o problema é o seed, não o teste.
