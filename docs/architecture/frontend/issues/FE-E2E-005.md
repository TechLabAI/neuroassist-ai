## Objetivo

Provar que cada `*MockAdapter` e o seu `*HttpAdapter` par satisfazem o **mesmo tipo de port**.
É a verificação mais barata do plano e a que pega drift de contrato mais cedo — antes de
qualquer investimento em specs de UI.

## Contexto

Os HTTP adapters foram escritos como stubs compiláveis (`TODO[INT-FE-<MOD>-NNN]: wire once
<svc> is deployed`) e **nunca** foram exercitados contra um backend. O compilador garante
que o adapter satisfaz a interface do port; ninguém garante que o **JSON que o backend
devolve** satisfaz essa interface.

Os base paths já foram conferidos contra os `@RequestMapping` reais e estão alinhados
(ver §2.1 do plano) — o risco remanescente é de **shape**, não de rota.

## Método

Um teste por port, parametrizado pelo adapter:

```
describe.each([['mock', MockAdapter], ['http', HttpAdapter]])(...)
  → mesma asserção de shape nos dois
```

O braço `http` roda apenas no perfil `integrated` (nightly), contra o stack Docker.
O braço `mock` roda em todo PR.

## Atenção

**Divergência de shape é bug de contrato, não de UI.** Se o backend devolve algo diferente
do port, a correção é decidida entre BE e FE — não se adapta o tipo do FE em silêncio.

`INT-FE-HIST-001` já registra o gap G2: confirmar se `rotulo`/`urgencia` vêm resolvidos
no read model do HIST ou se exigem client-join. CTR-04 é onde isso se decide.
