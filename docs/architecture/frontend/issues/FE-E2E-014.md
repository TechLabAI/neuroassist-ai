## Objetivo

Provar, pelo browser, a cadeia completa que justifica o produto: um gesto reconhecido
vira um alarme que **chega** à cuidadora, é confirmado, e fica auditado.

Espelha BE `E2E-011` / Flow-03.

## Fluxo

```
1. report de gesto injetado no EVNT (fixture de teste)
2. EVNT → ACS directory                → resolve cuidadores responsáveis
3. EVNT → DASH dispatch                → notificação
4. DASH SSE push                       → alarme aparece no shell outlet do browser
5. cuidador confirma na UI             → DASH → EVNT callback → EventoConfirmado
6. /historico                          → timeline mostra os 2 fatos do evento
```

## Gate

- O alarme chega ao browser por **SSE real** (não simulado)
- A confirmação persiste no EVNT
- HIST contém `EventoCriado` **e** `EventoConfirmado` (2 fatos)
- Evento com `feedback = real`

## Checklist

- [ ] Fixture de injeção de report no EVNT (não depende de câmera nem de gesto real)
- [ ] Alarme renderizado no outlet global do shell (não em rota)
- [ ] Confirmação pela UI dispara o callback ao EVNT
- [ ] `/historico` mostra os 2 fatos
- [ ] Latência do push medida e registrada (é requisito de produto, não só de teste)
- [ ] Caminho infeliz: cuidadora sem sessão aberta → `no_open_session` (DEG-05)
- [ ] Caminho infeliz: confirmação concorrente de dois cuidadores (ver FE-E2E-010)

## Atenção

Este é o único flow em que **atraso é falha**, mesmo com todos os passos retornando 2xx.
Vale registrar o tempo entre o passo 1 e o passo 4 em cada execução, para que uma
regressão de latência seja visível antes de virar incidente.
