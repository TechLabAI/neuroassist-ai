# FE-E2E-002 — shared/access-http-base: interceptor HTTP (auth, empresa, correlation, erro)

**Módulo:** FE E2E Integration
**Fase:** F0/F1 — Transporte + Auth
**Prioridade:** P1 (bloqueante)
**Status:** OPEN
**Criado em:** 2026-08-20
**Plano:** [plan-e2e-integration.md](../plans/plan-e2e-integration.md)

## Objetivo

Transformar `libs/shared/access-http-base` de stub em um interceptor real que injeta os headers
transversais em toda chamada HTTP dos 7 módulos, e normaliza erros RFC 7807.

## Contexto

Estado atual — o arquivo inteiro:

```ts
// libs/shared/access-http-base/src/lib/access-http-base.ts
// @neuroassist/shared/access-http-base — Wave-0 stub (D-328/FE-4)
export const ACCESS_HTTP_BASE = '/api';
```

E em `app.config.ts`: `provideHttpClient(withInterceptors([]))` — array vazio.

Todos os `*HttpAdapter` dos 7 módulos já comentam no cabeçalho que *"interceptors
(shared/access-http-base) injetam X-Empresa-Id, Authorization, X-Correlation-Id"* —
o contrato está documentado nos adapters mas nunca foi implementado.

## Cenários de Validação

| ID | Cenário | Critério |
|---|---|---|
| AUTH-FE-03 | `Authorization: Bearer <jwt>` presente em toda chamada de módulo | verificado em PAC, HIST, EVNT, EDGE, DASH, ACS, GEST |
| AUTH-FE-04 | `X-Empresa-Id` vem de `shared/empresa-context` | header igual ao tenant ativo |
| AUTH-FE-05 | `X-Correlation-Id` único por request | formato UUID, distinto entre requests |
| AUTH-FE-06 | `401` dispara refresh + replay | 1 refresh, 1 replay |
| AUTH-FE-08 | `403` **não** dispara refresh | 0 chamadas a `/oauth2/token/refresh` |
| AUTH-FE-09 | Requests concorrentes durante refresh são enfileiradas | exatamente 1 refresh |
| DEG-08 | `ProblemDetail` mapeado por `shared/error-model` | nunca JSON cru na tela |

## Escopo do interceptor

1. **Auth** — injeta `Authorization` a partir de `shared/auth-session` (FE-E2E-003).
2. **Tenant** — injeta `X-Empresa-Id` a partir de `shared/empresa-context`.
3. **Tracing** — gera `X-Correlation-Id` por request.
4. **Idempotência** — gera `Idempotency-Key` em `POST`/`PUT` mutantes (conforme comentado nos adapters).
5. **Erro** — converte `ProblemDetail` (RFC 7807) no tipo de `shared/error-model`.
6. **Refresh** — single-flight: um único refresh em voo, demais requests enfileiradas.

## Atenção

`POST /api/v1/edge/devices/enroll` **não** exige `Authorization` (usa `enrollmentToken`) —
ver comentário no `application.yml` do GWY. O interceptor deve tratar essa exceção.
