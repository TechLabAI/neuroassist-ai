## 1. Token usage on PAC surfaces

| UI element | Token | Rationale |
|---|---|---|
| Emergency urgency badge | `--color-alarm` / `--color-danger` | emergencies are the safety-critical class (BE `urgencia=emergencia`) |
| Routine urgency badge | `--color-brand-muted` | discreet, non-alarming |
| "ativo no dispositivo" sync badge | `--color-success` | armed & acknowledged (ADR-005) |
| "pendente de sincronização" sync badge | `--color-warning` | honest not-yet-active state (ADR-005) — must be visually distinct from success |
| Emergency-gate blocking modal | `--color-danger` header | fail-closed decision surface (SPEC-07) |
| Sensibilidade selector | `--color-brand` scale | mapped baixa/media/alta, never a raw threshold (FE 03 §5) |
| Field validation hint | `--color-danger-text` | inline error tone |

## 2. Rules

- **Never** encode `syncState = pending` and `syncState = synced` with the same hue — the honest-state
  distinction (ADR-005) must survive colorblind palettes; pair color with an icon/label.
- Emergency urgency must be perceivable **without** relying on color alone (icon + text label), because a
  mis-read emergency badge is a safety defect, not a cosmetic one.
- Typography and spacing inherit from `@neuroassist/shared/ui-layout`; PAC introduces no new type scale.
