# SPEC-06 — Shell Integration — PAC (Frontend)

> Module: **PAC** · Generated by `/fe-architect-specs neuroassist-ai PAC` · 2026-07-28
> Sources: FE 02 §4, FE 04 §2/§5, ADR-006 (module-as-library). Entry lib `@neuroassist/pac`.

## 1. Module descriptor (fallback for the Shell)

`libs/pac/shell-entry/src/lib/pac.descriptor.ts` exports `PAC_MODULE_DESCRIPTOR`, the static fallback the
`scope:web` shell uses to render nav even before the lazy module loads.

```ts
export const PAC_MODULE_DESCRIPTOR: ModuleDescriptor = {
  key: 'pac',
  label: 'Calibração',
  icon: 'tune',
  route: '/pac',
  loadChildren: () => import('@neuroassist/pac').then(m => m.PacModule),
  permissions: ['pac.comando.read'],
  showInNav: true,
  order: 30,
};
```

The barrel `@neuroassist/pac` re-exports (FE 04 §2): `PacModule`, `pac.contract` (SPEC-05), `PAC_ROUTES`
(SPEC-01), `pac.permission-map`, `pac.feature-flags`, `pac.bootstrap`, `pac.nav.config`,
`PAC_MODULE_DESCRIPTOR`.

## 2. `PacShellIntegrationService` (`libs/pac/integration`)

Bridges PAC into the shell without PAC reaching into `scope:web`. Responsibilities:

- **register()** — contribute `PAC_MODULE_DESCRIPTOR` + nav config to the shell registry.
- **contributeBreadcrumbs()** — expose `libs/pac/navigation` breadcrumb signal to the shell
  (`Calibração` → `Calibração › Novo comando` / `Editar "<rótulo>"`). Contributes **none** while the
  patient-register feature runs inside the ACS onboarding wizard (onboarding owns that trail — FE 05 §6).
- **liveTestComposition()** — declares the **composition seam** for the command editor: the shell page (not
  PAC) imports GEST's `GestureLiveTestComponent` and renders it alongside `CommandEditorComponent`, wiring the
  current `Comando` draft in via `@Input`/signal. `scope:pac` MUST NOT import `scope:gest` (FE 02 §4, ADR-006).

## 3. Bootstrap lifecycle (`pac.bootstrap.ts`)

```ts
export const pacBootstrap: ModuleBootstrap = {
  init(ctx: ShellContext): void {
    // - register permission map + feature flags with the shell
    // - subscribe libs/pac/navigation breadcrumb signal
    // - prime PacPacienteFacade.loadCurrent() so the tenant/patient guard resolves fast
    // - NO camera, NO detection, NO GEST import
  },
  destroy(): void {
    // - unsubscribe breadcrumb/nav contributions
    // - reset PacComandoFacade + PacPacienteFacade signals (drop cached catalog/patient)
    // - abort any in-flight catalog GET
  },
};
```

**init** wires nav + permissions + primes the patient read; **destroy** tears down subscriptions and clears
module-local signals so a re-entry starts clean. PAC holds no global store, so destroy is a full reset of its
facade signals.

## Criterios de aceite (EARS)

> Clauses are one clause each and dot-free so the coverage gate extracts them whole; each shares domain nouns
> with a `Scenario:` title in `e2e/`.

- WHEN the shell loads the PAC descriptor, THE SYSTEM SHALL contribute the Calibração nav item without eagerly
  loading the PAC module.
- WHEN the PAC bootstrap init runs, THE SYSTEM SHALL prime the paciente read so the tenant patient guard
  resolves on first navigation.
- WHEN the PAC bootstrap destroy runs, THE SYSTEM SHALL reset the PAC facade signals and abort any in-flight
  catalog request.
- WHILE the patient register feature is composed inside the onboarding wizard, THE SYSTEM SHALL contribute no
  PAC breadcrumb for the paciente step.
- THE SYSTEM SHALL compose the GEST live-test only at the shell page level without importing gest scope into
  any PAC library.
