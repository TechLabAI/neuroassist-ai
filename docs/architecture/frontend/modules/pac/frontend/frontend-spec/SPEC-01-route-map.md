# SPEC-01 — Route Map — PAC (Frontend)

> Module: **PAC — Pacientes e Catálogo de Comandos** · Nx scope `@neuroassist` · Entry lib `@neuroassist/pac` (ADR-006)
> Project: NeuroAssist AI · Generated by `/fe-architect-specs neuroassist-ai PAC` · 2026-07-28
> Sources: FE 02 §3/§4, FE 04 §5, FE 05 §6, BE `api-contract.md`, ADR-005 (draft-first), ADR-006 (module-as-library).

PAC **is a top-level nav destination** (the "Calibração / Catálogo" entry, FE 04 §7). Its shell entry is a
library loaded lazily by the `scope:web` shell via `loadChildren: () => import('@neuroassist/pac')`.
Sub-views are `loadComponent`. Every route is tenant-scoped (`X-Empresa-Id` interceptor) and guarded.

## 1. Master route table

| Path | Component | Feature Lib | Guards | Title | Breadcrumb |
|---|---|---|---|---|---|
| `/pac` | `CommandCatalogComponent` | `libs/pac/feature-command-catalog` | `authGuard`, `pacTenantPatientGuard` | "Calibração" | `[Calibração]` |
| `/pac/comandos/novo` | `CommandEditorComponent` | `libs/pac/feature-command-editor` | `authGuard`, `pacTenantPatientGuard`, `pacCommandWriteGuard` | "Novo comando" | `[Calibração, Novo comando]` |
| `/pac/comandos/:comandoId/editar` | `CommandEditorComponent` | `libs/pac/feature-command-editor` | `authGuard`, `pacTenantPatientGuard`, `pacCommandWriteGuard` | "Editar comando" | `[Calibração, Editar "<rótulo>"]` |

**Composed (not shell-routed) surface** — rendered *inside* another module's shell page, so PAC contributes
no top-level route and no breadcrumb for it (FE 04 §5, FE 05 §6):

| Composition host | Component | Feature Lib | Wiring |
|---|---|---|---|
| ACS-owned onboarding wizard (step 2 "Paciente") | `PatientRegisterComponent` | `libs/pac/feature-patient-register` | shell page mounts the component; onboarding owns the wizard breadcrumb |
| `scope:web` shell command-editor page (with the PAC editor) | `GestureLiveTestComponent` (**GEST-owned**) | GEST barrel | shell wires the current `Comando` draft into GEST via `@Input`/signal; **PAC never imports `scope:gest`** |

## 2. Route composition & lazy strategy

- Shell → `@neuroassist/pac` via `loadChildren` (whole module lazy).
- `PAC_ROUTES[]` (in `libs/pac/shell-entry/src/lib/pac.routes.ts`) declares the three sub-views via
  `loadComponent`, each with `canActivate: [authGuard, pacTenantPatientGuard]`; the editor routes add
  `pacCommandWriteGuard`.
- The editor route is shared by "novo" and "editar"; `:comandoId` presence selects create vs edit mode.
- Deep-link to `/pac/comandos/:comandoId/editar` for an unknown/foreign-empresa `comandoId` resolves to a
  not-found redirect (guarded by the resolver contract in SPEC-04, mapped from BE `404 /errors/not-found`).

## 3. Guard contracts

| Guard | Lib | Rule |
|---|---|---|
| `authGuard` | `@neuroassist/shared/access-decision` | authenticated session present |
| `pacTenantPatientGuard` | `libs/pac/access` | active tenant (`empresa-context`) **and** a registered `Paciente` for the tenant; otherwise redirect to onboarding |
| `pacCommandWriteGuard` | `libs/pac/access` | caller holds `pac.comando.write` (UI defense-in-depth; BE enforces `pac:command:write` scope) |

## Criterios de aceite (EARS)

> Clauses are one clause each and free of dotted identifiers so the coverage gate extracts them whole; each
> shares domain nouns with a `Scenario:` title in `e2e/`.

- THE SYSTEM SHALL expose the Calibração route rendering the command catalog for the active paciente.
- WHEN the caregiver opens the novo comando route, THE SYSTEM SHALL render the command editor with a blank
  draft in editing state.
- WHEN the caregiver opens the editar comando route for an existing comando, THE SYSTEM SHALL render the
  command editor pre-filled from that comando.
- IF no paciente is registered for the active empresa, THEN THE SYSTEM SHALL redirect the caregiver to the
  onboarding paciente step.
- IF the caller lacks the comando write permission, THEN THE SYSTEM SHALL block the command editor route and
  keep the command editor hidden.
- IF the editar route references a comandoId unknown to the active empresa, THEN THE SYSTEM SHALL redirect to
  the not-found view.
- WHILE a paciente is registered for the active empresa, THE SYSTEM SHALL keep the Calibração nav item
  visible.
