## 1. Token usage on ACS surfaces

| UI element | Token | Rationale |
|---|---|---|
| "Sem cobertura" coverage badge / banner | `--color-danger` | a paciente with zero active covering caregiver is a safety state (ADR-005) — never hidden, never muted |
| "Coberto (n)" coverage badge | `--color-success` | at least one active alarm-eligible responder is on the hook |
| Last-covering block modal | `--color-danger` header | fail-closed decision surface (SPEC-07); must not read as a routine confirm |
| Cross-tenant link reject modal | `--color-danger` header | fail-closed rejection (SPEC-07) |
| Role badge — `coordenador_clinica` | `--color-brand` | admin-capability marker |
| Role badge — `cuidadora` | `--color-brand-muted` | discreet, non-privileged marker |
| Status badge — `inactive` caregiver | `--color-neutral-muted` | deactivated; visibly distinct from an active covering caregiver |
| Tenant provisioning state | `--color-warning` | honest not-yet-active empresa state (BE saga §3.1) — distinct from active success |
| Field validation hint | `--color-danger-text` | inline error tone |

## 2. Rules

- **Never** encode `coberto` and `sem-cobertura` with the same hue — the coverage honesty (ADR-005) must
  survive colorblind palettes; pair color with an icon **and** a text label ("Coberto (n)" / "Sem cobertura").
  A mis-read coverage badge is a safety defect, not a cosmetic one.
- The `sem cobertura` state must be perceivable **without** relying on color alone (icon + text), and it is
  **never hidden** — an uncovered patient must always be visible on the roster and in the linkage header.
- An `inactive` linked caregiver must be visually distinct from an `active` one, because only active caregivers
  count toward coverage (ADR-005) — the color must not imply the patient is covered.
- Typography and spacing inherit from `@neuroassist/shared/ui-layout`; ACS introduces no new type scale.
