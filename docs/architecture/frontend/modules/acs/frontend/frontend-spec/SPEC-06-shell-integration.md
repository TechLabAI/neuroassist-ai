# SPEC-06 — Shell Integration — ACS (Frontend)

> Module: **ACS** · Generated by `/fe-architect-specs neuroassist-ai ACS` · 2026-07-29
> Sources: FE 02 §4, FE 04 §2/§5, FE 05 §6, ADR-006 (module-as-library). Entry lib `@neuroassist/acs`.

## 1. Module descriptor (fallback for the Shell)

`libs/acs/shell-entry/src/lib/acs.descriptor.ts` exports `ACS_MODULE_DESCRIPTOR`, the static fallback the
`scope:web` shell uses to render nav even before the lazy module loads.

```ts
export const ACS_MODULE_DESCRIPTOR: ModuleDescriptor = {
  key: 'acs',
  label: 'Cuidadores',
  icon: 'group',
  route: '/acs',
  loadChildren: () => import('@neuroassist/acs').then(m => m.AcsModule),
  permissions: ['acs.cuidador.read'],
  showInNav: true,
  order: 40,
};
```

The barrel `@neuroassist/acs` re-exports (FE 04 §2): `AcsModule`, `acs.contract` (SPEC-05), `ACS_ROUTES`
(SPEC-01), `acs.permission-map`, `acs.feature-flags`, `acs.bootstrap`, `acs.nav.config`,
`ACS_MODULE_DESCRIPTOR`, and the two composed step components `TenantSetupComponent` /
`CaregiverLinkStepComponent` (consumed only by the `scope:web` onboarding shell page).

## 2. `AcsShellIntegrationService` (`libs/acs/integration`)

Bridges ACS into the shell without ACS reaching into `scope:web`. Responsibilities:

- **register()** — contribute `ACS_MODULE_DESCRIPTOR` + nav config to the shell registry.
- **contributeBreadcrumbs()** — expose `libs/acs/navigation` breadcrumb signal to the shell
  (`Cuidadores` → `Cuidadores › Convidar` / `Editar "<nome>"` → `Cuidadores › Vínculos de "<paciente>"`).
  Contributes **none** while `TenantSetupComponent` / `CaregiverLinkStepComponent` run inside the onboarding
  wizard (the onboarding shell owns that trail — FE 05 §6).
- **onboardingWizardComposition()** — declares the **composition seam** for the ACS-owned onboarding wizard:
  ACS owns the wizard's step **sequence/descriptor**, but the wizard shell page (not ACS) imports PAC
  (`PatientRegisterComponent`, `CommandEditorComponent`) and EDGE (device-pairing) step features alongside ACS's
  own steps, wiring the shared session context (active tenant, current `pacienteId`) between them. `scope:acs`
  MUST NOT import `scope:pac`/`scope:edge`/`scope:gest` (FE 02 §4, ADR-006).
- **tenant-writer seam** — ACS is the **writer** of `@neuroassist/shared/empresa-context`; `register()` declares
  ACS as the active-tenant writer so peers know the source of `X-Empresa-Id` (FE 05 §1). No other module writes
  it.

## 3. Bootstrap lifecycle (`acs.bootstrap.ts`)

```ts
export const acsBootstrap: ModuleBootstrap = {
  init(ctx: ShellContext): void {
    // - register permission map + feature flags with the shell
    // - subscribe libs/acs/navigation breadcrumb signal
    // - hydrate the active tenant from @neuroassist/shared/empresa-context (ACS is its writer)
    // - prime AcsCuidadorFacade.loadRoster() + CoverageFacade so the roster/coverage resolve fast
    // - NO auth logic (auth-session owns token exchange), NO scope:pac/edge/gest import
  },
  destroy(): void {
    // - unsubscribe breadcrumb/nav contributions
    // - reset AcsCuidadorFacade + AcsLinkFacade + CoverageFacade signals (drop cached roster/links/coverage)
    // - abort any in-flight roster/linkage GET
    // - MUST NOT clear @neuroassist/shared/empresa-context (session-scoped, shared across modules)
  },
};
```

**init** wires nav + permissions + primes roster/coverage; **destroy** tears down subscriptions and clears
module-local signals so a re-entry starts clean — but it **never** clears the shared active tenant, because
peers depend on it for the rest of the session (FE 05 §3).

## Criterios de aceite (EARS)

> Clauses are one clause each and dot-free so the coverage gate extracts them whole; each shares domain nouns
> with a `Scenario:` title in `e2e/`.

- WHEN the shell loads the ACS descriptor, THE SYSTEM SHALL contribute the Cuidadores nav item without eagerly
  loading the ACS module.
- WHEN the ACS bootstrap init runs, THE SYSTEM SHALL prime the roster and coverage so the roster resolves on
  first navigation.
- WHEN the ACS bootstrap destroy runs, THE SYSTEM SHALL reset the ACS facade signals and abort any in-flight
  roster request.
- WHEN the ACS bootstrap destroy runs, THE SYSTEM SHALL keep the shared active empresa context so peer modules
  retain the empresa header.
- WHILE the tenant setup and caregiver link steps are composed inside the onboarding wizard, THE SYSTEM SHALL contribute no ACS breadcrumb for those steps.
- THE SYSTEM SHALL compose the PAC and EDGE onboarding steps only at the shell page level without importing pac
  or edge scope into any ACS library.
