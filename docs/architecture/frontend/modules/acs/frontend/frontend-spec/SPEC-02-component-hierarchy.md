# SPEC-02 — Component Hierarchy — ACS (Frontend)

> Module: **ACS** · Generated by `/fe-architect-specs neuroassist-ai ACS` · 2026-07-29
> Sources: FE 02 §4, FE 04 §3, FE 05 §2. Smart components consume facades (signals); presentational
> components receive `@Input` and emit `@Output`. No `BehaviorSubject` in components (FE 05 §2).

> This SPEC is a component tree (prose) — no `## Criterios de aceite (EARS)` section (per command guide:
> EARS is not applied to component trees).

## 1. `feature-caregiver-roster` (`libs/acs/feature-caregiver-roster`)

```
CaregiverRosterComponent  (smart)
│  reads signals: acsCuidadorFacade.roster(), acsCuidadorFacade.loadState(),
│                 coverageFacade.coverageByPatient()
│  dispatches: loadRoster(), invite(), edit(id), deactivate(id), openLinkage(pacienteId)
├── RosterKpiBarComponent            (presentational)  @Input kpis: RosterKpiVM
├── CoverageAlertBarComponent        (presentational)  @Input semCobertura: PatientCoverageVM[]
│      (shows danger banner listing any paciente sem cobertura — never hidden, ADR-005)
├── RosterEmptyStateComponent        (presentational)  @Output invite  (shown only if roster empty — rare post-onboarding)
├── RosterErrorCardComponent         (presentational)  @Input error: AppError  @Output retry
└── CaregiverRowComponent[]          (presentational, libs/acs/ui)
        @Input row: CuidadorRowVM
        @Output edit  @Output deactivate  @Output manageLinks
        ├── RoleBadgeComponent           @Input papel  ('cuidadora' | 'coordenador_clinica')
        ├── StatusBadgeComponent         @Input status ('active' | 'inactive')
        └── CoverageBadgeComponent       @Input coverage ('coberto' | 'sem-cobertura')  (icon + label, not color-only)
```

Signals read by `CaregiverRosterComponent`: `roster` (`CuidadorRowVM[]`), `loadState`
(`idle|loading|loaded|error`), `coverageByPatient` (`Map<pacienteId, PatientCoverageVM>` — **derived**,
FE 05 §1). The deactivate action is disabled/blocked by the derived `isLastCovering` flag (ADR-005); the row
never invents `coberto`.

## 2. `feature-caregiver-editor` (`libs/acs/feature-caregiver-editor`)

```
CaregiverEditorComponent  (smart)
│  reads signals: acsCuidadorFacade.editorState(), acsCuidadorFacade.draft(),
│                 acsCuidadorFacade.saveError()
│  dispatches: startNew()|startEdit(id), patchDraft(partial), save(), deactivate(), cancel(), retrySave()
├── CaregiverFormComponent             (presentational)  @Input draft: CuidadorFormVM  @Output change
│     ├── NomeFieldComponent             @Input value  @Output change   (required, synchronous validator)
│     ├── LoginFieldComponent            @Input value  @Output change   (required; unique per empresa — BE 409)
│     ├── RoleSelectorComponent          @Input papel  @Output change   (cuidadora | coordenador_clinica)
│     └── SenhaFieldComponent            @Input value  @Output change   (required on create only; never echoed)
├── SaveStatusComponent               (presentational)  @Input editorState  @Output retry
└── DeactivateActionComponent         (presentational)
      @Input status, isLastCovering  @Output deactivate
      (deactivate disabled WHILE isLastCovering — blocking reason surfaced, ADR-005)

CaregiverLinkStepComponent  (smart)  — composed inside ACS onboarding wizard step 5 (shell page)
│  reads signals: acsCuidadorFacade.draft(), acsLinkFacade.linksForPatient()
│  dispatches: registerPrimary(draft), link(cuidadorId, pacienteId)
└── (reuses CaregiverFormComponent + a compact link picker; contributes no breadcrumb)
```

`CaregiverEditorComponent` declares it reads exactly: `editorState` (`EditorState`), `draft`
(`CuidadorFormVM`), `saveError` (`AppError | null`). The `senha` field is write-only — never bound back from a
loaded caregiver (BE never returns a credential field).

## 3. `feature-patient-linkage` (`libs/acs/feature-patient-linkage`)

```
PatientLinkageComponent  (smart)
│  reads signals: acsLinkFacade.linksForPatient(), acsLinkFacade.candidates(),
│                 coverageFacade.coverageFor(pacienteId), acsLinkFacade.mutateState()
│  dispatches: load(pacienteId), link(cuidadorId), unlink(cuidadorId), retryLoad()
├── PatientCoverageHeaderComponent     (presentational)  @Input coverage: PatientCoverageVM
│      (shows "Coberto (n)" | "Sem cobertura" danger — ADR-005)
├── LinkedCaregiverListComponent       (presentational)  @Input links: VinculoRowVM[]
│     └── LinkedCaregiverRowComponent   @Input row  @Output unlink
│            (unlink disabled WHILE row.isLastCovering — blocking reason, ADR-005)
├── UnlinkedCandidateListComponent     (presentational)  @Input candidates: CuidadorRowVM[]  @Output link
└── LinkageErrorCardComponent          (presentational)  @Input error: AppError  @Output retry
```

`PatientLinkageComponent` reads: `linksForPatient` (`VinculoRowVM[]`), `candidates` (`CuidadorRowVM[]`),
`coverageFor` (`PatientCoverageVM`, **derived**), `mutateState` (`idle|linking|unlinking|error`). Coverage is
re-derived from a fresh fetch after any link/unlink — never optimistically flipped (FE 05 §4).

## 4. `feature-tenant-setup` (`libs/acs/feature-tenant-setup`)

```
TenantSetupComponent  (smart)  — composed inside ACS onboarding wizard step 1 (shell page)
│  reads signals: acsTenantFacade.tenant(), acsTenantFacade.saveState()
│  dispatches: createTenant(nome, tipo)
├── TenantFormComponent                (presentational)  @Input value  @Output change
│     ├── NomeFieldComponent             @Input value  @Output change  (required)
│     └── TenantTypeSelectorComponent    @Input tipo  @Output change   (familia | clinica)
└── TenantSaveStatusComponent         (presentational)  @Input saveState  @Output retry
```

`TenantSetupComponent` reads: `tenant` (`TenantVM | null`), `saveState`
(`idle|saving|provisioning|active|error`). On success it **writes** `@neuroassist/shared/empresa-context`
(ACS is the sole writer); it contributes **no breadcrumb** (onboarding shell owns the wizard trail).

## 5. Shared / domain libs (no page components)

- `libs/acs/data-access` — clients + facades (SPEC-04); exposes signals only.
- `libs/acs/access` — `acsCoordinatorGuard`, `acsCaregiverWriteGuard`, `acsLinkWriteGuard`.
- `libs/acs/integration` — `AcsShellIntegrationService` (SPEC-06).
- `libs/acs/navigation` — breadcrumb/menu state (SPEC-01 §1, FE 05 §6).
- `libs/acs/ui` — `RoleBadgeComponent`, `StatusBadgeComponent`, `CoverageBadgeComponent`,
  `CaregiverRowComponent` (pure presentational, no facade access).
