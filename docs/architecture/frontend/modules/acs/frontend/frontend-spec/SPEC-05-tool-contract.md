## 2. `MODULE_PERMISSION_MAP` (UI → BE authority)

UI permission keys map to BE authorities (`api-contract.md` §7.2, namespace `acs.<recurso>.<acao>`). The UI
enforces **defense-in-depth**; the backend is authoritative. Note the UI collapses the BE create/deactivate
authorities into a single `write` capability per resource, expanding to the exact BE authority at call time.

| UI permission | BE authority | Justification |
|---|---|---|
| `acs.cuidador.read` | `acs.cuidador.read` | render the roster / caregiver read-model |
| `acs.cuidador.write` | `acs.cuidador.criar`, `acs.cuidador.desativar` | invite/register and deactivate a cuidador (editor) — coordinator only |
| `acs.vinculo.write` | `acs.vinculo.criar`, `acs.vinculo.revogar` | link/unlink caregiver↔paciente (linkage panel) — coordinator only |
| `acs.tenant.write` | `acs.tenant.provisionar` | provision the empresa in the onboarding wizard (conductor authority) |

```ts
export const MODULE_PERMISSION_MAP = {
  'acs.cuidador.read':  'acs.cuidador.read',
  'acs.cuidador.write': 'acs.cuidador.criar',        // deactivate expands to acs.cuidador.desativar at call time
  'acs.vinculo.write':  'acs.vinculo.criar',         // revoke expands to acs.vinculo.revogar at call time
  'acs.tenant.write':   'acs.tenant.provisionar',
} as const;
```

## 3. `MODULE_FEATURE_FLAGS`

| Flag | Default | Justification |
|---|---|---|
| `acs.coverageGuard` | `on` | governs the ADR-005 last-covering block on unlink/deactivate; off degrades to warn-but-allow (rejected as default — kept only as a break-glass toggle, never off in production) |
| `acs.inviteByEmail` | `off` | toggles email-invite vs direct register-with-senha; off in MVP (no self-service sign-up — BE api-contract §2.1 resource-owner password grant only) |
| `acs.showSemCoberturaBanner` | `on` | surfaces the roster-level danger banner listing any paciente sem cobertura; off collapses it to a per-row badge only (used only where the aggregate banner is undesirable) |

```ts
export const MODULE_FEATURE_FLAGS = {
  'acs.coverageGuard':         'on',
  'acs.inviteByEmail':         'off',
  'acs.showSemCoberturaBanner':'on',
} as const;
```

## Criterios de aceite (EARS)

> Clauses are one clause each and dot-free so the coverage gate extracts them whole; each shares domain nouns
> with a `Scenario:` title in `e2e/`.

- WHILE the caller lacks the cuidador write permission, THE SYSTEM SHALL hide the convidar cuidador entry point.
- WHILE the caller lacks the cuidador write permission, THE SYSTEM SHALL disable the desativar cuidador action.
- WHILE the caller lacks the vinculo write permission, THE SYSTEM SHALL disable the vincular and desvincular
  actions.
- WHILE the caller lacks the tenant write permission, THE SYSTEM SHALL disable the criar empresa action in the
  onboarding wizard.
- WHILE the caller lacks the cuidador read permission, THE SYSTEM SHALL hide the Cuidadores nav item.
- WHERE the coverage guard flag is off, THE SYSTEM SHALL still surface the sem cobertura state and never mark an
  uncovered paciente as coberto.
- WHERE the invite by email flag is off, THE SYSTEM SHALL show the direct register cuidador form with a senha
  field instead of an email invite.
- WHERE the sem cobertura banner flag is off, THE SYSTEM SHALL collapse the coverage alert to a per row badge.
