## Scenario inventory

### caregiver-roster.feature
1. Open roster with existing caregivers → rows render with nome, papel, status, coverage badges.
2. Open roster while loading → loading state shown (no stale rows).
3. Roster load error → error card + "Tentar de novo" (no stale rows shown as fresh).
4. A paciente with zero active covering caregiver → row marked "Sem cobertura" (danger) + aggregate banner, never hidden.
5. KPI bar shows total ativos, coordenadores, pacientes sem cobertura counts.
6. Coordinator invites a cuidador → POST `/caregivers` with Idempotency-Key → roster reloads.
7. Retried invite reuses the same Idempotency-Key (no duplicate cuidador).
8. Invite with a login already used in the empresa → 409 login-duplicate → inline login error, not saved.
9. Blank nome / blank login / blank senha on create → "Salvar" disabled with inline hint.
10. Deactivate a non-last-covering caregiver → POST `…/deactivation` → status inactive, coverage re-derived.
11. Deactivate the last covering caregiver → blocked (client guard) → blocking modal, cuidador stays active.
12. Deactivate the last covering caregiver with guard bypassed → BE 409 → blocking modal, cuidador stays active.
13. "Convidar cuidador" hidden when caller lacks `acs.cuidador.write`.
14. Desativar action disabled when caller lacks `acs.cuidador.write`.
15. Cuidadores nav item hidden when caller lacks `acs.cuidador.read` (non-coordinator redirected from roster).
16. Invite error (ProblemDetail) → toast, draft preserved, nothing marked saved.

### patient-linkage.feature
1. Open vínculos panel → linked caregivers + unlinked candidates render with coverage header "Coberto (n)".
2. Link a candidate cuidador to the paciente → POST `…/links` → coverage re-derived, "Coberto (n+1)".
3. Link a cuidador already linked to the paciente → idempotent 200 → no duplicate vinculo.
4. Unlink a non-last covering caregiver → DELETE `…/links/{linkId}` → coverage re-derived.
5. Unlink the last covering caregiver → blocked (client guard) → blocking modal, vinculo unchanged.
6. Unlink the last covering caregiver with guard bypassed → BE 422 → blocking modal, vinculo unchanged.
7. Link a cuidador from a different empresa → 422 cross-tenant-link → blocking modal, coverage unchanged.
8. Link an unknown paciente reference → 404/422 unknown-patient → inline error.
9. Link/unlink error → coverage re-fetched and re-derived to stay truthful.
10. Vincular / desvincular actions disabled when caller lacks `acs.vinculo.write`.
11. An inactive linked caregiver is excluded from the paciente coverage count.

### tenant-onboarding.feature
1. Provision empresa in onboarding step 1 → POST `/tenants` → 201 active → active empresa context written.
2. Provisioning returns 202 → provisioning empresa state shown, active empresa context not written.
3. Provisioning retry → `provisioning:retry` → active → empresa context written.
4. Provisioning still not active (409 tenant-not-active) → retryable banner, empresa not reported active.
5. Criar empresa action disabled when caller lacks `acs.tenant.write`.
6. Register primary caregiver + link in step 5 → paciente becomes covered.
7. Tenant setup and caregiver link steps composed in the wizard contribute no ACS breadcrumb (onboarding owns the trail).
8. PAC and EDGE onboarding steps composed only at the shell page level (no pac/edge scope imported by ACS).
