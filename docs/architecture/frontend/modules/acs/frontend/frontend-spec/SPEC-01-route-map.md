# SPEC-01 — Route Map — ACS (Frontend)

> Module: **ACS — Cuidadores e Acesso** · Nx scope `@neuroassist` · Entry lib `@neuroassist/acs` (ADR-006)
> Project: NeuroAssist AI · Generated by `/fe-architect-specs neuroassist-ai ACS` · 2026-07-29
> Sources: FE 02 §3/§4, FE 04 §5, FE 05 §6, BE `api-contract.md` (§3 tenants, §4 caregivers, §5 links),
> ADR-005 (coverage invariant), ADR-006 (module-as-library), BE ADR-004/005/006.

ACS **is a top-level nav destination** (the "Cuidadores / Acesso" entry, FE 04 §7), coordinator-gated. Its
shell entry is a library loaded lazily by the `scope:web` shell via
`loadChildren: () => import('@neuroassist/acs')`. Sub-views are `loadComponent`. ACS is unique: it is the
module that **sets** the active tenant (`X-Empresa-Id`) the rest of the app rides on. Every admin route is
tenant-scoped and guarded; the tenant-setup step is the one surface that runs *before* a tenant is active.

| Composition host | Component | Feature Lib | Wiring |
|---|---|---|---|

## 2. Route composition & lazy strategy

- Shell → `@neuroassist/acs` via `loadChildren` (whole module lazy).
- `ACS_ROUTES[]` (in `libs/acs/shell-entry/src/lib/acs.routes.ts`) declares the four sub-views via
  `loadComponent`, each with `canActivate: [authGuard, acsCoordinatorGuard]`; the caregiver-editor routes add
  `acsCaregiverWriteGuard`, the linkage route adds `acsLinkWriteGuard`.
- The caregiver-editor route is shared by "novo" and "editar"; `:cuidadorId` presence selects create vs edit
  mode.
- Deep-link to `/acs/cuidadores/:cuidadorId/editar` (or `/acs/pacientes/:pacienteId/vinculos`) for an
  unknown/foreign-tenant id resolves to a not-found redirect (mapped from BE `404 /errors/caregiver-not-found`
  / `404 /errors/tenant-not-found`, SPEC-07).
- `TenantSetupComponent` is the only ACS surface reachable **before** an active tenant exists; it runs solely
  as a composed onboarding step, never as a standalone `scope:acs` route.

## 3. Guard contracts

| Guard | Lib | Rule |
|---|---|---|
| `authGuard` | `@neuroassist/shared/access-decision` | authenticated session present |
| `acsCoordinatorGuard` | `libs/acs/access` | caller holds a coordinator-capable `papel` (`coordenador_clinica` or the bootstrap conductor); a `cuidadora` is redirected away from the roster/admin surface (FE 02 §5) |
| `acsCaregiverWriteGuard` | `libs/acs/access` | caller holds `acs.cuidador.write` (UI defense-in-depth; BE enforces `acs.cuidador.criar`/`acs.cuidador.desativar`) |
| `acsLinkWriteGuard` | `libs/acs/access` | caller holds `acs.vinculo.write` (UI defense-in-depth; BE enforces `acs.vinculo.criar`/`acs.vinculo.revogar`) |

## Criterios de aceite (EARS)

> Clauses are one clause each and free of dotted identifiers so the coverage gate extracts them whole; each
> shares domain nouns with a `Scenario:` title in `e2e/`.

- THE SYSTEM SHALL expose the Cuidadores route rendering the caregiver roster for the active empresa.
- WHEN the coordinator opens the novo cuidador route, THE SYSTEM SHALL render the caregiver editor with a blank
  draft in editing state.
- WHEN the coordinator opens the editar cuidador route for an existing cuidador, THE SYSTEM SHALL render the
  caregiver editor pre-filled from that cuidador.
- WHEN the coordinator opens the vinculos route for a paciente, THE SYSTEM SHALL render the patient linkage
  panel scoped by the empresa header.
- IF the caller is not a coordinator, THEN THE SYSTEM SHALL redirect the caregiver away from the Cuidadores
  roster surface.
- IF the caller lacks the cuidador write permission, THEN THE SYSTEM SHALL block the caregiver editor route and
  keep the caregiver editor hidden.
- IF the caller lacks the vinculo write permission, THEN THE SYSTEM SHALL block the patient linkage route.
- IF the editar route references a cuidadorId unknown to the active empresa, THEN THE SYSTEM SHALL redirect to
  the not-found view.
- WHILE the caller is a coordinator of the active empresa, THE SYSTEM SHALL keep the Cuidadores nav item
  visible.
