## [INT-FE-ACS-001] HTTP interceptors — X-Empresa-Id + Authorization + X-Correlation-Id + Idempotency-Key wiring

**Status:** 🔲 ABERTA
**GitHub:** [#TBD]

**Outcome:**
All ACS HTTP requests carry the required headers: `Authorization: Bearer <JWT>` (from auth-session),
`X-Empresa-Id` (from empresa-context — set by ACS's `AcsTenantFacade` after provisioning), and
`X-Correlation-Id` (from shared HTTP base). Idempotency-Key is generated per user-initiated `POST` create
inside the facade (not via interceptor). Tenant provisioning requests (`POST /tenants`) do NOT carry
`X-Empresa-Id` (no active tenant yet).

**Context / Problem statement:**
- `contracts/backend-api-cross-link.md §1` defines all four headers and their sources.
- `X-Empresa-Id` comes from `@neuroassist/shared/empresa-context`; the shared HTTP interceptor reads it and
  attaches it to all ACS requests — EXCEPT the tenant create/retryProvisioning routes (which run before a tenant exists).
- This is a BE-alignment concern: the BE derives the acting tenant from the JWT `tenant` claim (authoritative),
  but `X-Empresa-Id` is still sent as a hint and must match.
- ACS-FE holds NO auth logic (FE 02 §1); `Authorization` header is managed by the shared `auth-http` interceptor.
- Bloqueia: FE-ACS-007..012 (all clients depend on correct headers)

**Approach (execution path):**
1. Verify the shared `@neuroassist/shared/access-http-base` interceptor chain covers Authorization + X-Empresa-Id
   + X-Correlation-Id for `scope:acs` requests.
2. Confirm there is a route exclusion or conditional for `/api/v1/acs/tenants` POST (no X-Empresa-Id pre-tenant).
3. If the shared interceptor does not handle the exclusion, add an ACS-specific HTTP interceptor in
   `libs/acs/data-access/src/lib/acs-http.interceptor.ts` that strips X-Empresa-Id for tenant provisioning
   requests.
4. Idempotency-Key: NOT an interceptor concern — generated by facades (AcsTenantFacade, AcsCuidadorFacade)
   per request (FE-ACS-007, FE-ACS-010).
5. Integration test: verify correct headers on each request type using `HttpClientTestingModule`.

**Non-goals:**
- No auth token management (shared `auth-session`).
- No Idempotency-Key interceptor (façades manage it).
