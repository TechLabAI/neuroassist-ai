# 03 — Domain Framing (Frontend) — EVNT

> Mirror of the backend domain — do **not** redefine terms here. See `_brief.md`
> and the BE `03-domain-framing` for EVNT (once generated). This document only
> frames how the shared vocabulary shows up on screen.

## 1. Ubiquitous language (mirror of BE)

| Term | Meaning (as used on screen) |
|---|---|
| **Evento** | A structured occurrence generated by `evnt-service` from a recognized command. The unit EVNT-FE renders and confirms. |
| **Comando** | The patient's catalog item (owned by PAC) bound to the event; carries `urgencia` and the family `rótulo`. |
| **urgencia** | `emergencia` \| `rotina` — drives the visual treatment (full-bleed vs discreet). Resolved from `Comando`, never from the label. |
| **rótulo** | The family's free-text word for the command (e.g. "água", "Ajuda"). Shown to the caregiver; not a system description. |
| **confirmadoEm / confirmadoPor** | The attendance confirmation timestamp + caregiver id, written by EVNT-FE on confirm. |
| **feedback** | `nao_avaliado` \| `real` \| `falso_positivo` — set later in **HIST**, not in EVNT-FE. |
| **evento ativo** | The single unconfirmed `emergencia` event currently driving the alarm state. |

## 2. View models (draft)

**AlarmVM** (feature-alarm)
- `eventId: string`
- `patientName: string` (resolved for display)
- `commandLabel: string` (`Comando.rotulo`, quoted)
- `detectedAt: string` (formatted "14h32")
- `isEmergency: true` (invariant for this VM)
- `confirming: boolean`
- `confirmError: string | null`

**RoutineNoticeVM** (feature-routine)
- `eventId: string`
- `commandLabel: string`
- `detectedAt: string`
- `urgency: 'rotina'`
- `dismissed: boolean`

**ActiveStateVM** (consumed by Home/DASH, exported from facade)
- `hasActiveAlarm: boolean`
- `activeEventId: string | null`
- `lastEventAt: string | null`
- `deliveryMode: 'live' | 'degraded'`

## 3. UI events (user-triggered, change state)

| Event | Trigger | Effect |
|---|---|---|
| `ConfirmAttendance` | Press "Confirmar que atendi Márcio" | POST confirm → `confirmadoEm/Por` → clear alarm |
| `DismissRoutine` | Dismiss a routine notice | Remove from routine queue (client-side) |
| `RetryConfirm` | Retry after a failed confirm | Re-POST confirm; alarm stays until success |
| `AcknowledgeDegraded` | Acknowledge degraded banner | Hide banner (polling continues) |

## 4. State transitions (UI level)

```
idle
  │  emergencia event delivered
  ▼
alarm-active ──ConfirmAttendance──▶ confirming ──success──▶ confirmed ──▶ idle
  │  ▲                                   │
  │  └────────────confirm fails──────────┘  (back to alarm-active, error shown)
  │
  │  rotina event delivered
  ▼
routine-notice (non-blocking; coexists, does not leave idle for alarm purposes)

any state ──live channel drops──▶ delivery-degraded (polling) ──recovers──▶ prior state
```

Invariant across transitions: **only `ConfirmAttendance` success leaves
`alarm-active`.** No timeout, no navigation, no auto-dismiss clears an emergency.

## 5. Invariants (client-side)

- **Single active alarm.** At most one `emergencia` event drives the overlay at a
  time; a newer emergency replaces the current VM only after (or alongside)
  confirmation policy defined by BE — FE never drops an unconfirmed emergency
  silently.
- **Urgency is authoritative from data.** FE must not up/down-grade urgency; it
  reads `Comando.urgencia` as delivered.
- **Confirmation is mandatory and attributed.** The confirm action is disabled
  only while `confirming`; on success both `confirmadoEm` and `confirmadoPor` must
  be present (BE-assigned actor from the authenticated session).
- **Routine is non-blocking.** A `rotina` notice must never take focus or block
  interaction, and must be dismissible.
- **Tenant isolation.** Events shown belong only to patients within the caregiver's
  tenant (enforced BE-side; FE never requests cross-tenant).
- **Idempotent confirm.** Retrying confirm on the same event must be safe; a late
  confirm on an already-confirmed event surfaces "Já confirmado por …", not an error.
