## 1. Canonical name and prefix
- **Prefix:** `GEST`
- **Canonical name:** `gest`
- **Service:** `gest-service` (Java 21 / Spring Boot backend module)

## 2. Problem the module solves
Patients with neurodegenerative disease produce only small residual voluntary facial
movements. The system must know **which facial-movement primitives can actually be recognized**
and turn a live classification of the active command into a structured signal — while the
raw computer-vision detection itself runs on the patient's local device, never in the cloud.

## 3. Personas
- **Primary:** Danilo Amaral (technical conductor / onboarding operator) — configures which
  gesture primitives the edge engine should classify and pairs the detection profile to a device.
- **Secondary:** Jamilly Amaral (family caregiver) — indirectly consumes GEST via PAC/DASH when
  she registers a new gesture type on the calibration screen and needs to know whether that
  gesture is *actually detectable yet* (not merely named).

## 4. MVP scope (in)
- Authoritative **TipoGesto** primitive catalog (facial-movement vocabulary) owned by the backend.
- **Detectability lifecycle** per primitive: `registered → pending-training → supported` (resolves
  the recurring `TODO[arquiteto]` in Framing §6.1/§7.1a/§9.3 — a registered *name* is not a
  detectable *movement*).
- **Detection profile** provisioning: a versioned bundle (supported primitives + classification
  parameters) that the edge `GestureDetectionEngine` pulls to configure itself.
- **Detection contract**: the schema/protocol the edge uses to report a recognized command
  (classified primitive(s) + confidence + timing), consumed downstream by EVNT.

## 5. Out of scope (MVP)
- The computer-vision detection itself (webcam capture, MediaPipe landmarks, classification) — that
  is the **edge deployable**, a separate non-Java process (ADR-005 local: edge/cloud split).
- Model training / retraining pipelines for new primitives (only the *lifecycle state* is modeled).
- Event persistence, alarm orchestration and notification (EVNT), device pairing/heartbeat (EDGE),
  patient command mapping `Comando` (PAC), audit trail (HIST).
- Any video/image leaving the edge device (hard privacy invariant, Framing §2.1).

## 6. Mandatory external integrations
- **Edge agent (`GestureDetectionEngine`)** — separate deployable on the patient's device; pulls
  the detection profile over REST/HTTPS and posts recognized-command telemetry. Not a third-party
  API — an in-product edge process outside the Java service boundary.
- **MediaPipe (or equivalent landmark library)** — a dependency *of the edge agent only*, never of
  gest-service. GEST models only which primitives the engine claims to support.

## 7. Hub / TechLab AI dependencies & inter-module contracts
- **TechLab AI services:** none. `ai.hasAi = false`; the "AI" here is deterministic computer vision
  on the edge, not generative (Framing §2.5/§9.1).
- **Messaging:** disabled (`stack.messaging.enabled = false`) → inter-module calls are synchronous
  REST between independent services (routed via GWY, discovered via REG). No event bus in the MVP.
- **Consumed by:** PAC (references TipoGesto from GEST when building `Comando`), EVNT (consumes the
  detection contract to build `Evento`), EDGE (delivers the detection profile to the paired device),
  DASH (surfaces primitive detectability status to the caregiver).

## 8. Domain anchor event
- **"Gesture primitive recognized"** (edge classifies the active command's primitive with a
  confidence over threshold). GEST owns the *vocabulary and detectability* of that recognition;
  EVNT owns the resulting business `Evento`.
