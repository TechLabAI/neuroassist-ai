# PEA — Events Published

**Component:** Python Edge Agent | **Date:** 2026-07-29

The PEA publishes one event type: `GestoDetectado`. This is a synchronous REST call
(not a message broker — messaging is disabled in MVP per project-context.json).

---

## Event: GestoDetectado

### Trigger

Emitted when `CommandMatcher` confirms a `Comando` match:
- `primitivoPrincipal` detected continuously for [`tempoMinGestoMs` .. `tempoMaxGestoMs`]
- If compound: `primitivoSecundario` detected within 500ms after the primary window closes
- Classifier confidence ≥ threshold derived from `Comando.sensibilidade`:
  - `alta` → 0.90
  - `media` → 0.75
  - `baixa` → 0.60

### Payload

```json
{
  "eventId":             "uuid-v4 — idempotency key; generated by PEA per match",
  "pacienteId":          "uuid — from device config",
  "comandoId":           "uuid — matched Comando ID",
  "tipoGestoPrincipal":  "string — TipoGesto.code, e.g. 'piscar_direito'",
  "tipoGestoSecundario": "string | null — second primitive code for compound commands",
  "confianca":           "float [0.0-1.0] — classifier confidence (primary primitive)",
  "durationMs":          "integer — actual gesture hold duration in ms",
  "capturedAt":          "ISO-8601 UTC — timestamp when the gesture window closed",
  "deviceId":            "uuid — enrolled device ID"
}
```

### Transport

```
POST {backend.url}/api/v1/evnt/events
Authorization: Bearer {access_token}
X-Empresa-Id: {device.tenant_id}
X-Idempotency-Key: {eventId}
X-Correlation-Id: {session_correlation_id}
Content-Type: application/json
```

### Delivery guarantees

| Scenario | Behavior |
|---|---|
| EVNT returns `202 Accepted` | Event delivered; removed from outbox |
| EVNT returns `409 Conflict` | Duplicate (already delivered); removed from outbox |
| EVNT returns `401 Unauthorized` | Refresh JWT; retry once; if auth fails → event stays in outbox |
| EVNT returns `422` + `unknown-command` | Event dropped; vocabulary re-fetch triggered |
| EVNT `5xx` / timeout / network error | Event retained in SQLite outbox; back-off retry |
| Outbox full (> 50 events) | Oldest event dropped; ALERT logged |

### Idempotency

`eventId` is a UUID v4 generated at match time and persisted in the outbox row. On retry,
the same `eventId` is reused as `X-Idempotency-Key`, so EVNT can detect and discard duplicates.

### EARS invariants

- WHEN a `Comando` is matched → exactly one `GestoDetectado` event is enqueued in the outbox
- WHEN the same gesture is detected within the cooldown window (`tempoMaxGestoMs + 200ms`) → no event is emitted (debounce)
- WHEN EVNT is unreachable → event is buffered (outbox) and retried; the detection loop continues uninterrupted
- WHEN outbox exceeds 50 events → the oldest event is silently dropped and logged at ALERT level; caregiver may miss alarms

## Domain facts the PEA does NOT publish

The following audit facts are published by the **Java backend** (not by the PEA):
- `AutenticacaoRealizada` / `AutenticacaoFalhou` — emitted by `acs-service` (ACS-006)
- `EventoCriado` — emitted by `evnt-service` upon receiving `GestoDetectado`
- `AlarmeRotacionado` — emitted by `evnt-service` after routing

The PEA only publishes the raw gesture event. All downstream processing and audit
are responsibility of the backend services.
