## Contexto
O header `Idempotency-Key` em `POST /pacientes` e `POST .../comandos` permite que clientes reenviem
a mesma requisição com segurança (ex.: retry por timeout). Se a key já foi vista com o mesmo body,
retorna o resultado original com `200`. Se a key foi vista com body diferente, retorna `409
/errors/idempotency-mismatch`. TTL de 24h. Derivado de SPEC-05.

- SPEC-01 §1.1 (Idempotency-Key header), §9 (edge cases)
- `contracts/api-contract.md` §1 (Idempotency-Key header)

      1) extrair `Idempotency-Key` header (se ausente → pass-through sem dedup);
      2) buscar no store por `(key, tenantId)`;
      3) se encontrado com mesmo hash → retornar response original + `200` (com ETag do resource original);
      4) se encontrado com hash diferente → `409 /errors/idempotency-mismatch`;
      5) se não encontrado → prosseguir, armazenar response no store pós-execução
