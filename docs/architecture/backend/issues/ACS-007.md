# ACS-007 -- Implementar JwkSetController + SigningKeyPublisher (GET /oauth2/jwks)

## Contexto

`GET /oauth2/jwks` é o endpoint público crítico que todos os resource servers (GEST, EVNT, PAC,
EDGE, DASH, HIST) usam para validar tokens ACS sem callback. Publica a chave ativa + todas as
chaves `retired` cujo `retired_at` está dentro de um TTL de 900s (para suportar tokens em-voo
durante rotação de chave — SPEC-03 §6). Responde com `Cache-Control: max-age=300`. Nunca expõe
`private_key_enc` — somente os campos públicos RSA (`n`, `e`, `kid`, `kty`, `use`, `alg`).

## Spec de referência

- SPEC-03 §6 (EARS invariants — JWK set)
- `contracts/api-contract.md §2.2`
- SPEC-01 §6 (status matrix: GET /oauth2/jwks → 200, nenhum erro)

## Escopo

- [ ] criar `JwkSetController` em `api/controller/`:
      `GET /oauth2/jwks` — público (sem Bearer); retorna `JwkSetResponse` com `keys[]`;
      header `Cache-Control: max-age=300` na resposta
- [ ] criar `SigningKeyPublisher` em `application/service/`:
      método `getPublicJwkSet(): JwkSetResponse` que:
      (a) carrega chaves via `SigningKeyPort.getPublicKeys()` (active + recently retired),
      (b) extrai apenas campos públicos de cada chave (`kty`, `use`, `kid`, `alg`, `n`, `e`),
      (c) monta `JwkSetResponse { keys: List<Map<String, Object>> }`
- [ ] garantir que `private_key_enc` nunca aparece no payload da resposta nem em nenhum campo
- [ ] criar `JwkSetResponse` DTO em `api/dto/`

## Resultado esperado

`GET /oauth2/jwks` retornando a chave pública ativa + chaves retired recentes, com
`Cache-Control: max-age=300`, sem exposição de material privado.

## Critérios de aceite

- [ ] Resposta contém campo `keys` com ao menos 1 objeto (chave ativa)
- [ ] Cada objeto em `keys` tem exatamente `{kty, use, kid, alg, n, e}` — sem `d`, `p`, `q` ou campos privados
- [ ] Header `Cache-Control: max-age=300` presente na resposta
- [ ] Endpoint responde `200 OK` sem Bearer token (público)
- [ ] Chave com `status = retired` e `retired_at > now() - 900s` aparece no JWK set
