## Contexto

O mesmo valor viaja com três nomes no token e dois no header:

| Camada | Nomes em uso | Canônico |
|---|---|---|
| Claim JWT | `tenant_id`, `tenant`, `empresaId` | `tenant_id` |
| Header HTTP | `X-Empresa-Id` (PAC, rejeita 400 sem ele), `X-Tenant-Id` (demais) | `X-Tenant-Id` |

Os aliases foram um shim de compatibilidade durante a integração. Cada um é um lugar a mais onde
um serviço novo pode ler o nome errado e resolver o tenant como nulo — e resolver tenant errado,
neste sistema, é vazar dado clínico entre empresas.

Relacionado: o gateway não injeta header de tenant nenhum (`grep -i "tenant|empresa"` no `src/main`
do api-gateway retorna zero), então cada serviço extrai do JWT por conta própria.

## Escopo

1. Todos os resource servers passam a ler `tenant_id` (mantendo a leitura dos aliases)
2. `TokenIssuer` para de emitir `tenant`/`empresaId`
3. PAC aceita `X-Tenant-Id`, mantendo `X-Empresa-Id` por uma versão
4. Remoção dos aliases dos dois lados

Ordem importa: emitir só o canônico antes de todos lerem o canônico quebra tudo de uma vez.

## Checklist

- [ ] Inventário de onde cada alias é lido, serviço a serviço
- [ ] Passo 1 (leitura canônica em todos) verde no E2E
- [ ] Passo 2 (emissão só do canônico)
- [ ] Passo 3 (header canônico no PAC)
- [ ] Passo 4 (remoção dos aliases) + teste negativo: token só com alias antigo é rejeitado
- [ ] Decidir se o gateway passa a injetar o header (hoje não injeta)
