# PEA-003 -- VocabularyCache: fetch do GEST API + cache SQLite + refresh

**Status:** PENDENTE | **Prioridade:** P1 | **Estimativa:** S

## Spec de referência

- `contracts/api-consumed.md §2` (GEST vocabulary endpoint)
- `contracts/data-model.md §2` (tabela `vocabulary_cache`)

## Escopo

- [ ] implementar `VocabularyCache` em `vocabulary.py`
  - fetch `GET /api/v1/gest/vocabulary/{pacienteId}/active` com `If-None-Match: {version}`
  - persistir em SQLite (`vocabulary_cache` table) via `aiosqlite`
  - background refresh a cada 5 minutos (asyncio task)
  - tratamento `304 Not Modified` → skip parse, usar cache
  - tratamento `410 Gone` → forçar re-fetch imediato
  - `get_active_vocabulary() -> list[Comando]` — retorna lista parseada
- [ ] startup: fetch síncrono (blocking); falhar com `VocabularyUnavailableError` se GEST unreachable E sem cache
- [ ] expor `async def invalidate()` para uso pelo `EventPublisher` em caso de `422 unknown-command`

## Critérios de aceite

- [ ] primeira chamada → HTTP GET ao GEST; segunda chamada (< 5min) → cache sem HTTP
- [ ] `410 Gone` → re-fetch imediato (validado em unit test com mock)
- [ ] GEST unreachable + cache existente → retorna cache + log WARN
- [ ] GEST unreachable + sem cache → `VocabularyUnavailableError`
