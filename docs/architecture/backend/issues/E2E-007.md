# E2E-007 — EVNT ↔ DASH: dispatch de notificação + ack callback

## Objetivo

Verificar o ciclo completo de notificação: EVNT detecta evento e faz dispatch para DASH (`POST /internal/notifications`); DASH entrega via SSE ao cuidador e callback `delivered`/`acknowledged` retorna ao EVNT; idempotência por `dispatchId` garantida.

## Fluxo

```
EVNT cria Evento
  → EVNT → DASH: POST /internal/notifications { dispatchId, tier, targetCaregiverId, ... }
  → DASH → cuidador: SSE frame "evento.created"
  → DASH → EVNT: callback delivered(dispatchId)
  → cuidador: POST /panel/notifications/{id}/acknowledge
  → DASH → EVNT: callback acknowledged(dispatchId)
  → EVNT: EventoConfirmado persisted
  → HIST: audit fact EventoConfirmado
```

## Cenários de Validação

| ID | Cenário | Critério |
|---|---|---|
| NTF-01 | Evento criado → dispatch → cuidador com sessão SSE aberta | `delivered` callback chega ao EVNT; SSE frame recebido |
| NTF-02 | Cuidador sem sessão aberta | DASH responde `no_open_session`; EVNT agenda retry |
| NTF-03 | `dispatchId` duplicado → idempotência | reenvio do mesmo `dispatchId` → sem duplo `delivered` |
| NTF-04 | DASH indisponível → retry budget EVNT | parar DASH → EVNT faz retries; não bloqueia fluxo principal de eventos |
| NTF-05 | Cuidador confirma → `acknowledged` → EVNT → HIST | `POST /panel/notifications/{id}/acknowledge` → `EventoConfirmado` em HIST |

## Invariantes (dos contratos)

- DASH nunca decide a `tier` (urgência → tier é política do EVNT)
- `dispatchId` é a chave de idempotência no DASH — janela = lifetime do dispatch em memória
- Callbacks são synchronous REST (não SSE) do DASH para o EVNT

## Checklist

- [ ] NTF-01: SSE frame recebido + `delivered` callback no EVNT
- [ ] NTF-02: `no_open_session` → sem falsa entrega; retry agendado
- [ ] NTF-03: segundo envio do mesmo `dispatchId` ignorado silenciosamente
- [ ] NTF-04: DASH down → EVNT retries; evento não perdido
- [ ] NTF-05: ack completa o ciclo até HIST
