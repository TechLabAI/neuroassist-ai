# E2E-005 — Heartbeat EDGE ↔ GEST + degraded mode

**Módulo:** E2E Cross-Service  
**Fase:** F5 — EDGE ↔ GEST  
**Prioridade:** P2  
**Status:** OPEN  
**Criado em:** 2026-08-20  
**Plano:** [plan-e2e-integration.md](../plans/plan-e2e-integration.md)

---

## Objetivo

Verificar que o heartbeat do dispositivo edge retorna o ponteiro de versão do perfil de detecção ativo (consultado em GEST), que o drift é detectado corretamente, e que o comportamento degradado (GEST indisponível) não bloqueia a liveness do dispositivo.

## Fluxo

```
Edge agent → POST /api/v1/edge/devices/{id}/heartbeat
                → EDGE consulta GEST: GET /api/v1/gest/detection-profiles/active
                → EDGE retorna { currentProfileVersion, profileDrift, ... }
```

## Cenários de Validação

| ID | Cenário | Critério |
|---|---|---|
| HB-01 | Heartbeat retorna `currentProfileVersion` | campo = versão ativa em GEST (não nulo) |
| HB-02 | `profileDrift: true` quando device roda versão antiga | `runningProfileVersion` < ativo → `profileDrift: true` |
| HB-03 | GEST indisponível → heartbeat aceito degradado | parar GEST → `200` + `profilePointerDegraded: true` |
| HB-04 | GEST sem perfil ativo → heartbeat OK | sem perfil ativo em GEST → `currentProfileVersion: null`, `profileDrift: false` |
| HB-05 | Circuit breaker EDGE→GEST abre | timeout GEST 10x → CB OPEN; degraded aceito imediatamente |

## Invariantes (dos contratos)

- Heartbeat NUNCA falha por causa do GEST — liveness não depende de GEST (ADR-006)
- EDGE não envia dados biométricos ou de paciente para GEST (apenas `tenant` via service token)
- `X-Correlation-Id` deve ser propagado em todas as chamadas EDGE → GEST

## Checklist

- [ ] HB-01: `currentProfileVersion` retornado e igual ao ativo em GEST
- [ ] HB-02: drift detectado corretamente
- [ ] HB-03: modo degradado — heartbeat `200` sem `currentProfileVersion`
- [ ] HB-04: sem perfil ativo → campos nulos sem erro
- [ ] HB-05: CB OPEN após threshold; falha rápida sem esperar 2s timeout

## Dependência
