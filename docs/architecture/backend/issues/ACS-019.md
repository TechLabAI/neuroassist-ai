# ACS-019 -- Implementar Spring Security dual-mode (OAuth2 AS + Resource Server) + @PreAuthorize

**Status:** INTACT -- gerado 2026-07-29
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/5 itens

## Contexto

ACS é simultaneamente OAuth2 Authorization Server (emite JWTs) e Resource Server (valida JWTs
nas rotas admin/diretório). Isso requer configuração cuidadosa do Spring Security para não criar
conflito entre os dois filtros. Público: `/oauth2/token`, `/oauth2/jwks`, `/actuator/health`.
Todo o resto exige `Authorization: Bearer <jwt>` válido.

## Spec de referência

- SPEC-03 §3 (technical decisions: Spring Authorization Server, dual mode)
- SPEC-06 §4 (EARS: autoridades por endpoint, LGPD guards, HTTPS enforcement)

## Escopo

- [ ] configurar `AuthorizationServerConfig` (Spring Authorization Server):
      token TTL 900s, issuer `acs-service`, RS256, registrar `jwk-set-uri` aponta para si mesmo
- [ ] configurar `ResourceServerConfig` (Spring Security Resource Server):
      `jwk-set-uri = http://acs-service/oauth2/jwks` (via REG); validate `iss = acs-service`
- [ ] allowlist público: `/oauth2/token`, `/oauth2/jwks`, `/actuator/health`, `/actuator/info`
- [ ] todo endpoint admin/diretório: `authenticated()` + `@PreAuthorize("hasAuthority('...')")`
      (sem método sem anotação — closed by default)
- [ ] CORS: permitir apenas origem Angular configurada; bloquear outros origins
- [ ] HTTPS: `requiresChannel().anyRequest().requiresSecure()` (exceto perfil `local`)

## Critérios de aceite

- [ ] `GET /oauth2/jwks` sem token → `200 OK`
- [ ] `POST /api/v1/acs/tenants` sem token → `401 unauthenticated`
- [ ] `POST /api/v1/acs/tenants` com token `cuidadora` → `403 insufficient-authority`
- [ ] `POST /api/v1/acs/tenants` com token `acs.tenant.provisionar` → `201` (smoke)
- [ ] Token com `iss != acs-service` → `401 unauthenticated`
