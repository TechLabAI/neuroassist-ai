## Contexto

`LinkService` orquestra o ciclo de vida do vínculo cuidador↔paciente (ADR-006). Valida
same-tenant via `PacPatientResolvePort` (fail-closed), aplica idempotência, coverage check
na revocação, e emite os eventos âncora ao HIST.

## Spec de referência

- SPEC-05 (EARS: linkage lifecycle, coverage invariant, idempotency, PAC port)
- `contracts/api-contract.md §5`
- `contracts/event-contracts.md §2.2` (PacPatientResolvePort timeout 2s)

## Escopo

- [ ] criar `LinkService` em `application/service/` com métodos:
      `createLink(cuidadorId, pacienteId, tenantId): CaregiverPatientLinkSnapshot`
        → valida via `PacPatientResolvePort.resolvePatient(pacienteId, tenantId)` (fail-closed 2s)
        → verifica same-tenant → idempotência (`ux_link_active`) → persiste → emite `CuidadorVinculadoAoPaciente`
      `revokeLink(linkId, cuidadorId, tenantId): CaregiverPatientLinkSnapshot`
        → coverage check → soft revoke → emite `CuidadorDesvinculado`
      `listLinks(cuidadorId, tenantId, status?): List<CaregiverPatientLinkSnapshot>`
- [ ] aplicar Resilience4j no `PacPatientResolvePort`: timeout 2s, 1 retry, circuit breaker OPEN → `502 upstream-unavailable`
- [ ] lançar `CrossTenantLinkException` (422) se tenant mismatch
- [ ] lançar `UnknownPatientException` (422) se PAC retornar 404
- [ ] emitir `CuidadorVinculadoAoPaciente` e `CuidadorDesvinculado` via `HistAuditPort` (best-effort)

## Critérios de aceite

- [ ] Vínculo já ativo → `200 OK` idempotente, sem nova linha
- [ ] Tenant diferente → `422 cross-tenant-link`
- [ ] PAC 404 → `422 unknown-patient`
- [ ] PAC timeout → `502 upstream-unavailable`
- [ ] Revogar último vínculo sem coordinator → `409 last-caregiver-link`
- [ ] `CuidadorVinculadoAoPaciente` registrado no HIST
