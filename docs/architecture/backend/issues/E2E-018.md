## Contexto

```
grep -rn "@CircuitBreaker" backend/services/dash-service/src/main → 0 ocorrências
```

O `application.yml` do dash-service declara breakers e time limiters resilience4j que **nada
anota**. O DASH é um BFF: agrega ACS, PAC, EVNT, HIST e EDGE em resposta a uma requisição de
painel. Sem breaker, um único upstream lento segura threads do dashboard inteiro — e o painel é o
que a cuidadora tem aberto quando o alarme chega.

É o caso mais nítido do padrão "guarda que não guarda nada" registrado em CLAUDE.md: a
configuração dá a impressão de proteção existente.

## Escopo

- `@CircuitBreaker` + fallback explícito em cada adapter Feign do DASH
- O fallback **degrada com honestidade**: o painel diz qual bloco não carregou, em vez de devolver
  vazio como se não houvesse dados (a lição do `DetectionProfilePort` de três estados no EDGE)
- Time limiter onde a agregação é síncrona
- Teste que derruba um upstream e afirma que os demais blocos continuam renderizando

## Checklist

- [ ] Inventário dos adapters Feign do DASH e do que cada um alimenta no painel
- [ ] `@CircuitBreaker(name=..., fallbackMethod=...)` em cada um
- [ ] `ignoreExceptions` para 4xx — 403 não é degradação (armadilha registrada em CLAUDE.md)
- [ ] Estado degradado visível na resposta, distinto de "sem dados"
- [ ] Teste de upstream indisponível por adapter
- [ ] Remover da config qualquer breaker que continue sem dono

## Critério de aceite

Parar o hist-service: o painel carrega, a timeline aparece marcada como indisponível, e os demais
blocos não são afetados.
