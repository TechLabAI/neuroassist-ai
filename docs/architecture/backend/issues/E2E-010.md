## Objetivo

Validar o ciclo de vida completo de um dispositivo edge: registro, vinculação ao tenant, pareamento ao paciente, primeiro heartbeat (com profile pointer do GEST), verificação do audit trail no HIST e liveness no DASH.

## Fluxo Completo

```
1. POST /api/v1/edge/devices/:register
      → EDGE registra dispositivo com device credential (service token ACS)
      
2. POST /api/v1/edge/devices/:claim
      → EDGE vincula device ao tenant (device passa a ser do tenant)
      
3. POST /api/v1/edge/devices/:enroll
      → EDGE pareia device ao paciente
      → HIST: fact DispositivoPareado
      
4. POST /api/v1/edge/devices/{id}/heartbeat
      → EDGE → GEST: GET /detection-profiles/active
      → resposta contém currentProfileVersion + profileDrift
      
5. GET /api/v1/hist/history?deviceId={id}
      → HIST retorna DispositivoPareado auditado
      
6. GET /api/v1/edge/devices/{id}/liveness (via DASH)
      → EDGE: status=online (heartbeat dentro do threshold)
      
7. [aguardar > stalenessThresholdSeconds sem heartbeat]
      → GET /liveness → status=offline (derivado em read-time)
```

## Critério de Sucesso (Gate)

- Passos 1–4 retornam 2xx sem erros
- HIST contém `DispositivoPareado`
- Heartbeat retorna `currentProfileVersion` não-nulo
- DASH liveness: `online` logo após heartbeat; `offline` após threshold expirar
