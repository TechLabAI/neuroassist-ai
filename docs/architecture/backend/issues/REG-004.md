## Contexto
SPEC-06 exige que REG nao faca nenhuma decisao de autenticacao/autorizacao -- edge auth (JWT do cuidador / token de dispositivo edge) e responsabilidade do GWY. O plano Eureka (registro/discovery) e platform-internal (network trust). O dashboard Eureka deve ser acessivel a operadores internos mas nao exposto via GWY na borda publica. REG nao le `X-Empresa-Id`, nao propaga contexto de tenant, nao consome JWT.

## Escopo
- [ ] Confirmar ausencia de `spring-boot-starter-security` no `build.gradle.kts` (REG nao valida JWT nem token)
- [ ] Se Spring Security estiver presente por dependencia transitiva, configurar `SecurityFilterChain` que permite acesso ao protocolo Eureka (`/eureka/**`) e dashboard (`/`) sem autenticacao por token
- [ ] Garantir que nenhum filter ou interceptor leia, derive ou propague `X-Empresa-Id` ou qualquer contexto de tenant
- [ ] Documentar em `setup-local.md` que dashboard e protocolo Eureka nao sao expostos via GWY (isolamento por topologia de rede)

## Criterios de aceite
- [ ] `GET /eureka/apps` retorna 200 sem header `Authorization`
- [ ] `GET /` (dashboard Eureka) retorna 200 sem header `Authorization`
- [ ] Nenhuma linha de log de startup ou request contem referencia a tenant / empresa / JWT / token / dados pessoais de paciente ou cuidador
