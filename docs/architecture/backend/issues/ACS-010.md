# ACS-010 -- Implementar CuidadorJpaAdapter (schema empresa, unicidade case-insensitive de login)

**Status:** INTACT -- gerado 2026-07-29
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/4 itens

## Contexto

`CuidadorJpaAdapter` opera no schema empresa (`t_<tenantId>`). Depende do `TenantSchemaResolver`
para rotear queries para o schema correto via `SET search_path`. A unicidade de `login` é
case-insensitive e parcial (`WHERE status = 'active'`) — um login desativado pode ser re-emitido.
O `credential_hash` nunca retorna no DTO de response (filtro no mapper).

## Spec de referência

- SPEC-04 §6 (EARS invariants: `ux_cuidador_login_active`, `ck_cuidador_papel`, `NOT NULL` hash)
- `contracts/data-model.md §2.3`
- SPEC-01 §4.2 (list caregivers — coordenador vê todos; cuidadora vê só a si)

## Escopo

- [ ] criar `CuidadorRepository` (Spring Data JPA) com métodos:
      `findByTenantIdAndLowerLoginAndStatusActive(tenantId, login)` (para auth),
      `findByIdAndTenantId(id, tenantId)`,
      `findByTenantId(tenantId, pageable)`,
      `findByTenantIdAndPapel(tenantId, papel, pageable)` (para listar por papel)
- [ ] criar `CuidadorJpaAdapter` em `infrastructure/persistence/`:
      métodos: `save(Cuidador)`, `findById(UUID, tenantId)`, `listByTenant(tenantId, pageable)`,
      `findByLogin(tenantId, login): Optional<Cuidador>` (case-insensitive via `lower(login)`),
      `deactivate(id, tenantId): void`
- [ ] criar `TenantSchemaResolver` em `infrastructure/tenant/`:
      `setSchema(tenantId)` → executa `SET search_path TO t_<tenantId>, public`;
      integrar via `AbstractRoutingDataSource` ou filter de request multi-tenant
- [ ] mapear `DataIntegrityViolationException` com constraint `ux_cuidador_login_active`
      para `409 login-duplicate` no `GlobalExceptionHandler`

## Resultado esperado

`CuidadorJpaAdapter` resolvendo no schema correto, com lookup case-insensitive de login e
mapeamento de constraint de unicidade para resposta de negócio.

## Critérios de aceite

- [ ] Dois cuidadores com `login` diferindo só em case → `409 login-duplicate` ao criar o segundo
- [ ] Cuidador `inactive` com mesmo `lower(login)` → **não** bloqueia criação de novo cuidador (partial index só em `active`)
- [ ] Query `findByLogin` usa `lower(login)` explicitamente (não `ILIKE` sem índice)
- [ ] Schema routing: query em `t_abc123` nunca retorna dados de `t_def456`
