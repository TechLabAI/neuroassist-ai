**Status:** OPEN

## Objetivo

Verificar que todos os 4 produtores de fatos de auditoria (ACS, PAC, EVNT, EDGE) entregam facts ao HIST corretamente, que a idempotência por `factId` funciona, e que a indisponibilidade do HIST não bloqueia o produtor.

## Produtores e Fatos

| Produtor | Fatos de auditoria |
|---|---|
| ACS | `AutenticacaoRealizada`, `AutenticacaoFalhou` |
| PAC | `ComandoPublicado`, `ComandoRecalibrado`, `ComandoAposentado` |
| EVNT | `EventoCriado`, `EventoConfirmado` |
| EDGE | `DispositivoPareado`, `DispositivoDespareado` |

## Cenários de Validação

| ID | Cenário | Critério |
|---|---|---|
| AUD-01 | Login bem-sucedido → fact em HIST | `AutenticacaoRealizada` visível via `GET /api/v1/hist/audit-facts` |
| AUD-02 | Login falho → fact em HIST | `AutenticacaoFalhou` visível |
| AUD-03 | Comando publicado → fact em HIST | `ComandoPublicado` com `calibracaoVersao` correto |
| AUD-04 | Comando recalibrado → fact em HIST | `ComandoRecalibrado` |
| AUD-05 | Comando aposentado → fact em HIST | `ComandoAposentado` |
| AUD-06 | Evento criado → fact em HIST | `EventoCriado` |
| AUD-07 | Evento confirmado → fact em HIST | `EventoConfirmado` |
| AUD-08 | Dispositivo pareado → fact em HIST | `DispositivoPareado` com `deviceId` correto |
| AUD-09 | Fact duplicado ignorado | reenviar mesmo `factId` → `200` + sem duplicata em HIST |
| AUD-10 | HIST indisponível não bloqueia ACS | parar HIST → ACS login → `200` em ACS; fact na fila de retry |

## Pré-condições

- E2E-001, E2E-002
- Dados mínimos criados: tenant, cuidador, paciente, comando, dispositivo

## Checklist

- [ ] AUD-01..08: cada fact chega ao HIST após ação no produtor
- [ ] AUD-09: mesmo `factId` → não duplica no ledger
- [ ] AUD-10: login retorna `200` mesmo com HIST down; fact reentregue após HIST voltar

## Dependência
