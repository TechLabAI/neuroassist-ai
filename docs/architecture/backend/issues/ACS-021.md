# ACS-021 -- Implementar MDC propagation + structured logging (correlationId, tenantId, userId)

**Status:** INTACT -- gerado 2026-07-29
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/3 itens

## Contexto

Todo log do `acs-service` deve carregar `correlationId` (de `X-Correlation-Id`), `tenantId`
(do JWT `tenant` claim) e `userId` (do JWT `sub`) no MDC. Nenhuma linha de log pode conter
credenciais ou dados biométricos (LGPD hard rule — SPEC-07 §3).

## Spec de referência

- SPEC-07 §3 (EARS: MDC, structured logging, LGPD, INFO/WARN levels)

## Escopo

- [ ] criar `CorrelationMdcFilter extends OncePerRequestFilter`:
      lê `X-Correlation-Id` (gera UUID se ausente), popula MDC `correlationId`, adiciona ao response header
- [ ] criar `TenantMdcFilter extends OncePerRequestFilter`:
      extrai `tenant` e `sub` do JWT (via `SecurityContextHolder`) após autenticação; popula MDC `tenantId`, `userId`
- [ ] configurar Logback pattern: `%d{ISO8601} [%X{correlationId}] [%X{tenantId}] [%X{userId}] %-5level %logger{36} - %msg%n`
- [ ] adicionar log `INFO` em início/fim de: `TenantProvisioningService.provision`, `LinkService.createLink`, `LinkService.revokeLink`
- [ ] adicionar log `WARN` em: MIG timeout, PAC timeout, circuit breaker OPEN, HIST unavailable

## Critérios de aceite

- [ ] Toda linha de log inclui `correlationId` não-nulo
- [ ] Nenhuma linha de log contém `credential_hash`, `senha`, `private_key_enc`, ou dado facial
- [ ] Mesmo `correlationId` do request aparece em todas as linhas do mesmo ciclo de vida

## Dependências

- ACS-001 (subprojeto)
- ACS-019 (Spring Security — tenant/userId só disponível pós-autenticação)
