# PEA-006 -- EventPublisher: POST ao EVNT + outbox SQLite + retry com back-off

**Status:** PENDENTE | **Prioridade:** P2 | **Estimativa:** M

## Spec de referência

- `contracts/events-published.md` (payload GestoDetectado, delivery guarantees)
- `contracts/data-model.md §1` (tabela `event_outbox`)

## Escopo

- [ ] implementar `EventPublisher` em `publisher.py`
  - `enqueue(evento: GestoDetectado)`: insere na tabela `event_outbox` (SQLite via `aiosqlite`)
  - background task: drena outbox continuamente (loop asyncio)
  - `POST /api/v1/evnt/events` com `Authorization: Bearer {token}` e `X-Idempotency-Key: {eventId}`
  - tratamento de respostas (per `contracts/events-published.md`)
- [ ] back-off schedule: `[1, 5, 30, 120, 600]` segundos (capped at 600s)
- [ ] outbox max 50 rows: ao inserir quando cheio → deletar oldest, log ALERT
- [ ] `401` → chamar `AuthClient.refresh_token()`, retry uma vez; se falhar → WARN, manter no outbox
- [ ] `422 unknown-command` → deletar do outbox + chamar `VocabularyCache.invalidate()`
- [ ] `X-Correlation-Id` gerado na sessão e propagado em todas as requisições

## Critérios de aceite

- [ ] event entregue com `202` → removido do outbox
- [ ] event com `409` → removido do outbox (idempotente)
- [ ] EVNT unreachable → event fica no outbox; retry após back-off
- [ ] outbox > 50 → ALERT logado e oldest deletado
- [ ] `422` → event deletado do outbox + vocabulary invalidada
