# E2E-025 — Enums de domínio do EVNT divergem do que é persistido

**Módulo:** EVNT

**Status:** DONE
**Criado em:** 2026-08-23
**Fechado em:** 2026-08-23

## Contexto

`DispatchStatus`, `Feedback` e `Tier` existem em `domain/model` com valores em minúsculas e **não
são referenciados por nada**. O código grava strings literais: `QUEUED`, `NAO_AVALIADO`, `REAL`.

A armadilha: "usar os enums que já existem" parece uma limpeza trivial e **mudaria silenciosamente
todo valor gravado**, invalidando as linhas já persistidas e qualquer consulta que as leia. É o
tipo de refactor que passa no gate e quebra dado histórico.

---

## Inventário dos valores reais (Docker DB — 2026-08-23)

| Coluna | Valores distintos no DB | Formato |
|---|---|---|
| `evento.feedback` | `NAO_AVALIADO`, `REAL` | UPPERCASE |
| `notification_dispatch.status` | `DELIVERED` | UPPERCASE |
| `notification_dispatch.tier` | `discreet`, `full_screen_alarm` | lowercase |

Migrations `V0500__evnt_initial_schema.sql`:
- `evento.feedback DEFAULT 'NAO_AVALIADO'` — varchar(50), sem CHECK constraint
- `notification_dispatch.status DEFAULT 'QUEUED'` — varchar(50), sem CHECK constraint
- `notification_dispatch.tier` — varchar(50), sem CHECK constraint, sem default

---

## Decisão

**`DispatchStatus` enum** — **removido**. Era dead code; `DispatchStatuses` (constants class,
uppercase) já implementava o contrato corretamente e estava em uso por toda a aplicação.

**`Feedback` enum** — **alinhado para UPPERCASE** (`NAO_AVALIADO`, `REAL`, `FALSO_POSITIVO`).
Os valores persisted são uppercase; o enum tinha lowercase — a divergência estava no enum, não no
banco. Renomear os constants não muda nenhum dado: o enum não era referenciado antes desta issue.
Agora `Feedback.NAO_AVALIADO.name()` produz `"NAO_AVALIADO"` — idêntico ao que Flyway persiste.

**`Tier` enum** — **mantido intacto e passado a ser usado**. Os valores no banco são lowercase
(`discreet`, `full_screen_alarm`) e o enum já tinha exatamente esses valores lowercase. Nenhuma
migration necessária: `Tier.full_screen_alarm.name()` produz `"full_screen_alarm"` — idêntico ao
persistido.

**Nenhuma migration de dados necessária.**
