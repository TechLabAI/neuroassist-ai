# E2E-025 — Enums de domínio do EVNT divergem do que é persistido

**Módulo:** EVNT
**Fase:** Higiene de código
**Prioridade:** P3
**Status:** OPEN
**Criado em:** 2026-08-23
**Plano:** [plan-e2e-integration.md](../plans/plan-e2e-integration.md) §11.2

---

## Contexto

`DispatchStatus`, `Feedback` e `Tier` existem em `domain/model` com valores em minúsculas e **não
são referenciados por nada**. O código grava strings literais: `QUEUED`, `NAO_AVALIADO`, `REAL`.

A armadilha: "usar os enums que já existem" parece uma limpeza trivial e **mudaria silenciosamente
todo valor gravado**, invalidando as linhas já persistidas e qualquer consulta que as leia. É o
tipo de refactor que passa no gate e quebra dado histórico.

## Escopo

- Alinhar os enums aos valores realmente gravados (maiúsculas), e só então passar a usá-los
- Ou removê-los, se a decisão for manter string literal
- Se houver linha já gravada com valor divergente, migration de dados junto

## Checklist

- [ ] Inventário dos valores realmente presentes em `notification_dispatch` e afins
- [ ] Enums alinhados aos valores gravados
- [ ] Substituição das strings literais pelos enums
- [ ] Migration de dados, se necessária
- [ ] Teste que compara valor persistido × constante do enum
