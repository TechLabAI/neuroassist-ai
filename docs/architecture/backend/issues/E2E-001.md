## Objetivo

Garantir que o `docker-compose.dev.yml` sobe todos os 9 componentes do stack (7 microserviços + GWY + REG) e que todos registram como `UP` no Eureka antes de qualquer validação cross-service.

## Cenários de Validação

| ID | Cenário | Critério |
|---|---|---|
| INF-01 | REG lista todos os 7 serviços como UP | `GET :8761/eureka/apps` → 7 instâncias `status=UP` |
| INF-02 | GWY roteia para cada serviço | `GET :8080/api/v1/<svc>/actuator/health` → `{"status":"UP"}` em todos |
| INF-03 | JWK Set público acessível | `GET :8080/oauth2/jwks` → JSON com `keys[]` não vazio |

## Ordem de Startup Obrigatória

1. PostgreSQL (docker-compose)
2. `neuroassist-ai-migrations` (DDL + seed)
3. `neuroassist-ai-service-registry` (REG)
4. `acs-service` (JWK Set deve estar disponível antes dos demais)
5. Demais serviços em paralelo: `gest`, `evnt`, `pac`, `edge`, `hist`, `dash`
6. `neuroassist-ai-api-gateway` (último)

## Notas de Implementação

### Banco de dados
Um único PostgreSQL `neuroassist_dev` compartilhado por todos os serviços (usuário `neuroassist`).
As migrations rodam em 2 estágios:
- `migrations-global`: `classpath:db/migration,classpath:db/migration/global` → schema `neuroassist_global`
- `migrations-empresa`: `classpath:db/migration/empresa` → schema `t_emp_dev`

### JWT / Auth Backbone
Todos os resource servers validam tokens via `KEYCLOAK_ISSUER_URI=http://acs-service:8088`.
ACS é o OAuth2 Authorization Server. Sem Keycloak no stack E2E.

### ActiveMQ Artemis
Todos os serviços usam `SPRING_ARTEMIS_MODE=native` apontando para o container Artemis.

### PRÉ-REQUISITO de execução
```bash
cd backend && ./gradlew bootJar -x test
docker compose -f docker/docker-compose.dev.yml up -d
```
