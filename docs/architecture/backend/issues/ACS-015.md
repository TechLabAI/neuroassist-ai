## Contexto

`CuidadorController` expõe a superfície admin de cuidadores (`/api/v1/acs/caregivers`).
Atenção especial: `GET /caregivers` filtra resultados por papel do caller (cuidadora vê só
a si mesma; coordenador vê todos — SPEC-01 §5).

## Spec de referência

- SPEC-01 §6 (endpoint × status matrix)
- `contracts/api-contract.md §4`

## Escopo

- [ ] criar `CuidadorController` com endpoints:
      `POST /api/v1/acs/caregivers` → `CuidadorService.createCuidador()` → `201`
      `GET /api/v1/acs/caregivers` → `CuidadorService.listCuidadores()` → `200`
      `GET /api/v1/acs/caregivers/{id}` → `CuidadorService.getCuidador()` → `200`
      `POST /api/v1/acs/caregivers/{id}/deactivation` → `CuidadorService.deactivateCuidador()` → `200`
- [ ] `@PreAuthorize` correto por método: `criar` exige `acs.cuidador.criar`, `desativar` exige `acs.cuidador.desativar`, etc.
- [ ] filtro de listing: injetar `papel` do JWT principal; se `cuidadora`, restringir a `id == caller.sub`

## Critérios de aceite

- [ ] Cuidadora chamando GET /caregivers retorna apenas sua própria conta
- [ ] Coordenador chamando GET /caregivers retorna todos do tenant
- [ ] Response nunca contém `credential_hash`
