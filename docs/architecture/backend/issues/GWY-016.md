## Contexto
Cada rota tem um bucket de rate-limit (ex.: `edge-ingest`, `login`, `default`); buckets sao token-bucket thread-safe, in-memory por replica no MVP (R-3, limite aceito como N x replicas).

**Spec de referencia:** SPEC-01 §5, SPEC-05, SPEC-10

## Escopo
- [ ] implementar `backend/services/neuroassist-ai-api-gateway/src/main/java/com/neuroassist/gateway/filter/RateLimiterFilter.java`
- [ ] configurar os buckets `edge-ingest`, `login`, `default` por `Route id` da tabela §3

## Resultado esperado
`RateLimiterFilter` aplica o bucket configurado por rota, respondendo `429` com `Retry-After` quando esgotado, e mapeando erro upstream para `502`/timeout para `504`.

## Criterios de aceite
- [ ] bucket esgotado responde `429` com header `Retry-After` e corpo `/errors/rate-limited`
- [ ] timeout de chamada upstream responde `504` sem retry automatico de metodo nao-idempotente
- [ ] erro `5xx` nao tratado do upstream e mapeado para `502 /errors/upstream-error` sem vazar o corpo original
