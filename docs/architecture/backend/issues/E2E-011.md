## Objetivo

Validar o fluxo crítico de negócio: um gesto reconhecido pelo dispositivo edge gera um evento de alarme, que é notificado ao cuidador via DASH, confirmado pela cuidadora, e todo o ciclo fica auditado no HIST com 2 fatos rastreáveis.

## Fluxo Completo

```
1. POST /api/v1/gest/reports (ou /api/v1/evnt/reports)
      → GEST recebe resultado de detecção do edge agent
      
2. POST /api/v1/evnt/reports
      → EVNT recebe report; valida contra catálogo PAC; cria Evento (urgência=emergência)
      → EVNT → ACS directory: resolve cuidadores responsáveis pelo paciente
      → EVNT → HIST: fact EventoCriado
      
3. EVNT → DASH: POST /internal/notifications
      { dispatchId, tier=full_screen_alarm, targetCaregiverId, commandLabel }
      → DASH → cuidador: SSE frame (ou long-poll)
      → DASH → EVNT: callback delivered(dispatchId)
      
4. Cuidador confirma:
      POST /api/v1/dash/panel/notifications/{id}/acknowledge
      → DASH → EVNT: callback acknowledged(dispatchId)
      → EVNT: EventoConfirmado persistido (feedback=real)
      → EVNT → HIST: fact EventoConfirmado
      
5. GET /api/v1/hist/history?patientId={id}
      → HIST retorna 2 fatos: EventoCriado + EventoConfirmado
      → correlationId igual nos 2 fatos
```

## Critério de Sucesso (Gate)

- Todos os passos retornam 2xx
- HIST contém **exatamente 2 fatos** relacionados ao evento (EventoCriado + EventoConfirmado)
- `correlationId` propagado de ponta a ponta (mesmo valor nos 2 fatos)
- Evento com `feedback = real` após confirmação
- SSE frame recebido pelo cuidador antes do ack
