# ACS-012 -- Implementar TenantProvisioningService (saga MIG fail-closed, retry)

**Status:** INTACT -- gerado 2026-07-29
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/4 itens

## Contexto

`TenantProvisioningService` orquestra a saga de provisionamento (ADR-004): persiste o `Tenant` em
`provisioning`, chama `MigProvisioningPort`, transiciona para `active` em sucesso ou mantém
`provisioning` em falha. O retry é idempotente: já `active` → no-op; `provisioning` → re-tenta MIG.

## Spec de referência

- SPEC-02 §5 (EARS: saga, retry, idempotency, TenantProvisionado fact)
- `contracts/event-contracts.md §2.1` (MigProvisioningPort timeout 5s, circuit breaker)

## Escopo

- [ ] criar `TenantProvisioningService` em `application/service/` com métodos:
      `provision(nome, tipo): TenantSnapshot` (cria em `provisioning`, chama MIG),
      `retryProvisioning(tenantId): TenantSnapshot` (idempotente: active → 200 no-op, provisioning → retry MIG)
- [ ] integrar `MigProvisioningPort` com Resilience4j: timeout 5s, circuit breaker `OPEN` → return `202 Accepted` sem chamar MIG
- [ ] ao sucesso do MIG: `TenantJpaAdapter.activate(tenantId, schemaName)` (atomico via `@Transactional`)
- [ ] ao sucesso: emitir `TenantProvisionado` via `HistAuditPort` (best-effort, não bloquear `201`)

## Critérios de aceite

- [ ] MIG OK → tenant `active`, `schema_name` preenchido, resposta `201`
- [ ] MIG timeout → tenant `provisioning`, `schema_name` null, resposta `202`
- [ ] retry de tenant `active` → `200 OK`, MIG não chamado
- [ ] retry de tenant `suspended` → `409 tenant-suspended`
- [ ] `TenantProvisionado` registrado no HIST em caso de sucesso
