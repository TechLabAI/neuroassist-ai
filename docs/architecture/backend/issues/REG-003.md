# REG-003 -- Implementar endpoint de readiness customizado: registry aceitando registros

**Status:** INTACT -- gerado 2026-07-27
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/7 itens

## Contexto
SPEC-07 exige que readiness reflita o registry estar aceitando registros -- nao apenas o servidor no ar. O `/actuator/health` padrao do Spring Boot nao distingue "processo vivo" de "registry pronto para receber registros". Um `HealthIndicator` custom resolve essa semantica, garantindo que orquestradores e compose so marquem a instancia como pronta quando ela efetivamente aceita registros.

- SPEC-01, SPEC-07

- [ ] Indicador `HealthIndicator` verifica que o Eureka server esta em estado aceitando registros (via `PeerAwareInstanceRegistry` ou flag de startup)
- [ ] Registrar como bean Spring exposto no grupo `readiness` do Actuator (`management.endpoint.health.group.readiness.include`)
- [ ] Cobrir com testes unitarios: UP quando aceitando, DOWN enquanto inicializando

## Criterios de aceite
- [ ] `GET /actuator/health/readiness` retorna `{"status":"DOWN"}` ate o registry estar pronto para registros
- [ ] `GET /actuator/health/readiness` retorna `{"status":"UP"}` apos o registry aceitar registros
- [ ] Testes unitarios do `RegistryReadinessHealthIndicator` passam com coverage >= 80%
