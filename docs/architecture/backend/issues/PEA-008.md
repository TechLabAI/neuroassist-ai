**Status:** PENDENTE | **Prioridade:** P3 | **Estimativa:** S

## Spec de referência

## Escopo

### Structured logging (`structlog`)

- [ ] configurar `structlog` com output JSON (produção) e pretty-print (dev)
- [ ] campos obrigatórios em todos os logs: `device_id`, `patient_id`, `tenant_id`, `correlation_id`, `timestamp`
- [ ] nível de log configurável via `logging.level` em `config.toml` (default `INFO`)
- [ ] **LGPD**: `structlog.processors.KeyValueRenderer` com lista de campos proibidos (`landmark_coords`, `frame_data`) — estes nunca entram no log

### Métricas internas (expostas via heartbeat)

- [ ] FPS real (média móvel 10s): contador de frames / tempo
- [ ] `outbox_depth`: count de rows em `event_outbox`
- [ ] `events_delivered_total` (counter, não persistido — session)
- [ ] `events_failed_total` (counter, não persistido)

### Signal handling (`main.py`)

- [ ] `SIGTERM` / `SIGINT` → graceful shutdown: parar capture loop → drenar outbox (timeout 5s) → fechar SQLite → exit 0
- [ ] `SIGHUP` → reload config + force vocabulary re-fetch (sem restart)

## Critérios de aceite

- [ ] JSON logs emitidos em produção (unit test: parse JSON do stdout)
- [ ] campo `landmark_coords` nunca aparece em nenhum log
- [ ] `SIGTERM` → outbox drenado antes de exit (unit test com mock)
- [ ] `SIGHUP` → vocabulary refreshed sem restart (integration test)
