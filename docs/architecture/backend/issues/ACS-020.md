# ACS-020 -- Implementar GlobalExceptionHandler com ProblemDetail (RFC 7807)

**Status:** INTACT -- gerado 2026-07-29
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/4 itens

## Contexto

`GlobalExceptionHandler` centraliza o mapeamento de exceções de domínio e de infraestrutura
para `application/problem+json` (RFC 7807). Todo erro deve incluir `correlationId`
(do MDC, via `X-Correlation-Id`). Nenhum corpo de erro pode conter credenciais ou dados clínicos.

## Spec de referência

- SPEC-01 §5 (EARS: `correlationId` em todo ProblemDetail; content type `application/problem+json`)
- `contracts/api-contract.md §8` (tabela completa de tipos de erro)

## Escopo

- [ ] criar `GlobalExceptionHandler extends ResponseEntityExceptionHandler` com `@RestControllerAdvice`
- [ ] mapear todas as exceções do catálogo (`api-contract.md §8`):
      `ValidationException` → `400`, `InvalidCredentialsException` → `401`, `UnauthenticatedException` → `401`,
      `TenantMismatchException` → `403`, `InsufficientAuthorityException` → `403`,
      `TenantNotFoundException` → `404`, `CaregiverNotFoundException` → `404`, `UnknownPatientException` → `404/422`,
      `LoginDuplicateException` → `409`, `TenantNotActiveException` → `409`, `TenantSuspendedException` → `409`,
      `LastCaregiverLinkException` → `409`, `CrossTenantLinkException` → `422`, `UpstreamUnavailableException` → `502/504`
- [ ] injetar `correlationId` do MDC em cada `ProblemDetail` (campo `correlationId`)
- [ ] garantir que nenhum handler inclui senha, hash, chave privada, dado biométrico ou clínico no body

## Critérios de aceite

- [ ] Todo response de erro tem `Content-Type: application/problem+json`
- [ ] Todo response de erro inclui `correlationId` não-nulo
- [ ] `401 invalid-credentials` não discrimina causa (enumeração prevenida)
- [ ] `DataIntegrityViolationException` com constraint `ux_cuidador_login_active` → `409 login-duplicate`
