## Objetivo

Validar o fluxo completo de onboarding de um novo tenant: provisioning de schema, criação de cuidador, autenticação, criação de paciente (com validação de dispositivo no EDGE), publicação de comando (com eligibility check no GEST) e verificação do audit trail no HIST.

## Fluxo Completo

```
1. POST /api/v1/acs/tenants
      → ACS provisiona tenant + chama MIG (schema criado)
      
2. POST /api/v1/acs/caregivers
      → ACS cria cuidadora Jamilly no novo tenant
      
3. POST /oauth2/token (login Jamilly)
      → ACS emite JWT RS256 com papel=cuidadora
      
4. POST /api/v1/pac/patients (com dispositivo_edge_id)
      → PAC → EDGE: valida device (GET /edge/patients/{id}/device)
      → PAC cria paciente
      
5. POST /api/v1/pac/commands
      → PAC cria rascunho de comando "Chamar cuidadora" (urgência=emergência)
      
6. POST /api/v1/pac/commands/{id}:publish
      → PAC → GEST: eligibility check (GestDetectabilityPort)
      → PAC → HIST: fact ComandoPublicado
      → comando fica ativo
      
7. GET /api/v1/hist/history?patientId={id}
      → HIST → ACS: resolve patient-scope de Jamilly
      → retorna ComandoPublicado na timeline
```

## Critério de Sucesso (Gate)

- Todos os 7 passos retornam 2xx
- HIST contém `ComandoPublicado` com `calibracaoVersao` e `correlationId` corretos
- GEST aceita o comando como elegível (primitiva suportada)
- Patient-scope: Jamilly vê apenas os fatos do seu paciente
