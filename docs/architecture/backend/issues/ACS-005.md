# ACS-005 -- Implementar TokenIssuer (JWT RS256, claims assembly, role → authorities)

**Status:** DONE -- validado 2026-08-19 (Modo 4 FULL-VALIDACAO)
**Maturidade:** 100 -- Maduro
**Done/Total:** 0/5 itens

## Contexto

O `TokenIssuer` é o coração do OAuth2 Authorization Server de ACS. Assina JWTs com RS256 usando
a chave ativa (`signing_key.status = 'active'`), monta os claims obrigatórios (`sub`, `tenant`,
`papel`, `authorities`, `iss`, `iat`, `exp`, `kid`) e aplica o mapeamento total `papel →
authorities` (ADR-005, SPEC-03 §5). O TTL padrão é 900s. A chave privada é lida via
`SigningKeyPort.getActiveSigningKey()` — nunca hardcodada.

## Spec de referência

- SPEC-03 §4 (JWT structure), §5 (role → authorities total map), §6 (EARS invariants — login)
- ADR-005 (authentication + RBAC authority model)
- `contracts/api-contract.md §7` (authorities namespace `acs.<recurso>.<acao>`)

## Escopo

- [ ] criar `TokenIssuer` em `application/service/`:
      método `issue(cuidador: Cuidador): TokenResponse` que:
      (a) carrega a signing key ativa via `SigningKeyPort.getActiveSigningKey()`,
      (b) monta claims: `sub=cuidadorId`, `tenant=tenantId`, `papel`, `authorities=roleToAuthorities(papel)`,
      `exp=now+900s`, `iss=acs-service`, `kid=signingKey.kid`,
      (c) assina com `Nimbus JOSE+JWT` ou Spring Authorization Server `JwtEncoder`,
      (d) retorna `TokenResponse`
- [ ] criar `RoleAuthorityPolicy` em `application/`:
      método `toAuthorities(papel: CuidadorPapel): List<String>` com mapeamento total
      (coordenador_clinica → 12 authorities; cuidadora → 5 authorities — SPEC-03 §5);
      lançar `IllegalStateException` se `papel` for desconhecido (pré-empted pela constraint DB)
- [ ] garantir que `exp ≤ now + 900s` (TTL máximo configurável via `application.yml`)
- [ ] garantir que a chave privada não vaza em logs, responses ou exceções
- [ ] cobrir `RoleAuthorityPolicy` com testes unitários (100% dos papéis declarados)

## Resultado esperado

`TokenIssuer` produzindo JWTs RS256 válidos com todos os claims obrigatórios e o mapeamento total
`papel → authorities` testado unitariamente.

## Critérios de aceite

- [ ] JWT produzido tem `kid` correspondente à chave ativa no `SigningKeyPort`
- [ ] `authorities` de `cuidadora` contém exatamente `[acs.cuidador.read, acs.directory.read, evnt.read, evnt.confirm, dash.read]`
- [ ] `authorities` de `coordenador_clinica` contém exatamente as 12 authorities declaradas em SPEC-03 §5
- [ ] `RoleAuthorityPolicy` com papel não mapeado lança `IllegalStateException` (não silencia)
- [ ] Token produzido não exibe `private_key_enc` em nenhuma exceção capturada
