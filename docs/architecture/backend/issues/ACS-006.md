## Contexto

`POST /oauth2/token` é o endpoint público que valida credencial do `Cuidador` e emite o JWT.
É o único endpoint de ACS que não requer Bearer token. O `AutenticacaoService` valida credencial
via `DelegatingPasswordEncoder` (bcrypt/argon2), verifica `cuidador.status = active` e
`tenant.status = active`, e chama `TokenIssuer`. Em caso de falha, a resposta `401` não
distingue qual condição falhou (no user enumeration — SPEC-03 §6). Após sucesso ou falha,
registra fact em HIST via `HistAuditPort` (best-effort, não bloqueante).

## Escopo

- [ ] criar `AutenticacaoController` em `api/controller/`:
      `POST /oauth2/token` — público (sem `@PreAuthorize`); aceita `LoginRequest`, retorna
      `ResponseEntity<TokenResponse>` 200 ou `ProblemDetailResponse` 401
- [ ] criar `AutenticacaoService` em `application/service/`:
      método `authenticate(request: LoginRequest): TokenResponse` que:
      (a) carrega `Cuidador` por `login` (case-insensitive) no schema do tenant,
      (b) valida senha via `DelegatingPasswordEncoder.matches(raw, hash)`,
      (c) verifica `cuidador.status = active` e `tenant.status = active`,
      (d) em qualquer falha: emite `AutenticacaoFalhou` fact (best-effort) e lança
      `AuthenticationFailedException` → 401 `invalid-credentials` (sem enumerar causa),
      (e) em sucesso: chama `TokenIssuer.issue(cuidador)`, emite `AutenticacaoRealizada` (best-effort)
- [ ] garantir que `AutenticacaoService` **não** bloqueia na chamada ao `HistAuditPort`
      (chamar em thread separado ou via `@Async`)
- [ ] garantir que nenhuma linha de log registra a senha em claro (raw password)
- [ ] criar `AuthenticationFailedException` mapeada para `401` no `GlobalExceptionHandler`

## Resultado esperado

`POST /oauth2/token` funcionando end-to-end: credencial válida → JWT 200; credencial inválida →
401 sem enumeração de causa.

## Critérios de aceite

- [ ] Credencial válida (`cuidador.status=active`, `tenant.status=active`, senha correta) → `200` com JWT
- [ ] `login` desconhecido → `401 invalid-credentials` (não `404`)
- [ ] Senha incorreta → `401 invalid-credentials` (mesma resposta que login desconhecido)
- [ ] `cuidador.status = inactive` → `401 invalid-credentials`
- [ ] `tenant.status ≠ active` → `401 invalid-credentials`
- [ ] Logs não contêm a senha em plaintext sob nenhuma condição
