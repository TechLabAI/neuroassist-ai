# E2E-023 — Catálogo de permissão do EDGE divergente, e o ArchUnit aceita os dois lados

**Plano:** [plan-e2e-integration.md](../plans/plan-e2e-integration.md) §11.2

## Contexto

`permission-catalogue.arch.json` declara códigos granulares para o EDGE
(`edge.device-registration.criar`, `edge.pairing.criar`, `edge.liveness.read`, …) que **não
existem no código**. O código usa códigos coarse: `edge.manage`, `edge.read`, `edge.device`,
`edge.internal`.

O `CrossAspectArchTest` do EDGE deveria guardar essa sincronia. Ele não guarda: o catálogo está
**pinado inline no próprio teste, contendo as duas famílias**. O teste que existe para detectar a
divergência aceita os dois lados dela.

Segundo caso do padrão registrado em CLAUDE.md — quando um guarda está verde, verificar o que ele
de fato compara.

## Escopo

- Decidir qual família é a verdadeira. Coarse é o que roda; granular é o que a spec pede. Granular
  é mais defensável (`edge.manage` autoriza registrar dispositivo e revogar pareamento com a mesma
  chave), mas é mudança de contrato: mexe no `RoleAuthorityPolicy` do ACS e em todo `@PreAuthorize`
  do EDGE.
- O teste passa a **ler** o catálogo do arquivo, nunca de uma cópia inline.

## Checklist

- [ ] Decisão registrada: coarse × granular
- [ ] `permission-catalogue.arch.json` alinhado ao código (ou vice-versa)
- [ ] `CrossAspectArchTest` lê o arquivo, sem catálogo inline
- [ ] Controle negativo: introduzir uma authority fora do catálogo deixa o teste vermelho
- [ ] Auditar os outros 6 serviços pelo mesmo padrão de teste pinado

## Critério de aceite

Renomear uma authority no código sem atualizar o catálogo quebra o `architectureCheck` do EDGE.
