# ACS-009 -- Implementar TenantJpaAdapter + SigningKeyJpaAdapter (schema global neuroassist_global)

## Contexto

`TenantJpaAdapter` e `SigningKeyJpaAdapter` são adapters do schema **global** (`neuroassist_global`).
Ao contrário dos adapters empresa, eles não precisam de routing multi-tenant — sempre acessam o
schema global. `TenantJpaAdapter` é usado pelo `ProvisionTenantUseCase` e pelo `DirectoryService`;
`SigningKeyJpaAdapter` implementa `SigningKeyPort` e fornece as chaves de assinatura e o JWK set.

A transição de status `provisioning → active` exige atomicidade: o adapter deve atualizar
`status`, `schema_name` e `atualizado_em` em uma única operação transacional.

## Escopo

- [ ] criar `TenantRepository` (Spring Data JPA) em `infrastructure/persistence/repository/`:
      métodos: `findById`, `save`, `findByStatus`; query custom para
      `findByIdAndStatus(id, status)` (usado no retry check)
- [ ] criar `TenantJpaAdapter` em `infrastructure/persistence/`:
      implementa `TenantRepositoryPort` (ou equivalente);
      métodos: `save(Tenant)`, `findById(UUID): Optional<Tenant>`,
      `transitionToActive(tenantId, schemaName): void` (atualiza status + schema_name atomicamente)
- [ ] criar `SigningKeyRepository` em `infrastructure/persistence/repository/`:
      métodos: `findByStatus(status)`, `findByKid(kid)`;
      query: `findActiveAndRecentlyRetired(since: Instant)` (para JWK set)
- [ ] criar `SigningKeyJpaAdapter` em `infrastructure/persistence/`:
      implementa `SigningKeyPort`;
      `getActiveSigningKey()` → carrega `signing_key WHERE status='active'`;
      `getPublicKeys()` → carrega active + retired com `retired_at > now() - 900s`
- [ ] criar bootstrap de chave de assinatura: se nenhuma chave `active` existir, gerar RSA 2048,
      encriptar `private_key_enc`, persistir via `SigningKeyRepository` (só em dev/test — prod usa secret manager)

## Resultado esperado

Dois adapters JPA globais funcionando com banco real (Testcontainers), sem routing de schema.

## Critérios de aceite

- [ ] `TenantJpaAdapter.transitionToActive` falha com `DataIntegrityViolationException` se `schema_name=null` (constraint DB)
- [ ] `SigningKeyJpaAdapter.getActiveSigningKey()` lança exceção se nenhuma chave ativa existe (não retorna null)
- [ ] `getPublicKeys()` retorna somente campos públicos (sem `private_key_enc` exposto)
- [ ] `findActiveAndRecentlyRetired` usa query JPQL parametrizada com `retired_at > :since`
