# ACS-014 -- Implementar CuidadorService (criar, desativar, verificação de cobertura)

**Maturidade:** 100 -- Maduro

## Contexto

`CuidadorService` orquestra o ciclo de vida do `Cuidador`: hash de senha, criação, desativação com
coverage check, e listagem. A verificação de cobertura no deactivate é safety-critical: bloqueia
a desativação do último cuidador alarm-eligible de um paciente (SPEC-05 §5).

## Spec de referência

- SPEC-01 §5 (autoridades por endpoint)
- SPEC-05 §5 (coverage invariant no deactivate)
- SPEC-06 §4 (LGPD: credential_hash nunca exposto)

## Escopo

- [ ] criar `CuidadorService` em `application/service/` com métodos:
      `createCuidador(req, tenantId): CuidadorSnapshot` (hash senha via `DelegatingPasswordEncoder`, persiste, emite `CuidadorRegistrado` ao HIST)
      `deactivateCuidador(id, tenantId): CuidadorSnapshot` (coverage check → deactivate soft → emite `CuidadorDesativado`)
      `listCuidadores(tenantId, papel?, status?, pageable): Page<CuidadorSnapshot>`
      `getCuidador(id, tenantId): CuidadorSnapshot`
- [ ] implementar coverage check no deactivate: para cada `active` link do cuidador, verificar se `countCoverageForPaciente > 1`; se qualquer paciente ficaria descoberto → `LastCaregiverLinkException`
- [ ] garantir que `credential_hash` nunca aparece em `CuidadorSnapshot` (filtro no mapper)
- [ ] emitir `CuidadorRegistrado` / `CuidadorDesativado` via `HistAuditPort` (best-effort)
- [ ] marcar `deactivateCuidador` com `@Transactional` + coverage check no mesmo tx

## Critérios de aceite

- [ ] Senha armazenada como hash (bcrypt); raw password zerada em memória após hashing
- [ ] Deactivate último link sem coordinator → `409 last-caregiver-link`
- [ ] Deactivate sem active links → `200 OK` (sem cobertura para checar)
- [ ] Snapshot nunca contém `credential_hash` ou `senha`
- [ ] `CuidadorDesativado` registrado no HIST
