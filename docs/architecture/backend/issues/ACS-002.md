# ACS-002 -- Criar DTOs das três superfícies de API (auth, admin, diretório)

**Status:** INTACT -- gerado 2026-07-29
**Maturidade:** 0 -- Inicial
**Done/Total:** 0/5 itens

## Contexto

ACS expõe três superfícies: **auth** (`/oauth2`), **admin** (`/api/v1/acs`) e **diretório**
(`/api/v1/acs/directory`). Cada uma tem request/response DTOs distintos que são o contrato com
FE, GWY e serviços pares. Os DTOs derivam exclusivamente de `contracts/api-contract.md`.
Nenhum DTO pode expor campos de credencial (`password`, `credential_hash`) ou material
biométrico/clínico (LGPD hard rule).

## Spec de referência

- SPEC-01 §2–§6 (resource hierarchy, status matrix, error model)
- `contracts/api-contract.md` §2 (auth), §3 (tenants), §4 (caregivers), §5 (links), §6 (directory)

## Escopo

- [ ] criar DTOs de **auth surface**:
      `LoginRequest` (grantType, login, password), `TokenResponse` (accessToken, tokenType,
      expiresIn, tenant, sub, papel, authorities)
- [ ] criar DTOs de **tenant admin**:
      `CreateTenantRequest` (nome, tipo), `TenantResponse` (id, nome, tipo, status, schemaName,
      criadoEm), `ProvisioningStatusResponse`
- [ ] criar DTOs de **caregiver admin**:
      `CreateCaregiverRequest` (nome, login, papel, senha — senha somente no request),
      `CaregiverResponse` (id, tenant, nome, login, papel, status, criadoEm — sem campo de credencial),
      `PagedCaregiversResponse` (items, page, size, total)
- [ ] criar DTOs de **link admin**:
      `CreateLinkRequest` (pacienteId), `CaregiverPatientLinkResponse` (id, tenant, cuidadorId,
      pacienteId, status, criadoEm)
- [ ] criar DTOs de **diretório**:
      `TenantValidityResponse` (tenantId, status, valid, tipo),
      `RoutingTargetsResponse` (pacienteId, tenant, responsibleCaregivers[]),
      `CaregiverRoleResponse` (cuidadorId, tenant, papel, status, authorities[]),
      `PatientScopeResponse` (cuidadorId, papel, scope, pacienteIds[])
- [ ] criar `ProblemDetailResponse` (type, title, status, detail, instance, correlationId, errors[])
      — RFC 7807 (`contracts/api-contract.md §8`)
- [ ] garantir que nenhum DTO contém campo `password`, `credential_hash`, biométrico ou clínico

## Resultado esperado

Todos os DTOs das três superfícies declarados em `api/dto/`, com Bean Validation nas requests,
sem nenhum vazamento de credencial ou dado sensível.

## Critérios de aceite

- [ ] `LoginRequest` com campo `senha` anotado `@NotBlank` mas **sem** campo correspondente no response
- [ ] `CaregiverResponse` não possui campo `credentialHash`, `senha` ou `password` (falha em code review se presente)
- [ ] `PagedCaregiversResponse` respeita shape `{items, page, size, total}` (SPEC-01 §1 pagination)
- [ ] `PatientScopeResponse` tem campo `scope` com valores `assigned | tenant` (ADR-006)
- [ ] `ProblemDetailResponse` tem campo `correlationId` (SPEC-01 §5)
