## Resultado esperado
`DeviceCredentialFilter` roda apos a autenticacao de cuidador; se nao houver JWT valido mas houver credencial de dispositivo, valida via `DeviceCredentialValidator` (impl default `SignedTokenDeviceValidator`, JWK-based) e produz `GatewayPrincipal(kind=device, ...)`.

## Criterios de aceite
- [ ] token de dispositivo valido autentica como `device` e resolve `empresa_id` da claim
- [ ] token de dispositivo ausente, expirado ou com assinatura invalida resulta em `401`, nada encaminhado
- [ ] token valido mas sem claim `empresa_id` resulta em `401` (fail closed)
- [ ] requisicao com JWT de cuidador E token de dispositivo trata como cuidador (primeiro filtro que resolve principal vence)
