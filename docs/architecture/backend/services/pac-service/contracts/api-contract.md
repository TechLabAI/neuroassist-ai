# PAC — API Contract (`pac-service`)

> Module: **PAC — Pacientes e Catálogo de Comandos** · Service: `pac-service` · Package: `com.neuroassist.pac`
> Project: NeuroAssist AI · Architecture: independent microservices (ADR-002 shared) · Messaging: disabled
> Generated by `/be-architect-specs neuroassist-ai PAC` · 2026-07-28
> ADR refs: ADR-004 (authoring source), ADR-005 (emergency-eligibility gate), ADR-006 (versioned-retire).
> EARS authoring guide: `docs/architecture/backend/standards/ears-notation.md`.

PAC is the **system of record for `Paciente` and `Comando`**. It exposes two REST surfaces over the same
service: an **authoring surface** (write/lifecycle, consumed by DASH via GWY) and a **read surface** (the
active, calibrated catalog + patient, consumed by GEST/EVNT/DASH). All cross-service traffic is
synchronous REST routed via GWY and discovered via REG (messaging disabled MVP).

---

## 1. Conventions

- **Base path:** `/api/pac/v1` (routed by GWY; internal callers resolve `pac-service` via REG/Eureka).
- **Media type:** `application/json; charset=utf-8`. Errors use `application/problem+json` (RFC 7807).
- **Resource ids:** UUID v4, server-assigned, returned in `Location` on `201`.
- **Timestamps:** RFC 3339 / ISO-8601 UTC (`2026-07-28T14:03:00Z`).
- **Idempotency:** unsafe non-idempotent creates (`POST`) accept an optional `Idempotency-Key` header
  (see SPEC-05). Lifecycle transitions are guarded by `If-Match` optimistic concurrency (ETag = row
  version), so a stale client cannot clobber a concurrent recalibration.

### 1.1 Mandatory headers

| Header | Direction | Rule |
|---|---|---|
| `X-Empresa-Id` | request | Tenant (empresa) scoping key. Selects the per-empresa schema. **Required on every call.** |
| `X-Correlation-Id` | request/response | Propagated end-to-end; PAC generates one if absent and echoes it. |
| `Authorization` | request | `Bearer <JWT>` (OAuth2 resource server). Tenant claim MUST match `X-Empresa-Id`. |
| `If-Match` | request | ETag of the resource for lifecycle/recalibration mutations (optimistic lock). |
| `ETag` | response | Row version of the returned/mutated resource. |
| `Idempotency-Key` | request | Optional on `POST` creates; dedups retried creates within the window. |

**EARS — headers & tenancy**

- THE SYSTEM SHALL require a non-empty `X-Empresa-Id` header on every request.
- IF `X-Empresa-Id` is absent or empty, THEN THE SYSTEM SHALL reject the request with `400`
  (`type=/errors/missing-tenant`).
- IF the JWT tenant claim does not match `X-Empresa-Id`, THEN THE SYSTEM SHALL reject the request with
  `403` (`type=/errors/tenant-mismatch`) and SHALL NOT leak whether the empresa exists.
- WHEN a request omits `X-Correlation-Id`, THE SYSTEM SHALL generate one and echo it on the response.

### 1.2 Auth (OAuth2 + scopes)

OAuth2 resource server (JWT bearer). Scopes:

| Scope | Grants |
|---|---|
| `pac:patient:read` | read `Paciente` |
| `pac:patient:write` | create/update `Paciente` |
| `pac:command:read` | read `Comando` / active catalog |
| `pac:command:write` | author/edit/calibrate `Comando` |
| `pac:command:publish` | run lifecycle transitions (validate/publish/recalibrate/retire) |
| `pac:catalog:read` | read the published catalog snapshot (service-to-service: GEST/EVNT) |

- WHILE the caller lacks the scope required by an endpoint, THE SYSTEM SHALL respond `403`
  (`type=/errors/insufficient-scope`).

## 2. Error model (RFC 7807 ProblemDetail)

All errors return `application/problem+json`:

```json
{
  "type": "/errors/emergency-not-detectable",
  "title": "Emergency command references a non-detectable gesture",
  "status": 422,
  "detail": "TipoGesto a1f2… is 'pending-training' in GEST; an emergency command cannot be published.",
  "instance": "/api/pac/v1/pacientes/{pid}/comandos/{cid}:publish",
  "correlationId": "3b9f…",
  "errors": [{ "field": "primitivoPrincipalId", "code": "not-supported" }]
}
```

| `type` | HTTP | When |
|---|---|---|
| `/errors/validation` | 400 | Bean-validation / malformed body |
| `/errors/missing-tenant` | 400 | `X-Empresa-Id` absent |
| `/errors/unauthorized` | 401 | Missing/invalid JWT |
| `/errors/insufficient-scope` | 403 | Scope missing |
| `/errors/tenant-mismatch` | 403 | JWT tenant ≠ `X-Empresa-Id` |
| `/errors/not-found` | 404 | Paciente/Comando not in this empresa |
| `/errors/conflict-precondition` | 409 | `If-Match` ETag stale (concurrent edit) |
| `/errors/invalid-lifecycle-transition` | 409 | Transition not allowed from current `estado` |
| `/errors/idempotency-mismatch` | 409 | Same `Idempotency-Key`, different body |
| `/errors/duplicate-active-mapping` | 422 | Duplicate active gesture→need for the patient |
| `/errors/emergency-not-detectable` | 422 | Emergency gate failed (primitive not `supported`) |
| `/errors/eligibility-gate-unavailable` | 503 | GEST unreachable while publishing an emergency (fail-closed) |

## 3. Paciente resource

PAC is system of record for `Paciente`. Tenant/caregiver/device are references resolved from ACS/EDGE.

### 3.1 `POST /api/pac/v1/pacientes` — register patient
Scope `pac:patient:write`.

Request:
```json
{
  "nome": "Márcio Amaral",
  "dispositivoEdgeId": "b2c3…",        // optional; reference to EDGE DispositivoEdge (by id)
  "cuidadorResponsavelIds": ["c4d5…"]  // references to ACS Cuidador (by id)
}
```
Response `201 Created`, `Location: /api/pac/v1/pacientes/{id}`, `ETag: "1"`, body = the `Paciente`.

**EARS**
- WHEN a valid registration is received, THE SYSTEM SHALL persist the `Paciente` scoped to `X-Empresa-Id`
  and return `201` with a `Location` header.
- WHERE `dispositivoEdgeId` is present, THE SYSTEM SHALL resolve it against EDGE (`EdgeDevicePort`); IF
  the device is unknown or bound to another empresa, THEN THE SYSTEM SHALL reject with `422`
  (`type=/errors/validation`, field `dispositivoEdgeId`).
- WHERE `cuidadorResponsavelIds` is non-empty, THE SYSTEM SHALL resolve each id against ACS
  (`AcsDirectoryPort`); IF any caregiver is unknown for the empresa, THEN THE SYSTEM SHALL reject with
  `422`.
- IF `nome` is blank, THEN THE SYSTEM SHALL reject with `400` (`type=/errors/validation`).

### 3.2 `GET /api/pac/v1/pacientes/{id}` — read patient
Scope `pac:patient:read`. Returns `200` + `Paciente`, or `404` if not in this empresa.

### 3.3 `GET /api/pac/v1/pacientes` — list patients (tenant-scoped)
Scope `pac:patient:read`. Paged (`page`, `size`, default `size=20`). Returns only this empresa's patients.
- THE SYSTEM SHALL never return a `Paciente` belonging to another empresa, regardless of query params.

### 3.4 `PUT /api/pac/v1/pacientes/{id}` — update patient
Scope `pac:patient:write`, `If-Match` required. Same reference-resolution EARS as 3.1.
- IF `If-Match` is missing or stale, THEN THE SYSTEM SHALL reject with `409`
  (`type=/errors/conflict-precondition`).

> No `DELETE` for `Paciente` in the MVP — LGPD suppression is handled at tenant/ACS level (ADR-006).

## 4. Comando resource (nested under Paciente)

Path root: `/api/pac/v1/pacientes/{pid}/comandos`. `Comando` lifecycle:
`drafted → validated → published → (recalibrated ↻) → retired` (ADR-006, history-preserving; no hard
delete). `retired` is terminal.

### 4.1 `POST …/comandos` — author (create draft)
Scope `pac:command:write`.

Request:
```json
{
  "rotulo": "quero água",
  "necessidade": "hidratacao",
  "primitivoPrincipalId": "e5f6…",      // GEST TipoGesto id (by reference)
  "primitivoSecundarioId": null,        // composite gesture (optional)
  "sensibilidade": "media",             // baixa | media | alta
  "tempoMinGestoMs": 300,
  "tempoMaxGestoMs": 1500,
  "urgencia": "rotina"                   // emergencia | rotina
}
```
Response `201`, `Location: …/comandos/{cid}`, `estado = "drafted"`, `calibracaoVersao = 0`, `ETag: "1"`.

**EARS — authoring invariants**
- WHEN a command draft is created, THE SYSTEM SHALL set `estado = drafted` and `calibracaoVersao = 0`.
- IF `rotulo` or `necessidade` is blank, THEN THE SYSTEM SHALL reject with `400`.
- IF `tempoMinGestoMs <= 0` or `tempoMinGestoMs > tempoMaxGestoMs`, THEN THE SYSTEM SHALL reject with
  `400` (`type=/errors/validation`).
- IF `primitivoSecundarioId == primitivoPrincipalId`, THEN THE SYSTEM SHALL reject with `400` (a composite
  gesture must reference two distinct primitives).
- IF an active (non-`retired`) command for the same `pacienteId` already maps the same gesture set to the
  same `necessidade`, THEN THE SYSTEM SHALL reject with `422` (`type=/errors/duplicate-active-mapping`).
- THE SYSTEM SHALL NOT run the emergency gate at draft creation — the gate runs at publish (§4.6).

### 4.2 `GET …/comandos/{cid}` — read one · Scope `pac:command:read`. `200`/`404`.

### 4.3 `GET …/comandos?estado=published` — list catalog for a patient
Scope `pac:command:read`. Filter by `estado` (repeatable). Default excludes `retired`.
- WHERE `estado` is omitted, THE SYSTEM SHALL return only active commands (`drafted|validated|published`),
  never `retired`.

### 4.4 `PUT …/comandos/{cid}` — edit draft (identity fields)
Scope `pac:command:write`, `If-Match` required. Editing gesture/label/need is allowed **only while
`drafted`** (identity is frozen once published — ADR-006).
- WHILE `estado != drafted`, THE SYSTEM SHALL reject identity edits with `409`
  (`type=/errors/invalid-lifecycle-transition`) and SHALL direct the caller to recalibrate (§4.7) or
  retire+recreate.

### 4.5 `POST …/comandos/{cid}:validate` — draft → validated
Scope `pac:command:publish`, `If-Match` required.
- WHEN validation is requested WHILE `estado = drafted`, THE SYSTEM SHALL resolve every referenced
  primitive against GEST (`GestDetectabilityPort`) and set `estado = validated` on success.
- IF any referenced primitive id is unknown to GEST, THEN THE SYSTEM SHALL reject with `422`
  (`type=/errors/validation`, field `primitivoPrincipalId`/`primitivoSecundarioId`).

### 4.6 `POST …/comandos/{cid}:publish` — validated → published (**emergency gate, ADR-005**)
Scope `pac:command:publish`, `If-Match` required.

**EARS — emergency-eligibility gate (fail-closed / advisory asymmetry)**
- WHEN publish is requested WHILE `estado = validated` AND `urgencia = emergencia`, THE SYSTEM SHALL call
  GEST synchronously to confirm **every** referenced primitive (principal and, for a composite, secondary)
  is `supported`.
- IF any referenced primitive is not `supported`, THEN THE SYSTEM SHALL reject publish with `422`
  (`type=/errors/emergency-not-detectable`) and SHALL leave `estado = validated`.
- IF the GEST eligibility call times out, errors, or returns an unknown result WHILE `urgencia =
  emergencia`, THEN THE SYSTEM SHALL fail closed: reject with `503`
  (`type=/errors/eligibility-gate-unavailable`), SHALL NOT publish, and SHALL surface a retry-able error.
- WHERE `urgencia = rotina`, THE SYSTEM SHALL treat the gate as **advisory**: a non-`supported` primitive
  produces a `warnings[]` entry in the `200` response but SHALL NOT block publish.
- WHEN publish succeeds, THE SYSTEM SHALL set `estado = published` and record the domain fact
  `ComandoPublicado` synchronously to HIST.

### 4.7 `POST …/comandos/{cid}:recalibrate` — in-place tuning (published)
Scope `pac:command:publish`, `If-Match` required. Body carries tuning fields only.
```json
{ "sensibilidade": "alta", "tempoMinGestoMs": 250, "tempoMaxGestoMs": 1400, "urgencia": "emergencia" }
```
**EARS**
- WHEN recalibration is applied WHILE `estado = published`, THE SYSTEM SHALL update the tuning fields
  in place and increment `calibracaoVersao` by exactly 1 (ADR-004/ADR-006).
- IF a recalibration raises `urgencia` to `emergencia` (or edits a primitive of an already-emergency
  command), THEN THE SYSTEM SHALL re-run the emergency gate (§4.6 fail-closed rules) before persisting.
- THE SYSTEM SHALL NOT alter the referenced primitive(s), `rotulo` or `necessidade` via recalibrate —
  those are identity fields; a material identity change is retire+recreate (§4.8).
- WHEN recalibration succeeds, THE SYSTEM SHALL record `ComandoRecalibrado` synchronously to HIST.

### 4.8 `POST …/comandos/{cid}:retire` — → retired (terminal, history-preserving)
Scope `pac:command:publish`, `If-Match` required.
- WHEN retire is requested from any non-`retired` state, THE SYSTEM SHALL set `estado = retired` and
  SHALL NOT hard-delete the row (ADR-006), preserving historical `Evento`/HIST interpretability.
- WHILE `estado = retired`, THE SYSTEM SHALL reject every further transition with `409`
  (`type=/errors/invalid-lifecycle-transition`).
- WHEN retire succeeds, THE SYSTEM SHALL record `ComandoAposentado` synchronously to HIST.

## 5. Catalog publication (read surface for detection)

Service-to-service surface consumed by **GEST** to snapshot per-command calibration into an immutable
`DetectionProfile` (ADR-004 — PAC authors, GEST materializes). Pull-based (no bus; messaging disabled).

### 5.1 `GET /api/pac/v1/pacientes/{pid}/catalogo-ativo` — active calibrated catalog
Scope `pac:catalog:read`.

Response `200`:
```json
{
  "pacienteId": "…",
  "empresaId": "…",
  "catalogoVersao": 42,                 // monotonic; bumps on any publish/recalibrate/retire of the patient
  "geradoEm": "2026-07-28T14:03:00Z",
  "comandos": [
    {
      "comandoId": "…",
      "rotulo": "chamar a cuidadora",
      "necessidade": "assistencia",
      "primitivoPrincipalId": "…",
      "primitivoSecundarioId": null,
      "sensibilidade": "alta",
      "tempoMinGestoMs": 250, "tempoMaxGestoMs": 1400,
      "urgencia": "emergencia",
      "calibracaoVersao": 3
    }
  ]
}
```
**EARS**
- THE SYSTEM SHALL include only `published` commands in `catalogo-ativo` (never `drafted|validated|
  retired`).
- WHEN any command of a patient is published, recalibrated or retired, THE SYSTEM SHALL bump the
  patient's `catalogoVersao` so GEST can detect that a re-snapshot is due.
- THE SYSTEM SHALL support conditional `GET` via `If-None-Match` on `catalogoVersao` (ETag), returning
  `304` when the catalog is unchanged.
