## 1. Objective

Specify the security posture of `pac-service`: OAuth2 resource server configuration, scope-per-endpoint enforcement, multi-tenant isolation, cross-service authentication, and security-sensitive edge cases.

---

## 2. Scope

**In scope:**
- JWT resource server configuration (Spring Security, Keycloak)
- Scope enforcement matrix (from SPEC-01 §7)
- Multi-tenant isolation: `X-Empresa-Id` validation and schema scoping
- Cross-service call security (`GestDetectabilityPort`, `AcsDirectoryPort`, `EdgeDevicePort`, `HistFactPort`)
- LGPD data scoping

**Out of scope:**
- Keycloak realm/client provisioning (infrastructure)
- mTLS between services (deferred post-MVP)
- Rate limiting (GWY responsibility)

## 3. OAuth2 resource server

PAC is configured as a Spring Security 6 OAuth2 resource server:

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          jwk-set-uri: ${KEYCLOAK_JWK_SET_URI}
```

- Every endpoint requires a valid `Bearer` JWT (no public endpoints in MVP).
- JWT claims used: `sub` (principal id), `empresaId` (tenant claim), `scope` (granted scopes).
- THE SYSTEM SHALL reject requests with an absent or invalid JWT with `401` (`type=/errors/unauthorized`).

---

## 4. Tenant isolation enforcement

### 4.1 `X-Empresa-Id` validation

Every request must include `X-Empresa-Id`. PAC resolves the DB schema from this header:

1. Extract `X-Empresa-Id` from the request.
2. Extract `empresaId` from the JWT claims.
3. Assert `X-Empresa-Id == empresaId`. If mismatch → `403 /errors/tenant-mismatch`.
4. Resolve the Postgres schema: `schema = "empresa_" + slugify(empresaId)` (or a lookup from ACS).
5. Set the JDBC connection's `search_path` to the resolved schema for the duration of the request.

EARS:
- THE SYSTEM SHALL require a non-empty `X-Empresa-Id` header on every request.
- IF `X-Empresa-Id` is absent or empty, THEN THE SYSTEM SHALL reject with `400` (`type=/errors/missing-tenant`).
- IF the JWT `empresaId` claim does not match `X-Empresa-Id`, THEN THE SYSTEM SHALL reject with `403` (`type=/errors/tenant-mismatch`) and SHALL NOT leak whether the empresa exists.

### 4.2 Row-level defense in depth

Every `paciente` row carries a `tenant_id` column that must match the schema's empresa. If the `search_path` is misconfigured and a row crosses schemas, the `WHERE tenant_id = $tenant` clause in all queries will catch it. This is a belt-and-suspenders guard, not a primary isolation mechanism.

EARS:
- THE SYSTEM SHALL never return a `Paciente` or `Comando` belonging to another empresa, regardless of query params.

## 5. Scope enforcement

| Operation | Required scope | Spring annotation |
|---|---|---|
| `POST /pacientes` | `pac:patient:write` | `@PreAuthorize("hasAuthority('SCOPE_pac:patient:write')")` |
| `GET /pacientes`, `GET /pacientes/{id}` | `pac:patient:read` | `@PreAuthorize("hasAuthority('SCOPE_pac:patient:read')")` |
| `PUT /pacientes/{id}` | `pac:patient:write` | same |
| `POST …/comandos` | `pac:command:write` | `@PreAuthorize("hasAuthority('SCOPE_pac:command:write')")` |
| `GET …/comandos`, `GET …/comandos/{cid}` | `pac:command:read` | `@PreAuthorize("hasAuthority('SCOPE_pac:command:read')")` |
| `PUT …/comandos/{cid}` | `pac:command:write` | same |
| `:validate`, `:publish`, `:recalibrate`, `:retire` | `pac:command:publish` | `@PreAuthorize("hasAuthority('SCOPE_pac:command:publish')")` |
| `GET …/catalogo-ativo` | `pac:catalog:read` | `@PreAuthorize("hasAuthority('SCOPE_pac:catalog:read')")` |

EARS:
- WHILE the caller lacks the scope required by an endpoint, THE SYSTEM SHALL respond `403` (`type=/errors/insufficient-scope`).

## 6. Cross-service authentication

Outbound calls to GEST, ACS, EDGE, and HIST use a **client-credentials** access token:

```
spring.security.oauth2.client.registration.pac-service:
  authorization-grant-type: client_credentials
  client-id: ${PAC_CLIENT_ID}
  client-secret: ${PAC_CLIENT_SECRET}
  scope: gest:read, acs:read, edge:read, hist:write
```

The token is fetched once and cached (Spring OAuth2 `ServletOAuth2AuthorizedClientManager` with auto-refresh on expiry). Every outbound Feign/RestTemplate call includes `Authorization: Bearer <service-token>` and `X-Correlation-Id` (propagated from the inbound request).

---

## 7. LGPD scoping

- `paciente.nome` is PII (patient name). It is stored in the per-empresa schema, already isolating it at the schema level.
- No biometric data is stored by PAC (pixels, landmarks are never ingested — owned by EDGE/GEST).
- Suppression on patient deletion is handled at the ACS/tenant level. PAC does not implement independent erasure in the MVP (noted as a future compliance item).
- `Comando` data (`rotulo`, `necessidade`) is family-authored and may contain indirect PII (e.g. personal need labels). Same schema isolation applies.

---

## 8. Security-relevant EARS summary

- THE SYSTEM SHALL reject requests with missing JWT with `401`.
- THE SYSTEM SHALL reject requests with an expired or invalid signature JWT with `401`.
- IF `X-Empresa-Id` is absent, THEN THE SYSTEM SHALL reject with `400`.
- IF `X-Empresa-Id` does not match JWT tenant claim, THEN THE SYSTEM SHALL reject with `403` and SHALL NOT reveal whether the empresa exists.
- WHILE a caller lacks the required scope, THE SYSTEM SHALL return `403`.
- THE SYSTEM SHALL set the JDBC `search_path` to the empresa schema on every request before any DB access.

---

## 9. Acceptance criteria

- THE SYSTEM SHALL return `401` for any request without a valid JWT.
- THE SYSTEM SHALL return `403` with `type=/errors/tenant-mismatch` when JWT tenant ≠ `X-Empresa-Id`.
- THE SYSTEM SHALL return `403` with `type=/errors/insufficient-scope` when a scope is missing.
- THE SYSTEM SHALL isolate all DB queries to the tenant schema by setting `search_path` per request.
- Cross-service tokens SHALL use `client_credentials` grant and SHALL be refreshed automatically before expiry.
