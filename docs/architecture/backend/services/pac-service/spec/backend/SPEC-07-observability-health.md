# SPEC-07 — Observability & Health (`pac-service`)

> Module: **PAC** · Service: `pac-service` · Package: `com.neuroassist.pac`
> Stack: Spring Boot Actuator, Micrometer, Spring Boot 3
> Generated by `/be-architect-specs-validate neuroassist-ai PAC` · 2026-07-28

---

## 1. Objective

Specify the observability surface of `pac-service`: health endpoints, structured logging, metrics, distributed traces, and alerting anchors. This spec enables SRE to monitor the service in production and detect calibration/gate failures before they become patient-safety issues.

---

## 2. Scope

**In scope:**
- Spring Boot Actuator endpoints (`/actuator/health`, `/actuator/info`, `/actuator/metrics`)
- Structured JSON logging (correlation-id, tenant-id, lifecycle events)
- Micrometer metrics (counters, timers, gauge for `catalogoVersao` drift)
- Distributed tracing (`X-Correlation-Id` propagation)
- Alert anchors (SLO violations worth a page)

**Out of scope:**
- Centralized log aggregation backend (infra concern)
- OpenTelemetry collector configuration (ops concern)
- Alert routing (PagerDuty/etc. — ops concern)

---

## 3. Health endpoints

Spring Boot Actuator exposed on the management port (default 8081):

| Endpoint | Purpose |
|---|---|
| `GET /actuator/health/liveness` | Kubernetes liveness — service process alive? |
| `GET /actuator/health/readiness` | Kubernetes readiness — DB reachable + GEST reachable? |
| `GET /actuator/info` | Build info (version, git SHA) |
| `GET /actuator/metrics` | Micrometer metrics scrape (Prometheus format via `/actuator/prometheus`) |

Readiness checks:
- PostgreSQL: `DataSourceHealthIndicator` (query: `SELECT 1`).
- GEST: custom `GestHealthIndicator` → `GET /api/gest/v1/actuator/health` (or a lightweight ping). If GEST unreachable → readiness `OUT_OF_SERVICE` (not `DOWN` — the service can still serve authoring for `rotina` commands).

EARS:
- THE SYSTEM SHALL expose `/actuator/health/liveness` and `/actuator/health/readiness` at all times.
- THE SYSTEM SHALL mark readiness as `OUT_OF_SERVICE` if the Postgres connection pool is exhausted.

## 4. Structured logging

All log lines are JSON (Logback + Logstash encoder). Mandatory MDC fields on every log line:

| MDC key | Value |
|---|---|
| `correlationId` | `X-Correlation-Id` of the request |
| `tenantId` | `X-Empresa-Id` of the request |
| `pacienteId` | Set when operating on a patient resource |
| `comandoId` | Set when operating on a command resource |
| `serviceVersion` | Build version from `application.properties` |

### 4.1 Mandatory log events

| Event | Level | When |
|---|---|---|
| `PAC_COMANDO_PUBLISHED` | INFO | Successful `:publish` transition |
| `PAC_COMANDO_RECALIBRATED` | INFO | Successful `:recalibrate` |
| `PAC_COMANDO_RETIRED` | INFO | Successful `:retire` |
| `PAC_GATE_BLOCKED` | WARN | Emergency gate blocked publish (`:publish` → `422`) |
| `PAC_GATE_UNAVAILABLE` | ERROR | Gate call failed/timed out (`:publish` → `503`) |
| `PAC_HIST_FACT_RETRY` | WARN | HIST unavailable → fact enqueued for retry |
| `PAC_HIST_FACT_LOST` | ERROR | HIST retry exhausted → fact dropped (monitoring alert) |
| `PAC_TENANT_MISMATCH` | WARN | JWT tenant ≠ `X-Empresa-Id` |

EARS:
- THE SYSTEM SHALL emit a structured log line with `correlationId` and `tenantId` on every request completion.
- WHEN the emergency gate blocks a publish, THE SYSTEM SHALL log `PAC_GATE_BLOCKED` at WARN with the blocked `primitivoId` and `urgencia`.
- WHEN the emergency gate is unavailable, THE SYSTEM SHALL log `PAC_GATE_UNAVAILABLE` at ERROR.

## 5. Metrics (Micrometer)

| Metric name | Type | Tags | Meaning |
|---|---|---|---|
| `pac.paciente.created` | Counter | `tenantId` | Patient registrations |
| `pac.comando.created` | Counter | `tenantId`, `urgencia` | Command drafts created |
| `pac.comando.published` | Counter | `tenantId`, `urgencia` | Published commands |
| `pac.comando.recalibrated` | Counter | `tenantId` | Recalibrations |
| `pac.comando.retired` | Counter | `tenantId` | Retired commands |
| `pac.emergency.gate.blocked` | Counter | `tenantId` | Gate-blocked emergency publishes |
| `pac.emergency.gate.unavailable` | Counter | `tenantId` | Gate-unavailable (503) events |
| `pac.gest.call.duration` | Timer | `operation` | GEST `resolveTipoGesto` + `isSupported` latency |
| `pac.hist.fact.retry` | Counter | `fact` | HIST retry events |
| `pac.hist.fact.lost` | Counter | `fact` | HIST facts dropped after retry exhaustion |
| `pac.catalog.version.max` | Gauge | `tenantId`, `pacienteId` | Max `catalogoVersao` across patients (staleness indicator) |

## 6. Distributed tracing

`X-Correlation-Id` is the correlation anchor (no Zipkin/Jaeger in MVP — the header is sufficient for log correlation). Implementation:

- `CorrelationIdFilter` (servlet filter): reads `X-Correlation-Id` from request; generates UUID if absent; stores in MDC and response header.
- All Feign / RestTemplate clients propagate `X-Correlation-Id` as an outbound header.

---

## 7. Alert anchors (SLO watch-list)

| Alert | Condition | Severity |
|---|---|---|
| Gate-blocked rate high | `pac.emergency.gate.blocked` > 3 / hour / tenant | WARNING |
| Gate-unavailable spike | `pac.emergency.gate.unavailable` > 5 in 5 min | CRITICAL (patient-safety gate down) |
| HIST facts lost | `pac.hist.fact.lost` > 0 | WARNING (audit trail gap) |
| Readiness degraded | `/actuator/health/readiness` returns `OUT_OF_SERVICE` for > 1 min | CRITICAL |
| GEST call p99 > 1.5 s | `pac.gest.call.duration` p99 > 1.5s | WARNING (near timeout ceiling) |

---

## 8. Acceptance criteria

- THE SYSTEM SHALL expose liveness and readiness probes via Actuator.
- THE SYSTEM SHALL include `correlationId` and `tenantId` on every log line during request processing.
- THE SYSTEM SHALL emit `PAC_GATE_BLOCKED` or `PAC_GATE_UNAVAILABLE` logs for all emergency gate outcomes.
- THE SYSTEM SHALL register `pac.emergency.gate.blocked` and `pac.emergency.gate.unavailable` counters.
- THE SYSTEM SHALL propagate `X-Correlation-Id` on all outbound calls to GEST, ACS, EDGE, and HIST.
