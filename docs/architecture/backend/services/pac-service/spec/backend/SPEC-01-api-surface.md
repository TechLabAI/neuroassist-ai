## 3. Technical decisions

- ADR-004: PAC is the authoring source; GEST is the execution motor. API surface enforces this boundary.
- ADR-005: Emergency-eligibility gate runs at `:publish` (and re-runs on `:recalibrate` if urgency rises).
- ADR-006: Versioned retire — `Comando` rows are never hard-deleted; `retired` is the terminal lifecycle state.

## 4. Resource hierarchy

```
/api/pac/v1/
├── pacientes                         POST (create), GET (list)
│   └── {id}                          GET, PUT
│       └── comandos                  POST (create draft), GET (list)
│           └── {cid}                 GET, PUT (edit draft)
│               └── :validate         POST (drafted → validated)
│               └── :publish          POST (validated → published)
│               └── :recalibrate      POST (published → published, tuning)
│               └── :retire           POST (any non-retired → retired)
│       └── catalogo-ativo            GET (active catalog for GEST snapshot)
```

Base path is `pac-service`-internal; GWY strips the `/api/pac/v1` prefix before Eureka routing.

## 5. Header protocol

### 5.1 Mandatory request headers

| Header | Rule |
|---|---|
| `X-Empresa-Id` | Required on every call. Routes schema selection. |
| `Authorization` | `Bearer <JWT>`. JWT `empresaId` claim must match `X-Empresa-Id`. |
| `If-Match` | Required on all PUT/lifecycle POST operations (optimistic lock). |
| `X-Correlation-Id` | Optional on request; generated+echoed by PAC if absent. |
| `Idempotency-Key` | Optional on `POST` creates; UUID format; dedup within 24h window. |

### 5.2 Response headers

| Header | Meaning |
|---|---|
| `ETag` | `row_version` of the returned/mutated resource (quoted integer string `"N"`). |
| `Location` | On `201` creates — absolute URI of the new resource. |
| `Retry-After` | On `503` eligibility-gate-unavailable — suggested retry delay in seconds. |
| `X-Correlation-Id` | Echoed (generated if absent). |

### 5.3 EARS — header invariants

- THE SYSTEM SHALL require a non-empty `X-Empresa-Id` header on every request.
- IF `X-Empresa-Id` is absent or empty, THEN THE SYSTEM SHALL reject with `400` (`type=/errors/missing-tenant`).
- IF the JWT tenant claim does not match `X-Empresa-Id`, THEN THE SYSTEM SHALL reject with `403` (`type=/errors/tenant-mismatch`) and SHALL NOT leak whether the empresa exists.
- WHEN a request omits `X-Correlation-Id`, THE SYSTEM SHALL generate one and echo it on the response.
- IF `If-Match` is missing or stale on a mutation, THEN THE SYSTEM SHALL reject with `409` (`type=/errors/conflict-precondition`).

## 6. Error model (RFC 7807 ProblemDetail)

Media type: `application/problem+json`. All error responses use this shape:

```json
{
  "type": "/errors/<code>",
  "title": "<Human-readable title>",
  "status": <HTTP code>,
  "detail": "<Context-specific message>",
  "instance": "<request path>",
  "correlationId": "<X-Correlation-Id>",
  "errors": [{ "field": "<field>", "code": "<validation code>" }]
}
```

| `type` | HTTP | Trigger |
|---|---|---|
| `/errors/validation` | 400 | Bean-validation / blank required fields |
| `/errors/missing-tenant` | 400 | `X-Empresa-Id` absent |
| `/errors/unauthorized` | 401 | Missing / invalid JWT |
| `/errors/insufficient-scope` | 403 | Required OAuth2 scope absent |
| `/errors/tenant-mismatch` | 403 | JWT tenant ≠ `X-Empresa-Id` |
| `/errors/not-found` | 404 | Resource not in this empresa |
| `/errors/conflict-precondition` | 409 | Stale `ETag` / `If-Match` |
| `/errors/invalid-lifecycle-transition` | 409 | Lifecycle transition not allowed from current `estado` |
| `/errors/idempotency-mismatch` | 409 | Same key, different body |
| `/errors/duplicate-active-mapping` | 422 | Same gesture+need already has an active command |
| `/errors/emergency-not-detectable` | 422 | Emergency gate failed (primitive not `supported`) |
| `/errors/eligibility-gate-unavailable` | 503 | GEST unreachable during emergency gate |

## 7. Scope matrix

| Endpoint | Required scope |
|---|---|
| `POST /pacientes` | `pac:patient:write` |
| `GET /pacientes`, `GET /pacientes/{id}` | `pac:patient:read` |
| `PUT /pacientes/{id}` | `pac:patient:write` |
| `POST /pacientes/{pid}/comandos` | `pac:command:write` |
| `GET /pacientes/{pid}/comandos`, `GET /pacientes/{pid}/comandos/{cid}` | `pac:command:read` |
| `PUT /pacientes/{pid}/comandos/{cid}` | `pac:command:write` |
| `POST …/comandos/{cid}:validate` | `pac:command:publish` |
| `POST …/comandos/{cid}:publish` | `pac:command:publish` |
| `POST …/comandos/{cid}:recalibrate` | `pac:command:publish` |
| `POST …/comandos/{cid}:retire` | `pac:command:publish` |
| `GET /pacientes/{pid}/catalogo-ativo` | `pac:catalog:read` |

- WHILE the caller lacks the required scope, THE SYSTEM SHALL respond `403` (`type=/errors/insufficient-scope`).

## 8. Pagination

`GET /pacientes` and `GET /pacientes/{pid}/comandos` are paged:
- Query params: `page` (0-based, default 0), `size` (default 20, max 100).
- Response envelope: `{ "items": [...], "page": N, "size": N, "total": N }`.
- THE SYSTEM SHALL never return a `Paciente` or `Comando` belonging to another empresa, regardless of query params.

## 9. Edge cases

| Scenario | Expected behaviour |
|---|---|
| `PUT /pacientes/{pid}/comandos/{cid}` with `estado != drafted` | `409 /errors/invalid-lifecycle-transition` |
| `:publish` on `estado = drafted` | `409 /errors/invalid-lifecycle-transition` |
| `:retire` on `estado = retired` | `409 /errors/invalid-lifecycle-transition` |
| `GET /pacientes/{pid}/catalogo-ativo` with matching `If-None-Match` | `304 Not Modified` (empty body) |
| `POST /pacientes` with duplicate `Idempotency-Key` (same body) | `200` + original resource |
| `POST /pacientes` with duplicate `Idempotency-Key` (different body) | `409 /errors/idempotency-mismatch` |

## 10. Acceptance criteria

- THE SYSTEM SHALL register a new patient and return `201` with a `Location` header pointing to the new resource.
- THE SYSTEM SHALL set `estado = drafted` and `calibracaoVersao = 0` on every new command creation.
- THE SYSTEM SHALL enforce the scope matrix — any call without the required scope returns `403`.
- THE SYSTEM SHALL maintain tenant isolation — no resource of empresa A is readable or mutable by empresa B.
- THE SYSTEM SHALL propagate `X-Correlation-Id` end-to-end (generate if absent).
- WHEN a request carries a stale `If-Match`, THE SYSTEM SHALL return `409` before applying any mutation.
