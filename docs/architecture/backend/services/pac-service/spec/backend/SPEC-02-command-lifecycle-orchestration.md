# SPEC-02 — Command Lifecycle Orchestration (`pac-service`)

> Module: **PAC** · Service: `pac-service` · Package: `com.neuroassist.pac`
> EARS guide: `docs/architecture/backend/standards/ears-notation.md`
> Generated by `/be-architect-specs-validate neuroassist-ai PAC` · 2026-07-28

---

## 1. Objective

Specify the full `Comando` lifecycle state machine: states, allowed transitions, guard conditions, side effects (domain-fact recording to HIST, `catalogoVersao` bump), and application-layer orchestration. This is the **core process** of PAC — everything else is preamble or read-surface.

---

## 2. Scope

**In scope:**
- `Comando` state machine (`drafted → validated → published → recalibrated ↻ → retired`)
- Per-transition guard conditions and EARS invariants
- Side effects: `calibracaoVersao` bump, `catalogoVersao` bump, HIST fact recording
- `Application` service components that execute each transition
- Interaction with `GestDetectabilityPort` for validation and emergency gate

**Out of scope:**
- Emergency gate full spec — see SPEC-03
- Idempotency / concurrency lock — see SPEC-05
- Domain-fact payload schema in HIST — see SPEC-09/SPEC-10
- API controller annotations — see SPEC-01

---

## 3. Technical decisions

- ADR-004: PAC authors calibration; GEST materializes it into `DetectionProfile` (pull model).
- ADR-005: Emergency gate runs at `:publish` — fail-closed for `emergencia`, advisory for `rotina`.
- ADR-006: History-preserving — no hard delete; `retired` is terminal.

---

## 4. State machine

```
           ┌──────────────────────────────────────────────────────────┐
           │                                                          │
  [create] │            :validate          :publish                   │
 ──────────▼──────────  ──────────────►  ──────────────►  ─────────────────►
   drafted              validated           published          retired
                                            │    ▲
                                            │    │ :recalibrate (in-place)
                                            └────┘
```

Terminal state: `retired`. `retired` → anything is `409 invalid-lifecycle-transition`.
Recalibration is an in-place loop — `published → published` with `calibracaoVersao +1`.

---

## 5. Transition specifications

### 5.1 Create draft (`POST .../comandos`)

**Application component:** `ComandoAuthoringService.createDraft(CreateComandoRequest, PacienteId, TenantId)`

Guards (in order):
1. `PacienteId` belongs to the tenant.
2. `rotulo` non-blank, `necessidade` non-blank.
3. `tempoMinGestoMs > 0` and `<= tempoMaxGestoMs`.
4. If composite: `primitivoSecundarioId != primitivoPrincipalId`.
5. No active (non-retired) command with the same `(pacienteId, gesture-set, necessidade)` — enforced via `ux_comando_active_mapping` index in DB or application check.

Side effects:
- Persist `Comando` with `estado = drafted`, `calibracaoVersao = 0`, `row_version = 0`.
- THE SYSTEM SHALL NOT run the emergency gate at draft creation.

EARS:
- WHEN a command draft is created, THE SYSTEM SHALL set `estado = drafted` and `calibracaoVersao = 0`.
- IF an active (non-`retired`) command for the same `pacienteId` already maps the same gesture set to the same `necessidade`, THEN THE SYSTEM SHALL reject with `422` (`type=/errors/duplicate-active-mapping`).

### 5.2 Validate draft (`:validate`)

**Application component:** `ComandoLifecycleService.validate(ComandoId, IfMatchVersion, TenantId)`

Pre-condition: `estado = drafted`. Post-condition: `estado = validated`.

Guards:
1. ETag / `row_version` matches (optimistic lock).
2. Every referenced primitive id (`primitivoPrincipalId`, `primitivoSecundarioId` if present) resolves in GEST (`GestDetectabilityPort.resolveTipoGesto`).

Side effects:
- Update `estado = validated`, bump `row_version`.
- No `calibracaoVersao` change; no `catalogoVersao` bump; no HIST fact.

EARS:
- WHEN validation is requested WHILE `estado = drafted`, THE SYSTEM SHALL resolve every referenced primitive against GEST and set `estado = validated` on success.
- IF any referenced primitive id is unknown to GEST, THEN THE SYSTEM SHALL reject with `422`.

### 5.3 Publish (`:publish`)

**Application component:** `ComandoLifecycleService.publish(ComandoId, IfMatchVersion, TenantId)`

Pre-condition: `estado = validated`. Post-condition: `estado = published`.

Guards:
1. ETag matches.
2. **Emergency gate** (SPEC-03): if `urgencia = emergencia`, call `GestDetectabilityPort.isSupported` for every primitive — fail-closed (see SPEC-03).

Side effects on success:
- Update `estado = published`, bump `row_version`.
- Bump patient's `catalogoVersao` by 1.
- Record `ComandoPublicado` to HIST (synchronous, best-effort-with-retry).

EARS:
- WHEN publish succeeds, THE SYSTEM SHALL set `estado = published` and record the domain fact `ComandoPublicado` synchronously to HIST.
- WHEN any command is published, THE SYSTEM SHALL bump the patient's `catalogoVersao`.

### 5.4 Recalibrate (`:recalibrate`) — in-place tuning

**Application component:** `ComandoLifecycleService.recalibrate(ComandoId, RecalibrateRequest, IfMatchVersion, TenantId)`

Pre-condition: `estado = published`. Post-condition: `estado = published`.

Tuning fields (the only mutable fields post-publish): `sensibilidade`, `tempoMinGestoMs`, `tempoMaxGestoMs`, `urgencia`.
Identity fields (`rotulo`, `necessidade`, `primitivoPrincipalId`, `primitivoSecundarioId`) are **frozen** after publish — a change here requires `retire + recreate`.

Guards:
1. ETag matches.
2. If `urgencia` is being raised to `emergencia` (or editing tuning of an already-`emergencia` command): re-run emergency gate (SPEC-03).

Side effects:
- Update tuning fields, increment `calibracaoVersao` by exactly 1, bump `row_version`.
- Bump patient's `catalogoVersao` by 1.
- Record `ComandoRecalibrado` to HIST.

EARS:
- WHEN recalibration is applied WHILE `estado = published`, THE SYSTEM SHALL update the tuning fields in place and increment `calibracaoVersao` by exactly 1.
- THE SYSTEM SHALL NOT alter `rotulo`, `necessidade`, `primitivoPrincipalId` or `primitivoSecundarioId` via `:recalibrate`.
- IF a recalibration raises `urgencia` to `emergencia`, THE SYSTEM SHALL re-run the emergency gate before persisting.
- WHEN recalibration succeeds, THE SYSTEM SHALL record `ComandoRecalibrado` synchronously to HIST.

### 5.5 Retire (`:retire`) — terminal

**Application component:** `ComandoLifecycleService.retire(ComandoId, IfMatchVersion, TenantId)`

Pre-condition: any non-`retired` state. Post-condition: `estado = retired`.

Guards:
1. ETag matches.
2. `estado != retired` (else `409 /errors/invalid-lifecycle-transition`).

Side effects:
- Update `estado = retired`, bump `row_version`.
- Bump patient's `catalogoVersao` by 1.
- Record `ComandoAposentado` to HIST.
- Row is **not** deleted (ADR-006 — history-preserving).

EARS:
- WHEN retire is requested from any non-`retired` state, THE SYSTEM SHALL set `estado = retired` and SHALL NOT hard-delete the row.
- WHILE `estado = retired`, THE SYSTEM SHALL reject every further transition with `409` (`type=/errors/invalid-lifecycle-transition`).
- WHEN retire succeeds, THE SYSTEM SHALL record `ComandoAposentado` synchronously to HIST.

---

## 6. `catalogoVersao` management

`catalogoVersao` is a per-patient monotonic counter that bumps on every `publish`, `recalibrate`, or `retire` transition (any event that changes what GEST would see). Implementation: a `catalogo_versao integer NOT NULL DEFAULT 0` column on `paciente`, incremented atomically in the same DB transaction as the lifecycle update.

It backs the `ETag` on `GET .../catalogo-ativo` — GEST uses `If-None-Match` to avoid redundant snapshots.

- WHEN any command of a patient is published, recalibrated or retired, THE SYSTEM SHALL bump the patient's `catalogoVersao` so GEST can detect that a re-snapshot is due.

---

## 7. Identity-edit restriction (ADR-006)

EARS:
- WHILE `estado != drafted`, THE SYSTEM SHALL reject identity-field edits via `PUT .../comandos/{cid}` with `409 /errors/invalid-lifecycle-transition`.

Identity fields (frozen after first publish): `rotulo`, `necessidade`, `primitivoPrincipalId`, `primitivoSecundarioId`. Tuning fields are only mutable via `:recalibrate`.

## 8. Edge cases

| Scenario | Behaviour |
|---|---|
| `:validate` on `validated` command | `409 /errors/invalid-lifecycle-transition` |
| `:publish` on `drafted` command | `409 /errors/invalid-lifecycle-transition` |
| `:recalibrate` on `drafted` or `validated` | `409 /errors/invalid-lifecycle-transition` |
| `:retire` on `retired` | `409 /errors/invalid-lifecycle-transition` |
| HIST unavailable during fact recording | Retry outbox (local); do NOT roll back lifecycle transition |
| Duplicate gesture+need for the same patient (second draft) | `422 /errors/duplicate-active-mapping` |
| First `retired` command then same gesture+need recreated | Allowed (`ux_comando_active_mapping` is partial — `WHERE estado <> 'retired'`) |

## 9. Implementation components

| Component | Layer | Responsibility |
|---|---|---|
| `ComandoController` | `api` | HTTP → `ComandoAuthoringService` / `ComandoLifecycleService` dispatch |
| `ComandoAuthoringService` | `application` | `createDraft`, `editDraft` with guard checks |
| `ComandoLifecycleService` | `application` | All lifecycle transitions + side effects |
| `ComandoRepository` | `infrastructure` | CRUD + row_version + partial unique index |
| `GestDetectabilityPort` | `application/port` | Interface for primitive resolution/gate |
| `HistFactPort` | `application/port` | Interface for synchronous fact dispatch to HIST |
| `PacienteVersionBumper` | `application` | Atomic `catalogoVersao` increment on lifecycle events |

## 10. Acceptance criteria

- THE SYSTEM SHALL set `estado = drafted` and `calibracaoVersao = 0` on every new command.
- WHEN validation completes, THE SYSTEM SHALL set `estado = validated` and verify every primitive in GEST.
- WHEN publish completes, THE SYSTEM SHALL set `estado = published`, bump `catalogoVersao`, and record `ComandoPublicado` to HIST.
- WHEN recalibration completes, THE SYSTEM SHALL increment `calibracaoVersao` by exactly 1 and bump `catalogoVersao`.
- WHEN retire completes, THE SYSTEM SHALL set `estado = retired`, preserve the row, bump `catalogoVersao`, and record `ComandoAposentado` to HIST.
- THE SYSTEM SHALL reject any attempt to transition a `retired` command with `409`.
