# SPEC-05 — Caregiver-Patient Linkage & Coverage Invariant (`acs-service`)

> Module: **ACS** · Service: `acs-service` · Package: `com.neuroassist.acs`
> Contract source: `contracts/api-contract.md §5`, `contracts/api-contract.md §6.2`
> EARS guide: `docs/architecture/backend/standards/ears-notation.md`
> Generated by `/be-architect-specs neuroassist-ai ACS` · 2026-07-29

---

## 1. Objective

Specify the caregiver-patient linkage lifecycle (ADR-006): link creation, revocation, the same-tenant
invariant, the idempotency contract, and the **coverage invariant** (a patient must always have at
least one alarm-eligible, active caregiver). This is a safety-critical spec: the coverage invariant
protects a patient from a silent routing failure in EVNT.

---

## 2. Scope

**In scope:**
- Link creation: `POST /api/v1/acs/caregivers/{id}/links` (including PAC resolve call)
- Link revocation: `DELETE /api/v1/acs/caregivers/{id}/links/{linkId}`
- Same-tenant invariant enforcement (cross-tenant link rejection)
- Idempotency: duplicate active link → `200 OK`, not `201`
- Coverage invariant: block last-caregiver unlink/deactivation
- `CuidadorVinculadoAoPaciente` and `CuidadorDesvinculado` fact recording to HIST
- Directory routing: `GET /api/v1/acs/directory/patients/{pid}/caregivers` consistency

**Out of scope:**
- PAC `PacPatientResolvePort` implementation details — see SPEC-10
- Data-scope (entity-scope) query patterns — see SPEC-01 §6 + doc 04
- Caregiver deactivation + coverage check — see §5 of this spec

---

## 3. Technical decisions

- **ADR-006:** the `caregiver_patient_link` table is the single authoritative routing/scope source;
  EVNT reads it synchronously via the directory surface.
- **Coverage invariant (FE ADR-005 BE enforcement):** the guard is implemented at the application-service
  level (not only in the FE); the BE enforces it with a `409 Conflict` response.
- **Coordinator-override:** `coordenador_clinica` is implicitly alarm-eligible for all patients in the
  tenant (ADR-006 scope rule); no explicit link row is required for coordinators.

---

## 4. Link lifecycle

```
(none)
  ↓  POST /caregivers/{id}/links
active  ← idempotent on duplicate active link
  ↓  DELETE /caregivers/{id}/links/{linkId}
revoked (terminal; soft; audit preserved)
```

---

## 5. EARS invariants — linkage & coverage

**Link creation**
- WHEN a link is requested, THE SYSTEM SHALL verify (a) the caregiver exists and `status = active` in
  the caller's tenant and (b) `pacienteId` resolves in the **same tenant** via `PacPatientResolvePort`
  before writing the link.
- IF the caregiver and patient are in different tenants, THEN THE SYSTEM SHALL respond
  `422 Unprocessable Entity` (`type: /errors/cross-tenant-link`) — same-tenant invariant #1.
- IF `pacienteId` does not resolve in PAC (404 or unreachable), THEN THE SYSTEM SHALL respond
  `422 Unprocessable Entity` (`type: /errors/unknown-patient`) or `502`/`504`
  (`type: /errors/upstream-unavailable`) respectively — fail-closed.
- IF an `active` link already exists for the same (`cuidadorId`, `pacienteId`), THEN THE SYSTEM SHALL
  respond `200 OK` with the existing link and SHALL NOT create a duplicate (`ux_link_active`) —
  idempotent no-op.
- WHEN a link is created, THE SYSTEM SHALL emit `CuidadorVinculadoAoPaciente` (the anchor event) and
  record it to HIST synchronously/best-effort; the link SHALL immediately become visible in
  `GET /api/v1/acs/directory/patients/{pid}/caregivers`.
- WHERE the caller lacks `acs.vinculo.criar`, THE SYSTEM SHALL respond `403 Forbidden`.

**Link revocation**
- WHEN a link revocation is requested and the link is `active`, THE SYSTEM SHALL apply the **coverage
  check** before revoking: IF this is the last active link for the patient AND no `coordenador_clinica`
  exists in the tenant, THEN THE SYSTEM SHALL respond `409 Conflict`
  (`type: /errors/last-caregiver-link`) — coverage invariant (ADR-005 local / SPEC-06).
- IF the link is already `revoked`, THE SYSTEM SHALL respond `200 OK` (idempotent no-op).
- WHEN a link is revoked (coverage check passed), THE SYSTEM SHALL set `status = revoked` and
  `revogado_em = now()` (soft-revoke — audit invariant #7), emit `CuidadorDesvinculado`, record to HIST.
- WHERE the caller lacks `acs.vinculo.revogar`, THE SYSTEM SHALL respond `403 Forbidden`.

**Caregiver deactivation + coverage**
- WHEN a caregiver deactivation is requested, THE SYSTEM SHALL check if the caregiver has any `active`
  links AND is the last alarm-eligible person for any of those patients (counting coordinator override).
  IF so, THE SYSTEM SHALL respond `409 Conflict` (`type: /errors/last-caregiver-link`) before deactivating.
- The same coverage invariant that guards link revocation guards caregiver deactivation — both paths
  enforce it at the application service level.

**Directory consistency**
- WHEN a link is revoked, THE SYSTEM SHALL exclude that caregiver from the next
  `GET /api/v1/acs/directory/patients/{pid}/caregivers` response (no eventual-consistency lag; same
  database transaction).
- WHEN no active caregiver link resolves for a patient (and no `coordenador_clinica` exists), THE SYSTEM
  SHALL return `200 OK` with `responsibleCaregivers: []`; EVNT interprets this as a routing-failure
  alert, not a silent drop.
