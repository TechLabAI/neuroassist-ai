## 2. Feature: Tenant Provisioning

```gherkin
Feature: Tenant Provisioning
  As a platform conductor
  I want to provision a new tenant
  So that caregivers and patients can be registered within it

  Scenario: Successful tenant provisioning
    Given MIG is available and can provision schemas
    When I POST a tenant with nome "Família Amaral" and tipo "familia"
    Then the response status is 201
    And the tenant status is "active"
    And schema_name is not null

  Scenario: Tenant stuck in provisioning when MIG times out
    Given MIG times out on schema request
    When I POST a tenant with nome "Família Souza" and tipo "familia"
    Then the response status is 202
    And the tenant status is "provisioning"
    And schema_name is null

  Scenario: Retry a stuck tenant provisioning
    Given a tenant with status "provisioning" exists
    And MIG is now available
    When I POST provisioning:retry for that tenant
    Then the response status is 200
    And the tenant status is "active"

  Scenario: Retry an already active tenant is a no-op
    Given a tenant with status "active" exists
    When I POST provisioning:retry for that tenant
    Then the response status is 200
    And MIG is not called

  Scenario: Invalid tipo is rejected
    When I POST a tenant with tipo "unknownType"
    Then the response status is 400
    And the error type is "/errors/validation"
```

## 3. Feature: Caregiver Management

```gherkin
Feature: Caregiver Management
  As a coordinator
  I want to manage caregiver accounts
  So that the right people can respond to patient alarms

  Scenario: Create a caregiver in an active tenant
    Given an active tenant "t_0f8a" exists
    And I authenticate as a coordinator for that tenant
    When I POST a caregiver with login "jamilly@familia-amaral" and papel "cuidadora"
    Then the response status is 201
    And the caregiver status is "active"
    And the response body does not contain credential_hash or senha

  Scenario: Duplicate login in same tenant is rejected
    Given an active caregiver with login "jamilly@familia-amaral" exists
    When I POST another caregiver with the same login
    Then the response status is 409
    And the error type is "/errors/login-duplicate"

  Scenario: Create caregiver against non-active tenant is rejected
    Given a tenant with status "provisioning" exists
    When I POST a caregiver for that tenant
    Then the response status is 409
    And the error type is "/errors/tenant-not-active"

  Scenario: Deactivate a caregiver
    Given an active caregiver "5c1a" with no active patient links
    When I POST deactivation for caregiver "5c1a"
    Then the response status is 200
    And the caregiver status is "inactive"
    And the caregiver cannot authenticate afterwards

  Scenario: Deactivate last alarm-eligible caregiver is rejected
    Given an active caregiver "5c1a" is the only active link for patient "p_9a3f"
    And no coordinator exists in the tenant
    When I POST deactivation for caregiver "5c1a"
    Then the response status is 409
    And the error type is "/errors/last-caregiver-link"
```

## 4. Feature: Authentication & JWT

```gherkin
Feature: Authentication and JWT Issuance
  As a caregiver
  I want to authenticate with my credentials
  So that I receive a JWT to access the platform

  Scenario: Successful login
    Given an active caregiver with login "jamilly@familia-amaral" in active tenant "t_0f8a"
    When I POST /oauth2/token with correct credentials
    Then the response status is 200
    And the response contains accessToken, tenant, papel, and authorities
    And the token expires in at most 900 seconds

  Scenario: Wrong password returns 401 without user enumeration
    Given a caregiver with login "jamilly@familia-amaral"
    When I POST /oauth2/token with incorrect password
    Then the response status is 401
    And the error type is "/errors/invalid-credentials"
    And the error body does not indicate which field was wrong

  Scenario: Inactive caregiver login is rejected
    Given a caregiver with status "inactive"
    When I POST /oauth2/token with correct credentials
    Then the response status is 401
    And the error type is "/errors/invalid-credentials"

  Scenario: JWK set is accessible without authentication
    When I GET /oauth2/jwks without Authorization header
    Then the response status is 200
    And the response contains at least one key with kid and public JWK material
    And the response does not contain private_key_enc
```

## 5. Feature: Caregiver-Patient Linkage

```gherkin
Feature: Caregiver-Patient Linkage
  As a coordinator
  I want to link caregivers to patients
  So that alarms are routed to the right people

  Scenario: Successfully link a caregiver to a patient
    Given active caregiver "5c1a" in tenant "t_0f8a"
    And PAC confirms patient "p_9a3f" in tenant "t_0f8a"
    When I POST a link between caregiver "5c1a" and patient "p_9a3f"
    Then the response status is 201
    And the link status is "active"
    And the anchor event CuidadorVinculadoAoPaciente is recorded to HIST

  Scenario: Duplicate active link is idempotent
    Given an active link between caregiver "5c1a" and patient "p_9a3f" exists
    When I POST the same link again
    Then the response status is 200
    And no duplicate link is created

  Scenario: Cross-tenant link is rejected
    Given caregiver "5c1a" in tenant "t_0f8a"
    And PAC reports patient "p_9a3f" belongs to tenant "t_11cd"
    When I POST a link between caregiver "5c1a" and patient "p_9a3f"
    Then the response status is 422
    And the error type is "/errors/cross-tenant-link"

  Scenario: Link to unknown patient is rejected
    Given PAC returns 404 for patient "p_unknown"
    When I POST a link between caregiver "5c1a" and patient "p_unknown"
    Then the response status is 422
    And the error type is "/errors/unknown-patient"

  Scenario: Revoke the last caregiver link is blocked by coverage invariant
    Given caregiver "5c1a" is the only active link for patient "p_9a3f"
    And no coordinator exists in the tenant
    When I DELETE the link
    Then the response status is 409
    And the error type is "/errors/last-caregiver-link"

  Scenario: Revoke a link when another caregiver still covers the patient
    Given caregiver "5c1a" and caregiver "6d2b" are both linked to patient "p_9a3f"
    When I DELETE the link for caregiver "5c1a"
    Then the response status is 200
    And the link status is "revoked"
```
