# SPEC-07 — Observability & Health (`acs-service`)

> Module: **ACS** · Service: `acs-service` · Package: `com.neuroassist.acs`
> EARS guide: `docs/architecture/backend/standards/ears-notation.md`
> Generated by `/be-architect-specs neuroassist-ai ACS` · 2026-07-29

---

## 1. Objective

Specify the observability posture of `acs-service`: health endpoints, structured logging, key metrics,
and MDC propagation. Because ACS is a safety-critical identity service, its health directly affects
every other module's ability to authenticate and route alarms.

---

## 2. Scope

**In scope:**
- Spring Boot Actuator health/liveness/readiness endpoints
- MDC (`X-Correlation-Id`, `tenantId`, `userId`) on every log line
- Structured log fields — no credential/biometric data
- Key operational metrics (login attempts, provisioning sagas, JWK cache hits)
- Health indicators: DB connection, MIG reachability, JWK set validity

**Out of scope:**
- Alerting rules / Prometheus configuration (infra layer)
- HIST audit trail (separate concern — see SPEC-09)

---

## 3. EARS invariants — observability

**Health endpoints**
- THE SYSTEM SHALL expose `GET /actuator/health` with liveness and readiness sub-indicators, accessible
  without authentication.
- THE SYSTEM SHALL include the following health indicators:
  - `db`: JDBC connection pool to the global and empresa schemas.
  - `migPort`: reachability of `MigProvisioningPort` endpoint (used by provisioning saga).
  - `jwkSet`: at least one `active` signing key present in `signing_key` table.
- IF any of `db` or `jwkSet` is DOWN, THE SYSTEM SHALL report `OUT_OF_SERVICE` on readiness.

**Structured logging**
- THE SYSTEM SHALL propagate `X-Correlation-Id` into the MDC (`correlationId`) on every inbound
  request and include it on every log line for that request.
- THE SYSTEM SHALL include `tenantId` (from JWT `tenant` claim) and `userId` (from JWT `sub`) in the
  MDC for every authenticated request.
- THE SYSTEM SHALL never log the raw `senha`, `credential_hash`, `private_key_enc`, biometric data,
  or any PII beyond reference ids (`cuidadorId`, `pacienteId`, `tenantId`).
- THE SYSTEM SHALL log at `INFO` the start and end of each provisioning saga attempt, link create,
  and link revoke, including the `correlationId`, outcome, and latency.
- THE SYSTEM SHALL log at `WARN` any MIG or PAC integration timeout/circuit-open event with the
  upstream, `correlationId`, and retry attempt number.

**Metrics (Micrometer)**
- THE SYSTEM SHALL expose the following custom meters:
  - `acs.auth.attempts` (counter, tag: `outcome=success|failure`) — login attempts.
  - `acs.tenant.provisioning.duration` (timer) — end-to-end provisioning saga latency.
  - `acs.link.created` (counter) — caregiver-patient links created.
  - `acs.link.revoked` (counter) — caregiver-patient links revoked.
  - `acs.coverage.guard.triggered` (counter) — last-caregiver guard triggered (rejected revocations).
- THE SYSTEM SHALL expose the standard Spring Boot / JVM / Tomcat metrics at `/actuator/metrics`.
