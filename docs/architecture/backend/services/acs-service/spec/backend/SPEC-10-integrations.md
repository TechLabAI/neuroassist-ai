## 1. Objective

Specify the integration surface of `acs-service`: outbound ports (MIG, PAC), inbound reads (EVNT, EDGE,
DASH, HIST, PAC via directory surface), and the JWK-set dependency that all resource servers share.

---

## 2. Outbound integrations (ports)

### 2.1 `MigProvisioningPort` → MIG (`neuroassist-ai-migrations`)

**Purpose:** Request per-tenant schema provisioning as part of the tenant-creation saga (ADR-004).

| Operation | Interface method | REST shape |
|---|---|---|
| `requestTenantSchema(tenantId, schemaName)` | `MigProvisioningPort.requestTenantSchema` | `POST /api/mig/v1/tenants/{tenantId}/schemas` |
| `getTenantSchemaStatus(tenantId)` | `MigProvisioningPort.getTenantSchemaStatus` | `GET /api/mig/v1/tenants/{tenantId}/schemas/status` |

**EARS — MIG integration**
- THE SYSTEM SHALL call `MigProvisioningPort.requestTenantSchema` synchronously during tenant creation;
  the tenant transitions to `active` only on a `2xx` response.
- IF MIG responds with an error or times out (timeout ≤ 5s), THE SYSTEM SHALL NOT set the tenant to
  `active` — fail-closed (see SPEC-02).
- THE SYSTEM SHALL apply a circuit breaker on the MIG port: OPEN state → respond `202 provisioning`
  rather than hanging the caller.
- THE SYSTEM SHALL propagate `X-Correlation-Id` and `X-Empresa-Id` on every MIG call.

### 2.2 `PacPatientResolvePort` → PAC (`pac-service`)

**Purpose:** Validate that a `pacienteId` exists and belongs to the correct tenant before writing a
caregiver-patient link (fail-closed — SPEC-05).

| Operation | Interface method | REST shape |
|---|---|---|
| `resolvePatient(pacienteId, tenantId)` | `PacPatientResolvePort.resolvePatient` | `GET /api/pac/v1/pacientes/{pacienteId}` |

**EARS — PAC integration**
- THE SYSTEM SHALL call `PacPatientResolvePort.resolvePatient` before every link creation; only on a
  valid same-tenant response SHALL the link be written.
- IF PAC returns `404` or the tenant mismatches, THE SYSTEM SHALL respond `422` and SHALL NOT write the
  link.
- IF PAC is unreachable (timeout ≤ 2s), THE SYSTEM SHALL respond `502`/`504` (`upstream-unavailable`)
  — fail-closed (an unvalidated link is a routing hazard).
- THE SYSTEM SHALL propagate `X-Correlation-Id` and `X-Empresa-Id` on every PAC call.

## 3. Inbound integrations (ACS as provider)

### 3.1 JWK set — all resource servers

Every service (GEST, EVNT, PAC, EDGE, DASH, HIST) configures `jwk-set-uri = http://acs-service/oauth2/jwks`
(resolved via REG/Eureka) to validate ACS-issued JWTs without calling back on each request. See SPEC-03.

**EARS — JWK cache**
- THE SYSTEM SHALL set `Cache-Control: max-age=300` on `/oauth2/jwks` responses so resource servers
  cache the JWK set and do not poll ACS on every request.
- THE SYSTEM SHALL publish all recently-retired keys (within one JWT TTL) alongside the active key so
  in-flight tokens remain validatable across key rotations.

### 3.2 Directory surface — EVNT, PAC, DASH, EDGE, HIST

See `contracts/event-contracts.md §3` and `contracts/api-contract.md §6`.

| Consumer | Reads | Used for |
|---|---|---|
| EVNT (`CaregiverRoutingClient`) | `GET /api/v1/acs/directory/patients/{pid}/caregivers` | Alarm routing targets |
| PAC | `GET /api/v1/acs/directory/tenants/{tenantId}` | Tenant validity on patient writes |
| DASH, PAC, HIST | `GET /api/v1/acs/directory/caregivers/{id}/patient-scope` | Entity-scope filter (which patients the caller may see) |
| All | `GET /api/v1/acs/directory/caregivers/{id}` | Role + authorities resolution |

**EARS — directory SLA**
- THE SYSTEM SHALL respond to directory reads within **100ms p99** (same-node DB read; no remote call).
- THE SYSTEM SHALL set `Cache-Control: max-age=60` on directory responses (caregivers and links change
  infrequently; short TTL is acceptable for routing).
- WHEN EVNT calls routing and `responsibleCaregivers` is empty, THE SYSTEM SHALL return `200 OK` with
  an empty array (not 404); EVNT must raise a routing-failure alert, not discard the alarm.

### 3.3 HIST fact recording (outbound from ACS)

ACS records domain facts to HIST via synchronous REST (see `contracts/event-contracts.md §1` and SPEC-09).
`HistAuditPort` is an outbound port; facts are best-effort with retry outbox; HIST unavailability does
not block ACS operations.
