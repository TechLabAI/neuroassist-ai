# SPEC-09 — Messaging Architecture (`acs-service`)

> Module: **ACS** · Service: `acs-service` · Package: `com.neuroassist.acs`
> EARS guide: `docs/architecture/backend/standards/ears-notation.md`
> Generated by `/be-architect-specs neuroassist-ai ACS` · 2026-07-29

---

## 1. Status — N/A (messaging disabled in MVP)

`stack.messaging.enabled = false`. There is **no message broker** in the NeuroAssist AI MVP.

ACS does not publish asynchronous events to a broker and does not consume any. All inter-service
interactions are **synchronous REST**, routed through GWY and discovered via REG (Eureka). The
synchronous domain-fact recording to HIST (§1 of `event-contracts.md`) replaces event-bus publishing.

---

## 2. Domain facts (synchronous, to HIST)

See `contracts/event-contracts.md §1` for the complete list of domain facts ACS records to HIST and
their payload envelopes:
- `TenantProvisionado`
- `CuidadorRegistrado`
- `CuidadorDesativado`
- `CuidadorVinculadoAoPaciente` (anchor event)
- `CuidadorDesvinculado`
- `AutenticacaoRealizada` / `AutenticacaoFalhou`

All facts are recorded via synchronous REST calls to HIST, best-effort with retry outbox.

---

## 3. Reevaluation trigger

If tenant count or caregiver volume grows significantly, the `CuidadorVinculadoAoPaciente` /
`CuidadorDesvinculado` events are the first candidates to move behind a broker (e.g. RabbitMQ),
enabling asynchronous propagation of linkage changes to EVNT/DASH. This is a known post-MVP decision
(doc 04 §Decision points), **not** MVP work.
