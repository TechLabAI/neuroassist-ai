# SPEC-06 — Security (`acs-service`)

> Module: **ACS** · Service: `acs-service` · Package: `com.neuroassist.acs`
> Contract source: `contracts/api-contract.md §7`
> EARS guide: `docs/architecture/backend/standards/ears-notation.md`
> Generated by `/be-architect-specs neuroassist-ai ACS` · 2026-07-29

---

## 1. Objective

Specify the security posture of `acs-service`: OAuth2 configuration, authority enforcement, RBAC
mapping, HTTPS/CORS, and LGPD data-handling guards. ACS is simultaneously an **authorization server**
(issues JWTs) and a **resource server** (validates its own admin/directory calls against the JWK set).

---

## 2. Scope

**In scope:**
- Spring Security OAuth2 authorization-server configuration
- Resource-server configuration for the admin/directory surface
- Authority namespace and `@PreAuthorize` annotations per endpoint
- HTTPS enforcement, CORS policy
- LGPD guards: no credential/biometric/clinical data in logs, responses, or facts
- Known gap: residual-window on deactivation (no server-side session)
- Coverage invariant as a security-critical business rule

**Out of scope:**
- JWT issuance mechanics — see SPEC-03
- RBAC role-to-authorities total map — see SPEC-03 §5
- Data model encryption at rest (doc 05 §Keys)

---

## 3. Technical decisions

- **Spring Authorization Server** (not Keycloak) manages the `/oauth2/token` and `/oauth2/jwks` endpoints.
- **Resource-server mode:** the admin/directory surface is a resource server validating against its own
  JWK set (self-consistent; no external IdP in MVP — ADR-005).
- **`@PreAuthorize("hasAuthority('acs.xxx.yyy')")`** on every controller method; no method-level
  omissions allowed (security by default — closed unless explicitly opened).

---

## 4. EARS invariants — security

**Authorization server**
- THE SYSTEM SHALL configure Spring Authorization Server to expose `/oauth2/token` and `/oauth2/jwks`
  as public endpoints (no Bearer required).
- THE SYSTEM SHALL configure all other paths as protected, requiring a valid JWT with the appropriate
  authority (closed by default — explicit allowlist only).

**Resource server (admin/directory surface)**
- THE SYSTEM SHALL validate every Bearer token on protected endpoints against the local JWK set
  (`jwk-set-uri = http://acs-service/oauth2/jwks`, resolved via REG).
- IF a token is expired or its `iss` is not `acs-service`, THEN THE SYSTEM SHALL respond `401
  Unauthorized` (`type: /errors/unauthenticated`).
- THE SYSTEM SHALL enforce authorities via `@PreAuthorize` on every admin/directory controller method;
  a caller missing the required authority SHALL receive `403 Forbidden`
  (`type: /errors/insufficient-authority`).

**HTTPS & CORS**
- THE SYSTEM SHALL enforce HTTPS on all endpoints in non-local environments; HTTP is permitted only on
  the loopback interface (`localhost`) for local development.
- THE SYSTEM SHALL configure CORS to allow requests only from the configured Angular origin
  (`neuroassist-web`) and SHALL block cross-origin requests from unknown origins.

**LGPD guards**
- THE SYSTEM SHALL never log, return, or include in any error body: the raw `senha`/credential,
  biometric data, facial landmark data, clinical data, or any PII beyond `cuidadorId`/`pacienteId`
  reference ids.
- THE SYSTEM SHALL store credentials exclusively as `credential_hash` (bcrypt/argon2);
  the raw credential SHALL be zeroed in memory after hashing.
- `signing_key.private_key_enc` SHALL never appear in logs, error responses, or health payloads.

**Coverage invariant (safety-critical business rule)**
- THE SYSTEM SHALL enforce the coverage invariant (at most one alarm-eligible caregiver per patient)
  at the **application-service layer** (not only in the FE); the check is synchronous, within the
  same transaction as the revocation/deactivation.
- IF the coverage invariant would be violated, THE SYSTEM SHALL respond `409 Conflict`
  (`type: /errors/last-caregiver-link`) and SHALL NOT commit the state transition — fail-closed.

**Known gap (ADR-005 residual window)**
- In the MVP there is no server-side session store; JWT revocation is not instantaneous. Operators must
  be aware that a deactivated caregiver retains access until their current token expires (≤ 900s). This
  is documented and accepted; a post-MVP token blocklist is the remedy (doc 06 gap list).
