# DASH — API Contract

> Service: `dash-service` · Base package: `com.neuroassist.dash` · Port: `8090` (dev)
> All traffic is routed via GWY (`neuroassist-ai-api-gateway`) and discovered via REG (Eureka).
> Auth: OAuth2 Resource Server (JWT issued by ACS). Correlation: `X-Correlation-Id` propagated everywhere.
> EARS notation is used for per-endpoint invariants — see `docs/architecture/backend/standards/ears-notation.md`.

## 1. Conventions

- **Base path (panel):** `/panel` — the caregiver-facing surface consumed by the Angular panel.
- **Base path (internal):** `/internal` — service-to-service surface (EVNT → DASH dispatch sink); not
  exposed to the browser through GWY's public routes.
- **Media types:** `application/json` for REST; `text/event-stream` for the SSE stream.
- **Auth (panel):** `Authorization: Bearer <JWT>` — JWT validated locally against ACS's JWK set.
  Claims consumed: `sub` (caregiverId), `tenant` (empresa), `authorities` (roles).
- **Auth (internal):** service-to-service credential (client-credentials JWT with `authorities` containing
  `SVC_EVNT`); the browser can never reach `/internal/**`.
- **Mandatory headers (inbound):** `Authorization` (panel), `X-Correlation-Id` (generated by DASH if absent).
- **Tenant + scope:** never taken from a request parameter — always resolved from the JWT `tenant` claim and
  ACS caregiver↔patient linkage. A `patientId` in a path is authorized against that scope.
- **Errors:** RFC 7807 `application/problem+json` (§7).

### Global invariants (EARS)

- THE SYSTEM SHALL reject any `/panel/**` request without a valid ACS-issued JWT with `401 Unauthorized`.
- WHEN a request omits `X-Correlation-Id`, THE SYSTEM SHALL generate one and echo it on the response.
- IF the JWT `tenant` claim is absent or unparyseable, THEN THE SYSTEM SHALL respond `401` and log a
  security event (no scope ⇒ no view).
- IF an authenticated caregiver requests a `patientId` outside their ACS-resolved scope, THEN THE SYSTEM
  SHALL respond `403 Forbidden` and SHALL NOT reveal whether the patient exists.
- WHILE an upstream owner service is unreachable, THE SYSTEM SHALL degrade the affected view-model section
  (return it as `null`/empty with a `degraded` flag) rather than fail the whole response (ADR-004).

## 2. Panel composition (BFF reads)

### 2.1 `GET /panel/summary`
Home dashboard view model — the cross-module composition (ADR-005 FE server-driven home). Composes patient
list + latest event/alarm state (EVNT) + device liveness (EDGE) + unacknowledged notification count (EVNT).

- **Query:** none (scope from JWT).
- **200 Response:**
```json
{
  "tenantId": "e1a...",
  "caregiver": { "id": "c1...", "name": "Jamilly Amaral", "role": "cuidadora" },
  "patients": [
    {
      "patientId": "p1...",
      "name": "Márcio Amaral",
      "device": { "status": "online", "lastSeenAt": "2026-08-17T00:04:11Z", "degraded": false },
      "latestEvent": { "eventId": "ev9...", "commandLabel": "Preciso de água", "urgencia": "rotina",
                       "feedback": "nao_avaliado", "at": "2026-08-17T00:03:55Z" },
      "unacknowledgedCount": 1
    }
  ],
  "degradedSections": []
}
```
- **Invariants (EARS):**
  - THE SYSTEM SHALL return only patients within the caregiver's ACS-resolved scope.
  - WHEN EDGE is unreachable, THE SYSTEM SHALL set `device.degraded = true` and `device.status = "unknown"`
    rather than assert `offline`.
  - WHEN EVNT is unreachable, THE SYSTEM SHALL omit `latestEvent`/`unacknowledgedCount` and add
    `"evnt"` to `degradedSections`.

### 2.2 `GET /panel/patients/{patientId}/overview`
Per-patient overview (patient + command catalog + current calibration + device status). Composes PAC + EDGE.

- **Path:** `patientId` (authorized against scope).
- **200 Response:** patient header, `commands[]` (label, `urgencia`, `sensibilidade`, min/max gesture time),
  `device` block.
- **Invariants (EARS):**
  - IF `patientId` is outside scope, THEN THE SYSTEM SHALL respond `403`.
  - WHEN PAC is unreachable, THE SYSTEM SHALL respond `503` with a ProblemDetail of type
    `about:blank#upstream-unavailable` (the overview is meaningless without its command catalog).

### 2.3 `GET /panel/patients/{patientId}/history`
History/audit timeline for a patient — read-through to HIST.

- **Query:** `type` (optional filter), `actor` (optional), `from`/`to` (ISO-8601 window), `page`, `size`.
- **200 Response:** paged `items[]` (audit records shaped for the "Histórico" screen) + `page` metadata.
- **Invariants (EARS):**
  - THE SYSTEM SHALL forward `from`/`to`/`type`/`actor`/paging to HIST unchanged after scope validation.
  - WHEN HIST is unreachable, THE SYSTEM SHALL respond `503` `upstream-unavailable` (history has no
    partial-degrade meaning).
  - THE SYSTEM SHALL cap `size` at `100`.

### 2.4 `GET /panel/patients/{patientId}/device`
Device liveness detail — read-through to EDGE (ETag/304 honored upstream, `DASH poll 15s`).

- **200 Response:** `{ status: online|offline|unknown, lastSeenAt, degraded }`.
- **Invariants (EARS):**
  - WHEN EDGE returns `304 Not Modified` to DASH's conditional poll, THE SYSTEM SHALL serve the last known
    liveness value.
  - WHILE EDGE has been unreachable beyond the staleness threshold (§ SPEC-07), THE SYSTEM SHALL report
    `status = "unknown"` and `degraded = true`.

## 3. Real-time notification stream (SSE)

### 3.1 `GET /panel/stream`  (`Accept: text/event-stream`)
Opens the caregiver's live notification channel. One logical session per (tenant, caregiver, connection).

- **Response:** `200` `text/event-stream`, connection held open.
- **Events emitted:**
  - `event: notification` — `data:` = `NotificationEnvelope` (see event-contracts §2): `dispatchId`,
    `tier` (`full_screen_alarm|discreet`), `patientId`, `commandLabel`, `urgencia`, `raisedAt`.
  - `event: heartbeat` — `data:` = `{ "at": "<iso>" }` every `HEARTBEAT_SECONDS` (default 15s).
  - `event: catchup-complete` — sent after on-connect replay drains.
- **Invariants (EARS):**
  - WHEN a panel connects to `/panel/stream`, THE SYSTEM SHALL register an in-memory `PanelSession` and
    trigger on-connect catch-up (§4.1).
  - WHILE a session is open, THE SYSTEM SHALL emit a `heartbeat` every `HEARTBEAT_SECONDS`.
  - WHEN the connection drops or heartbeat times out, THE SYSTEM SHALL evict the `PanelSession` from the
    registry (no persistence).
  - THE SYSTEM SHALL scope every pushed `notification` to the connected caregiver's own dispatches only.

### 3.2 Long-poll fallback — `GET /panel/notifications/poll`
Transport fallback where SSE is unavailable.

- **Query:** `waitSeconds` (≤30), `cursor` (opaque).
- **200 Response:** `{ notifications: [ ...NotificationEnvelope ], cursor }`. Empty array on timeout.

## 4. Caregiver notification actions

### 4.1 `GET /panel/notifications/unacknowledged`
On-connect catch-up (also callable directly). Pulls the caregiver's unacknowledged notifications from EVNT.

- **200 Response:** `{ notifications: [ ...NotificationEnvelope ] }`.
- **Invariant (EARS):** THE SYSTEM SHALL read unacknowledged notifications from EVNT and SHALL NOT persist
  them locally.

### 4.2 `POST /panel/notifications/{dispatchId}/acknowledge`
Caregiver acknowledges a notification. Write-through to EVNT.

- **Request:** empty body (caregiver from JWT).
- **204 No Content** on success.
- **Invariants (EARS):**
  - WHEN a caregiver acknowledges a `dispatchId`, THE SYSTEM SHALL report `acknowledged(dispatchId)` to EVNT.
  - THE SYSTEM SHALL treat a repeated acknowledge of the same `dispatchId` as idempotent (still `204`).
  - IF `dispatchId` is not addressed to the caregiver's scope, THEN THE SYSTEM SHALL respond `403`.

## 5. Write-through caregiver actions

### 5.1 `PUT /panel/patients/{patientId}/commands/{commandId}/calibration`
Proxy a calibration edit to PAC (PAC is the authoring source, PAC ADR-004; DASH ADR-006).

- **Request:**
```json
{ "sensibilidade": "media", "minGestureMs": 400, "maxGestureMs": 2500 }
```
- **200 Response:** the updated calibration as returned by PAC (echoed, not stored).
- **Invariants (EARS):**
  - WHEN a caregiver submits a calibration edit, THE SYSTEM SHALL validate the payload and forward it to PAC,
    returning PAC's authoritative result.
  - THE SYSTEM SHALL NOT persist any calibration value locally (write-through only, ADR-006).
  - IF PAC rejects the edit (validation/conflict), THEN THE SYSTEM SHALL relay PAC's ProblemDetail
    unchanged (same status).
  - IF `commandId` does not belong to `patientId`, THEN THE SYSTEM SHALL respond `404`.

### 5.2 `POST /panel/events/{eventId}/confirm`
Proxy an event confirmation verdict to EVNT (`real | falso_positivo`; EVNT ADR-006).

- **Request:** `{ "feedback": "real" }` (enum: `real | falso_positivo`).
- **200 Response:** EVNT's updated event state (echoed).
- **Invariants (EARS):**
  - WHEN a caregiver confirms an event, THE SYSTEM SHALL forward the verdict to EVNT and return EVNT's result.
  - IF `feedback` is not `real|falso_positivo`, THEN THE SYSTEM SHALL respond `422` before calling EVNT.
  - THE SYSTEM SHALL NOT store the verdict locally (write-through only).

## 6. Internal dispatch sink (service-to-service)

### 6.1 `POST /internal/notifications`
EVNT dispatches a notification to DASH for delivery to the caregiver's panel (DASH is EVNT's delivery
target, EVNT ADR-005). Service-to-service auth only.

- **Request:**
```json
{
  "dispatchId": "d-77...",
  "tier": "full_screen_alarm",
  "tenantId": "e1...",
  "targetCaregiverId": "c1...",
  "patientId": "p1...",
  "commandLabel": "Emergência",
  "urgencia": "emergencia",
  "raisedAt": "2026-08-17T00:03:55Z"
}
```
- **202 Accepted** — `{ "delivery": "delivered" | "no_open_session" }`.
- **Invariants (EARS):**
  - WHEN EVNT dispatches to `/internal/notifications` and the target caregiver has an open session, THE
    SYSTEM SHALL push it over SSE and report `delivered(dispatchId)` to EVNT.
  - IF the target caregiver has no open session, THEN THE SYSTEM SHALL respond `202` with
    `delivery: "no_open_session"` so EVNT's fail-open retry holds the emergency (invariant: undelivered is
    surfaced, never dropped, ADR-005).
  - THE SYSTEM SHALL treat a redelivered `dispatchId` idempotently (no duplicate `delivered` callback).
  - THE SYSTEM SHALL reject a request lacking service-to-service authority (`SVC_EVNT`) with `401`.

## 7. Error model (RFC 7807)

All errors return `application/problem+json`:

```json
{
  "type": "about:blank#upstream-unavailable",
  "title": "Upstream service unavailable",
  "status": 503,
  "detail": "PAC did not respond within 2s",
  "instance": "/panel/patients/p1/overview",
  "correlationId": "corr-abc"
}
```

| Type (`type` suffix) | Status | When |
|---|---|---|
| `#unauthenticated` | 401 | missing/invalid JWT or service credential |
| `#forbidden-scope` | 403 | patient/dispatch outside caregiver scope |
| `#not-found` | 404 | patient/command/event not found within scope |
| `#validation` | 422 | malformed calibration/confirmation payload |
| `#upstream-unavailable` | 503 | required upstream (PAC/HIST/ACS) down |
| `#upstream-rejected` | *relayed* | PAC/EVNT rejected the write-through (status relayed) |

- **Invariant (EARS):** THE SYSTEM SHALL include the `correlationId` on every ProblemDetail response.

## 8. Auth summary (EARS)

- THE SYSTEM SHALL validate panel JWTs locally against ACS's published JWK set (no per-request ACS call for
  signature validation).
- THE SYSTEM SHALL resolve caregiver↔patient scope from ACS (cached with a short TTL, § SPEC-06) on the
  authorization path.
- THE SYSTEM SHALL require distinct authorities for `/panel/**` (caregiver roles) and `/internal/**`
  (`SVC_EVNT`).
