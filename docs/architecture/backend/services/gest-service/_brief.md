## 1. Canonical name and prefix
- **Prefix:** `GEST`
- **Canonical name:** `gest`
- **Service:** `gest-service` (Java 21 / Spring Boot 3.3.x / Gradle Kotlin backend module)

## 2. Problem the module solves
A safety product for patients with neurodegenerative disease needs a single, authoritative
**vocabulary of gestures**: which primitive facial movements exist (`TipoGesto`, a shared catalog)
and, per patient, which gesture-to-need mappings are active (`Comando`, e.g. "raise eyebrow twice →
I need water"). The Python Edge Agent (PEA) that runs on the patient's device must be able to pull
that active vocabulary to know what to look for. GEST owns and serves this vocabulary; it does not
see a single pixel of video.

## 3. Personas
- **Primary:** Jamilly Amaral (family caregiver) — configures the patient's `Comando` catalog on the
  web UI (`frontendLib = gest`): picks a primitive (or a composite of two), gives it a free-text
  label, sets sensitivity/urgency and the min/max gesture-hold window.
- **Secondary — machine actor:** the **Python Edge Agent (PEA)** — a non-Java process on the patient's
  device that authenticates via ACS `client_credentials` (role `edge_agent`) and consumes
  `GET /api/v1/gest/vocabulary/{pacienteId}/active` to configure its detector.

## 4. MVP scope (in)
- **TipoGesto catalog** — authoritative, extensible (LBC Emenda 2) vocabulary of primitive facial
  movements. **Global** (shared across empresas, `neuroassist_global` schema). Carries a detectability
  attribute: being in the catalog is *authorization to be referenced*, not proof the engine supports it.
- **Comando catalog** — per-patient gesture→need mapping. Fields: `label` (free, family-defined),
  `primitivoPrincipal` (TipoGesto), `primitivoSecundario` (TipoGesto | null → composite of up to two
  primitives), `sensibilidade` (baixa/media/alta), `urgencia` (emergencia/rotina), `tempoMinGestoMs`,
  `tempoMaxGestoMs`, `status` (ativo/inativo). **Per empresa** (tenant schema).
- **Active-vocabulary endpoint** — `GET /api/v1/gest/vocabulary/{pacienteId}/active`: every active
  `Comando` of the patient with its resolved `TipoGesto`(s). The critical contract consumed by the PEA.
- Caregiver CRUD over `Comando` (web UI) and read/catalog admin over `TipoGesto`.

## 5. Out of scope (MVP)
- **Video capture, facial-landmark extraction and gesture classification** — that is the **Python Edge
  Agent (PEA)**, a separate repository/process, never gest-service (ADR-005 local).
- Publishing the recognized-gesture event (`GestoDetectado`) — the PEA posts that to **EVNT**, not to GEST.
- Event persistence / alarm orchestration / notification (EVNT); patient identity & registration (PAC);
  caregiver identity, roles and patient-linkage (ACS); device pairing & heartbeat (EDGE); audit trail (HIST).
- Any image/video ever reaching the backend (hard privacy invariant).

## 6. Mandatory external integrations
- **Python Edge Agent (PEA)** — separate deployable on the patient's device; pulls the active vocabulary
  over REST/HTTPS (bearer token minted by ACS, role `edge_agent`). Not a third-party API — an in-product
  edge process outside the Java service boundary.
- **ACS** — identity provider: gest-service is an OAuth2 **Resource Server** validating JWTs against ACS's
  JWK set; the PEA obtains its token from ACS via `client_credentials`.
- **PAC** — patient identity authority: gest-service references `pacienteId` and must validate that the
  patient exists and belongs to the caller's tenant (sync REST port, fail-closed).

## 7. Hub / TechLab AI dependencies & inter-module contracts
- **TechLab AI services:** none. `ai.hasAi = false`; the "AI" is deterministic computer vision on the
  edge (PEA), not generative.
- **Messaging:** disabled (`stack.messaging.enabled = false`) → all inter-module calls are synchronous
  REST between independent services (routed via GWY, discovered via REG). No event bus in the MVP.
- **Consumed by:** PEA (active-vocabulary pull), FE `gest` lib (caregiver command configuration UI),
  EVNT (resolves `Comando` when building `Evento`), DASH (surfaces the patient's command catalog).
- **Depends on:** ACS (JWK / token issuer), PAC (patient existence/tenant validation).

## 8. Domain anchor event
- **"Comando ativado"** — a caregiver adds or activates a gesture→need mapping in a patient's vocabulary,
  making it visible to the PEA's next active-vocabulary pull. GEST owns the vocabulary; the downstream
  *recognition* fact (`GestoDetectado`) is produced by the PEA and owned by EVNT.

## 9. Provenance / correction note (read before Specs)
This brief **supersedes** the 2026-07-27 GEST vision, which modeled GEST as a generic edge "detection
authority" owning a *detection profile* and *detection contract*. The corrected conception (LBC Emendas
1 & 2; ACS handoff D-534, Python Edge Agent = external deployable):
- GEST = **vocabulary catalog** (TipoGesto + **Comando**). `Comando` moved **from PAC into GEST**
  (registry still labels PAC "Pacientes e Catálogo de Comandos" — stale; PAC keeps Paciente only).
- The edge consumer is **named**: the Python Edge Agent (PEA), auth via ACS `client_credentials`.
- The "detection profile" is reframed as the **active-vocabulary endpoint**; the "detection contract"
  (recognized-gesture reporting) is **EVNT's** ingestion contract, not GEST's.
- The existing downstream artifacts (`spec/`, `contracts/`, `tests/`, `events/`) predate this correction
  and MUST be regenerated by `/be-architect-specs` — do not trust them as-is.
