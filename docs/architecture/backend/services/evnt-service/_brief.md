## 1. Canonical name and prefix
- **Prefix:** `EVNT`
- **Canonical name:** `evnt`
- **Service:** `evnt-service` (Java 21 / Spring Boot backend module)

## 2. Problem the module solves
When the edge recognizes the patient's active command, that recognition is worth nothing until it
becomes a **help request someone actually answers**. EVNT turns the edge's `RecognizedCommandReport`
into a persisted, structured business **Evento**, decides *how loudly* to alert based on the command's
urgency (full-screen emergency alarm vs. a discreet routine notice), routes it to the responsible
caregiver, and closes the loop by capturing whether the alert was **real** or a **false positive**.
It is the safety-critical bridge between "the engine saw a gesture" and "a person was helped".

## 3. Personas
- **Primary — Jamilly Amaral (family caregiver):** receives the alarm on the panel (Wireframe Tela
  "alarme"), acts on it, and marks each event as `real` or `falso_positivo`. Her trust depends on
  emergencies never being missed and false positives being easy to dismiss and learn from.
- **Secondary — Danilo Amaral (technical conductor):** configures which caregiver is responsible for a
  patient's events and reviews the feedback signal (false-positive rate) during onboarding/tuning.
- **Indirect — Márcio Amaral (patient):** the person whose help request the Evento represents; never a
  system user, but the reason emergency latency and reliability are non-negotiable.

## 4. MVP scope (in)
- **Report ingress**: accept a `RecognizedCommandReport` from the edge (REST via GWY), **idempotent on
  `reportId`**, validating it against GEST before persisting.
- **Evento generation**: build and persist the structured business `Evento` (patient, command, urgency,
  timing, feedback=`nao_avaliado`) — EVNT is the system of record for events (GEST does not persist).
- **Urgency-tiered notification orchestration**: resolve the command's `urgencia` (`emergencia` |
  `rotina`) and dispatch the matching notification tier — full-screen alarm for emergency, discreet for
  routine — routed to the responsible caregiver.
- **Confirmation feedback loop**: let a caregiver transition an event `nao_avaliado → real | falso_positivo`,
  an audited action that also records who confirmed it (`confirmadoPor`).

## 5. Out of scope (MVP)
- Computer-vision detection and the primitive vocabulary/detectability (edge + GEST).
- Mapping a gesture to a family need and its urgency/sensitivity configuration — that is the `Comando`
  owned by **PAC**; EVNT *reads* it, never authors it.
- Device pairing, heartbeat and edge credential issuance (**EDGE**).
- The immutable audit ledger *storage* (**HIST**) — EVNT emits audit-worthy facts; HIST persists the
  trail. Dashboard rendering, history browsing and calibration UI (**DASH**).
- Any asynchronous broker / event bus (messaging disabled MVP) and any push to third-party channels
  (SMS/e-mail providers) — the MVP notification channel is the in-app panel.
- Any video, image or facial-landmark data — EVNT carries only primitive ids, confidence and timing.

## 6. Mandatory external integrations
- **Edge agent** — posts `RecognizedCommandReport` over REST/HTTPS (routed via GWY) using a
  device-scoped token (auth shape jointly owned with EDGE; still open — see doc 06).
- **GEST** (`gest-service`) — stateless validation of the incoming report against the referenced
  detection profile/primitives before an Evento is created.
- **PAC** (`pac-service`) — resolves `Comando` (label, `urgencia`, `sensibilidade`) and the patient.
- **ACS** (`acs-service`) — resolves the responsible caregiver / routing target for a patient.
- **DASH** (`dash-service`) — the panel that renders the alarm and the caregiver's action surface.
- **HIST** (`hist-service`) — receives the audit-worthy transitions (event created, confirmed, resolved).

## 7. Hub / TechLab AI dependencies & inter-module contracts
- **TechLab AI services:** none. `ai.hasAi = false`; urgency is a deterministic policy on the command,
  not an inference.
- **Messaging:** disabled (`stack.messaging.enabled = false`) → all inter-module calls are synchronous
  REST between independent services (routed via GWY, discovered via REG). No event bus in the MVP.
- **Consumes:** GEST detection contract (`RecognizedCommandReport` + validation), PAC `Comando`, ACS
  `Cuidador`. **Produces/owns:** `Evento` (read by DASH; audited by HIST).

## 8. Domain anchor event
- **"Evento gerado" (help request raised)** — the moment a recognized command becomes a structured,
  persisted business event awaiting a caregiver's response. EVNT owns the Evento's lifecycle from
  raised → notified → confirmed (`real` | `falso_positivo`).
