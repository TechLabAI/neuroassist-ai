# TREI — API Contract (`trei-service`)

> Module **TREI** · Service `trei-service` · Stack Java 21 / Spring Boot
> Public surface routed by GWY at `/api/v1/trei/**` (shared `ADR-008-public-api-surface-normalization.md`).
> Two authenticated actors on the **shared ACS realm** (OAuth2 Resource Server): the **caregiver**
> (ACS/DASH shell) and the **patient-with-session** (`ADR-012`, patient shell). Assisted generation is
> **authoring-only** (ADR-002 local / ADR-016); no LLM/ElevenLabs is ever on CONV's runtime path.
> EARS acceptance criteria per [`../../../standards/ears-notation.md`](../../../standards/ears-notation.md) (D-057).

---

## 1. Conventions

- **Base path (internal):** `/trei`. **Public path (via GWY):** `/api/v1/trei`. All paths below are
  relative to the public base `/api/v1/trei`.
- **Media type:** `application/json; charset=utf-8`; errors `application/problem+json`.
- **Tenancy:** `empresa` (tenant) and `pacienteId` are **derived from the validated JWT / session scope**,
  never taken from the request body or query string (schema-per-tenant).
- **Locale:** the authoring locale is an **explicit** field on session/proposal operations (`pt` | `en`),
  because each locale is authored independently (ADR-018); TREI does not infer it from `Accept-Language`.
- **Versioning:** breaking changes introduce `/api/v2/trei/**` and keep `/api/v1` alive (ADR-008);
  additive fields are non-breaking.
- **Idempotency:** approval and publication endpoints are **idempotent** — re-issuing the same approval or
  re-triggering publication for an already-`ativo` locale is a no-op (SPEC-05).

### 1.1 Mandatory headers

| Header | Direction | Rule |
|---|---|---|
| `Authorization: Bearer <jwt>` | request | ACS-issued token; caregiver token (DASH) or patient-with-session token (`ADR-012`), validated as resource server. |
| `X-Correlation-Id` | request/response | Injected by GWY when absent; **always echoed** and propagated to downstream calls (ACS/PAC/HIST, ElevenLabs, embedding sidecar, ES). |
| `X-Degraded` | response | `true` when a read was served while a soft dependency (ES/audio) is degraded. |

**EARS — headers & envelope**
- THE SYSTEM SHALL expose exactly the endpoints in §2 under public base path `/api/v1/trei`.
- WHEN a request lacks `X-Correlation-Id`, THE SYSTEM SHALL accept the value injected by GWY, echo it on
  the response, and propagate it to every downstream call (Anthropic, ElevenLabs, embedding sidecar, ES,
  ACS, HIST) so the whole authoring/publication chain shares one trace.
- THE SYSTEM SHALL derive `empresa` and `pacienteId` solely from the validated JWT/session scope and SHALL
  ignore any tenant/patient identifier in the body or query string.
- IF a request body carries image, video frame, landmark, or any biometric-capture data, THEN THE SYSTEM
  SHALL reject it with `400` (`type: …/no-biometric-ingress`) — TREI authors text, never biometrics.

## 2. Resources

Scopes come from the JWT. **Caregiver scopes:** `treinamento.sessao.conduzir`, `treinamento.no.propor`,
`treinamento.no.aprovar.cuidadora`, `treinamento.no.descartar`. **Patient-with-session scope:**
`treinamento.no.aprovar.paciente`. No single actor holds both approval scopes (ADR-003).

### 2.1 `POST /api/v1/trei/sessoes` — start an LLM authoring session (caregiver)

- **Scope:** `treinamento.sessao.conduzir`
- **Request:**

```json
{ "pacienteId": "p-1024", "localeAutoria": "en" }
```

- **201 response:**

```json
{ "sessaoId": "s-77", "pacienteId": "p-1024", "localeAutoria": "en",
  "estado": "ativa", "llmModelId": "claude-<model>-<version>", "iniciadaEm": "2026-08-31T18:00:00Z" }
```

**EARS**
- WHEN a caregiver starts a session for a patient in their `empresa`, THE SYSTEM SHALL create a
  `trei_sessao_treinamento` in state `ativa` with a fixed `localeAutoria ∈ {pt,en}` and record the
  concrete Anthropic `llmModelId` used (TECH-007).
- IF `pacienteId` does not resolve within the caller's `empresa` (PAC read), THEN THE SYSTEM SHALL reject
  with `404` (`type: …/patient-not-found`).
- THE SYSTEM SHALL disclose to the caregiver that content is being generated by AI (ElevenLabs Use Policy
  / ADR-017) — the disclosure flag is returned so the FE can surface it.

### 2.2 `POST /api/v1/trei/sessoes/{sessaoId}/propostas` — request an LLM proposal (caregiver)

Drives one turn of the assisted conversation: the caregiver's guidance goes to Claude/Anthropic, which
**proposes** new category/phrase text; TREI persists it as `trei_proposta_llm` (never auto-publishes).

- **Scope:** `treinamento.no.propor`
- **Request:**

```json
{ "instrucao": "phrases for asking to change position in bed", "parentNoId": "n-root", "tipo": "frase" }
```

- **200 response:**

```json
{ "propostas": [
    { "propostaId": "pr-1", "texto": "Please help me turn on my side", "tipo": "frase", "locale": "en" },
    { "propostaId": "pr-2", "texto": "I need to change position", "tipo": "frase", "locale": "en" } ],
  "aiDisclosed": true }
```

**EARS**
- WHEN a proposal turn runs, THE SYSTEM SHALL call the Anthropic API request-scoped to the active session
  and SHALL persist every returned candidate as `trei_proposta_llm` **before** returning it (SEC-002).
- THE SYSTEM SHALL NEVER publish, embed, synthesize, or index LLM output at this step — a proposal is
  inert until a human materializes it (§2.3) and both approvals fire (ADR-003, TECH-007).
- IF the LLM output contains clinical/diagnostic phrasing, THEN THE SYSTEM SHALL flag it and require the
  caregiver to edit it into the everyday-need register before materialization (SEC-002; ADR-017 PHI caveat).
- IF the Anthropic API is unreachable, THEN THE SYSTEM SHALL reject with `503` (`type: …/llm-unavailable`)
  and SHALL NOT leave a partial proposal — authoring simply cannot proceed until it recovers.

### 2.3 `POST /api/v1/trei/nos` — materialize a proposal into a draft node (caregiver)

Turns a proposal (or a hand-written phrase) into a `rascunho` node: creates/locates the
`conv_no_arvore_fala` node and a `conv_no_conteudo` row (`status='pendente'`, both approval flags
`false`) plus the `trei_conteudo_autoria` record.

- **Scope:** `treinamento.no.propor`
- **Request:**

```json
{ "pacienteId": "p-1024", "propostaId": "pr-1", "parentNoId": "n-root",
  "tipo": "frase", "locale": "en", "texto": "Please help me turn on my side",
  "engineFeatureRef": null }
```

- **201 response:**

```json
{ "noId": "n-90", "locale": "en", "subEstado": "rascunho",
  "confirmadoCuidadora": false, "confirmadoPaciente": false, "contentStatus": "pendente" }
```

**EARS**
- WHEN a draft node is materialized, THE SYSTEM SHALL create the `conv_no_conteudo` row with
  `status='pendente'` and both approval flags `false`, and set `trei_conteudo_autoria.sub_estado='rascunho'`.
- THE SYSTEM SHALL keep node **structure** (`parentId`, `tipo`, `engineFeatureRef`, `ordem`) locale-invariant
  (ADR-018): materializing the same logical node in a second locale reuses the same `noId` and adds only a
  new `(no_id, locale)` content row.
- IF `tipo = 'categoria'`, THEN THE SYSTEM SHALL allow children; only `frase` nodes are ever speakable
  downstream by CONV (categoria is navigational).

### 2.4 `POST /api/v1/trei/nos/{noId}/aprovacoes/cuidadora` — caregiver approval

- **Scope:** `treinamento.no.aprovar.cuidadora`
- **Request:** `{ "locale": "en" }`
- **200 response:**

```json
{ "noId": "n-90", "locale": "en", "confirmadoCuidadora": true, "confirmadoPaciente": false,
  "subEstado": "aguardando_aprovacao", "publicacaoDisparada": false }
```

**EARS**
- WHEN the caregiver approves `(noId, locale)`, THE SYSTEM SHALL set `confirmado_cuidadora = true` for that
  `(no_id, locale)` and SHALL re-evaluate the gate.
- WHILE `confirmado_paciente` is still `false`, THE SYSTEM SHALL NOT trigger publication and SHALL return
  `publicacaoDisparada: false` (asynchronous dual authorization, ADR-003).
- WHEN the same caregiver approval is re-issued for an already-approved `(noId, locale)`, THE SYSTEM SHALL
  treat it as an idempotent no-op (SPEC-05).

### 2.5 `POST /api/v1/trei/nos/{noId}/aprovacoes/paciente` — patient approval

Issued from the patient shell under the **patient-with-session** identity (`ADR-012`) — a different token,
a different scope, a different moment (never the same screen, ADR-003).

- **Scope:** `treinamento.no.aprovar.paciente`
- **Request:** `{ "locale": "en" }`
- **200 response (this approval closes the gate):**

```json
{ "noId": "n-90", "locale": "en", "confirmadoCuidadora": true, "confirmadoPaciente": true,
  "subEstado": "publicando", "publicacaoDisparada": true }
```

**EARS**
- WHEN the patient approves `(noId, locale)`, THE SYSTEM SHALL set `confirmado_paciente = true` and
  re-evaluate the gate.
- WHEN both `confirmado_cuidadora` AND `confirmado_paciente` are `true`, THE SYSTEM SHALL transition the
  locale to `publicando`, enqueue the three outbox steps, and start the publication pipeline **exactly
  once** (ADR-004) — returning `publicacaoDisparada: true`.
- IF the token is on the ACS revocation blacklist, THEN THE SYSTEM SHALL reject with `401`
  (`type: …/session-revoked`) on every call, regardless of non-expiry (fail-closed, ADR-003/ADR-012).
- THE SYSTEM SHALL accept the patient approval **only** on a patient-with-session token and SHALL reject a
  caregiver token here with `403` (`type: …/forbidden-scope`), and vice-versa for §2.4.

### 2.6 `GET /api/v1/trei/nos/{noId}` — inspect a node's authoring state (caregiver)

- **Scope:** `treinamento.sessao.conduzir`
- **200 response:**

```json
{ "noId": "n-90", "pacienteId": "p-1024", "tipo": "frase", "parentNoId": "n-root",
  "locales": [
    { "locale": "en", "texto": "Please help me turn on my side", "subEstado": "ativo",
      "confirmadoCuidadora": true, "confirmadoPaciente": true,
      "embeddingModelId": "multilingual-e5-<ver>", "audioRef": { "present": true, "formato": "opus" },
      "publicadoEm": "2026-08-31T18:05:00Z" },
    { "locale": "pt", "texto": null, "subEstado": "rascunho", "confirmadoCuidadora": false,
      "confirmadoPaciente": false, "audioRef": { "present": false } } ] }
```

**EARS**
- THE SYSTEM SHALL report each locale's authoring `subEstado`, both approval flags, the recorded
  `embeddingModelId` (G5) once `ativo`, and audio presence — so the caregiver sees exactly what is
  published where (locale integrity, doc 01 success signal).
- THE SYSTEM SHALL NOT expose one locale's `texto` under another locale (no cross-locale bleed, ADR-018).

### 2.7 `DELETE /api/v1/trei/nos/{noId}?locale=en` — discard a draft (caregiver)

- **Scope:** `treinamento.no.descartar`
- **200 response:** `{ "noId": "n-90", "locale": "en", "subEstado": "descartado" }`

**EARS**
- WHERE a `(noId, locale)` is in `rascunho` or `aguardando_aprovacao`, THE SYSTEM SHALL allow discard →
  `sub_estado='descartado'` (soft, retained for audit, ORG-001) and SHALL keep `conv_no_conteudo.status`
  at `pendente` (CONV never serves it).
- IF the `(noId, locale)` is already `ativo`, THEN THE SYSTEM SHALL reject discard with `409`
  (`type: …/already-published`) — an `ativo` locale is retired by re-authoring, not deleted (doc 05).

### 2.8 `GET /api/v1/trei/nos/{noId}/publicacao` — publication pipeline status (caregiver)

- **Scope:** `treinamento.sessao.conduzir`
- **200 response:**

```json
{ "noId": "n-90", "locale": "en", "subEstado": "publicando",
  "passos": [ { "passo": "embed", "estado": "ok" }, { "passo": "tts", "estado": "ok" },
              { "passo": "index", "estado": "pendente", "tentativas": 1 } ] }
```

**EARS**
- THE SYSTEM SHALL expose the per-step outbox state (`embed`/`tts`/`index`) so a stuck publication is
  observable; a step in `falha` SHALL be reported without the locale ever showing `ativo` (ADR-004).

### 2.9 `GET /api/v1/trei/health` — readiness projection

```json
{ "status": "UP", "anthropic": "REACHABLE", "elevenlabs": "REACHABLE",
  "embeddingSidecar": "REACHABLE", "elasticsearch": "REACHABLE", "audioStore": "REACHABLE",
  "acs": "REACHABLE", "embedModelId": "multilingual-e5-<ver>", "degradedCapabilities": [] }
```

**EARS**
- WHILE the Anthropic API, ElevenLabs, the embedding sidecar, or ES is unreachable, THE SYSTEM SHALL list
  the affected capability in `degradedCapabilities` (authoring / publication cannot complete) while keeping
  `status: UP` for already-published content — TREI is off CONV's runtime path, so its outage never stops
  the patient's communication.
- IF ACS is unreachable, THEN THE SYSTEM SHALL report `acs: UNREACHABLE` and `status: DEGRADED` — identity
  is fail-closed.
- THE SYSTEM SHALL surface `embedModelId` (= `TREI_EMBED_MODEL_ID`) in health so a G5 mismatch with CONV is
  operationally visible.

## 3. Error model (RFC 7807 ProblemDetail)

Every error is a `ProblemDetail` (`application/problem+json`) with `type`, `title`, `status`, `detail`,
`instance`, `correlationId`. `type` base: `https://neuroassist.ai/problems/`.

| `type` (suffix) | HTTP | When |
|---|---|---|
| `no-biometric-ingress` | 400 | Body carries image/frame/landmark data. |
| `invalid-request` | 400 | Malformed body, unsupported `locale`/`tipo`, blank `texto`. |
| `unauthenticated` | 401 | Missing/invalid/expired JWT signature. |
| `session-revoked` | 401 | JWT on the ACS blacklist (immediate revocation, ADR-003/ADR-012). |
| `forbidden-scope` | 403 | Token lacks the required scope, or wrong actor for the approval endpoint. |
| `patient-not-found` | 404 | `pacienteId` not resolvable in the caller's `empresa` (PAC). |
| `node-not-found` | 404 | Node/locale not in the patient's tree. |
| `already-published` | 409 | Discard/edit-conflict on an `ativo` locale. |
| `gate-not-satisfied` | 409 | Publication requested while an approval flag is `false`. |
| `llm-unavailable` | 503 | Anthropic API unreachable (authoring cannot proceed). |
| `tts-unavailable` | 503 | ElevenLabs unreachable at publish time (pipeline retries via outbox). |

**EARS**
- THE SYSTEM SHALL return every error as an RFC 7807 `ProblemDetail` carrying `type`, `status`, `detail`,
  `instance`, and `correlationId`.
- IF the token carries the wrong actor authority for an approval endpoint (caregiver token on the patient
  approval, or vice-versa), THEN THE SYSTEM SHALL reject with `403` even if a valid TREI scope is present
  (the two approvals are distinct identities, ADR-003).

## 4. Authentication & authorization

- **Model:** OAuth2 Resource Server (Spring Security), shared ACS/Keycloak realm. JWT validated by
  signature (`jwk-set-uri`) **and** against the ACS revocation blacklist on every request via
  `AcsSessionPort` (fail-closed, ADR-003/ADR-012).
- **Required claims:** `sub`, `empresa`, `pacienteId`, `scope`, and — for the patient token — the
  patient-with-session marker (`ADR-012`).
- **Two-actor gate:** the caregiver and patient approvals require **different scopes** issued to
  **different identities**; TREI enforces the dual-authorization invariant in the `application` layer, not
  as a mere pair of endpoints (ADR-003). Full rules in
  [`../spec/backend/SPEC-06-security.md`](../spec/backend/SPEC-06-security.md).

> **Test config note (Learning D-492):** `application-test.yml` MUST set
> `spring.security.oauth2.resourceserver.jwt.jwk-set-uri` (a static test JWKS), **not** `issuer-uri`
> — `issuer-uri` triggers OIDC discovery at boot against a Keycloak that is not up in tests. Carried into
> scaffold/BDD.

## 5. Non-functional invariants

- **Off the runtime path:** no TREI endpoint is ever called by CONV or on the patient's daily
  communication path; a TREI outage degrades **authoring**, never **communication** (doc 01).
- **Atomic publication:** a locale is visible to CONV (`conv_no_conteudo.status='ativo'` + ES doc) only
  after `embed`+`tts`+`index` all succeed — never a partial state (ADR-004).
- **G5 surfaced:** `embedModelId` is exposed on `GET /health` and recorded per published locale (§2.6),
  making index/query model parity with CONV operationally observable ([`data-model.md`](data-model.md) §3).
- **AI disclosure:** every authoring surface that shows LLM output flags it as AI-generated (ADR-017).
